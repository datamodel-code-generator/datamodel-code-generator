# Acceptance and verification plan

The checks below specify evidence required from future implementation; they are not results of executed product tests. Passing tests on unchanged dcg, or a document review reporting no findings, does not prove non-interference or performance of this design.

## 1. Keep comparison baselines separate

| Comparison | Required match or expectation | Invalid shortcuts |
| --- | --- | --- |
| Existing entry points: baseline dcg versus candidate dcg | Same input/configuration/environment: entire tree and bytes, APIs/signatures/exports, exceptions/warnings/stdout/stderr, side effects, performance | Updating goldens/API baselines to erase differences, accepting AST equivalence alone, inventing an allowed regression rate |
| Ordinary dcg versus the same dcg with a new target | Identical model artifact bytes under the same explicit model settings; no interference with order, references, or state | Keeping/deleting/renaming models for a target or silently changing scopes/presets |
| Legacy FastAPI generator versus new FastAPI target | Practical F01–F13 capabilities, new independent oracles, real HTTP behavior, regeneration behavior | Requiring legacy byte identity universally, counting legacy availability as replacement coverage, declaring completion from a narrow probe |
| Normal API maintenance in the legacy generator | Its own tests/releases validate changes; intentional documentation/help differences are recorded | Making a permanent dcg 0.65 pin a prerequisite for the new foundation or adding a selector/dual-environment launcher |
| New client | Explicit C01–C33 contracts, wire behavior, exceptions, resource ownership, packaging, types, documentation | Claiming parity from matching method names or using only expectations generated from the implementation under test |

Use existing supported timestamp fixing/suppression options. Fix input filenames, CWD, locale, timezone, formatting, Python, and dependencies. Report differences whose conditions cannot be aligned; do not broadly normalize headers, line endings, or import order. Compilation and normalized-text comparisons do not establish raw-byte equality or HTTP behavior; verify both separately.

### 2.1 Conformance with standard FastAPI patterns

Require FA01–FA06 in addition to F01–F13 for both supported server backends. Reject standard dataclass/TypedDict/msgspec settings at new server generate/render/verify/check entry points after the existing facade has resolved effective model settings but before core preparation. Preserve earlier existing configuration errors. Confirm that rejection occurs before input resolution, model generation, or publication. Apply the same backend rule to primitive-only/class-free inputs; ordinary dcg and client-only calls with those settings remain valid. ENTRY defines diagnostic codes and decision order.

Check codec conformance to original OAS/RFC requirements separately from behavior delegated to standard FastAPI. Do not derive standard FastAPI expectations from the client's strict codec. Use official minimal examples, pinned FastAPI source, and handwritten requests as independent oracles.

| ID | Input or operation | Independent observation |
| --- | --- | --- |
| FA01 | Standard parameters/JSON bodies/responses within one operation, plus uses requiring adapters for direction, aliases, nullable differences, or strict validation mode in Pydantic v2 models | Select each integration point at generation time according to FASTAPI's finite table; actual arguments, annotations, return types, manifest, and context agree. There is no runtime retry through a codec after standard-API failure. Include dcg-default optional non-nullable fields and dates in strict Pydantic JSON. For int32/int64, distinguish explicit parameter/Form ge/le from whether final body/primary annotations actually retain ranges; use literal in-range/out-of-range expectations. Check byte/base64 adapters, the scope of treating float/double as ordinary numbers, primitive preservation for unknown formats, and Pydantic BaseModel MISSING. Separate a Pet case whose other nullable field determines projection first from an id-only range case. Do not overlook known validate_json versus FastAPI validate_python differences because type names match, or conceal an invalid native range. |
| FA02 | Standard Annotated/Path/Query/Header/Body; cookie-form and custom-style adapters; colliding aliases/reserved names/ordinary paths | Send HTTP using actual wire names; typed handler values, public signatures, and served parameters agree. Handwrite cookie bytes for spaces, literal percent signs, and Unicode from the selected cookie contract, and confirm original values reach handlers. Do not add a helper that decodes standard Cookie values or choose native handling by exception type. Preserve readable ordinary path names; round-trip only necessary internal slots. Distinguish intentional standard coercion from strict codec behavior. |
| FA03 | Standard Form/File/UploadFile; required/optional/multiple files; ordinary text fields; unrepresentable uses such as part-specific headers/media | Delegate ordinary parsing, spooling, and lifetime to FastAPI. Do not generate MultipartRoute, parser-callback infrastructure, cancellation tasks, or private Request-cache rewrites. Diagnose unrepresentable typed uses with source information; generate raw Request handling only when explicitly selected. Do not falsely require complete cleanup for every parsing exception when the standard framework does not guarantee it. |
| FA04 | Add user DI with `Annotated[int, Header()]`; send missing, invalid, and valid values; add dependency overrides, sub-dependencies, and Security | Standard DI executes once. Do not constrain ordinary 422 records to three keys when input/ctx and other fields can occur. Distinguish sanitization of generated-codec errors from secrecy guarantees for the entire app. Do not silently register a global exception handler or DI container. |
| FA05 | Required Header/Query/Security added by user DI, handwritten routers, custom OpenAPI factories, identities shared with generated source | Required values/security survive in served OpenAPI rather than disappearing through whole-operation replacement. Diagnose conflicts with adapter-owned fields according to contract. For shared native/DI identities, retain FastAPI aggregation and required-value precedence; do not add custom provenance reconstruction or DI inspection. Reflect DI input-contract changes in standard factory output rather than claiming automatic reproduction of the original specification. Handle prefixes, nested prefixes, and multiple includes of one router through public openapi_extra markers, not private route context. For include A/B → install A → install B, installation calls the factory zero times; the first app.openapi calls the saved factory once, combines every registered plan, and removes markers. Independently test reinstall cache invalidation, explicit operation_keys subsets/empty/unknown/duplicate values, unknown owners, unused markers, and missing expected operations. Distinguish detection when a custom app evaluates docs from detection before create_app returns. Do not promise complete reconstruction of same-path/method registrations already lost during FastAPI document merging. |
| FA06 | Standard primary response_model, adapter primary, +json-only/parameterized response media, HTTPResult, explicit Response/streams, both Pydantic v2 backends, minimum/latest dependencies, user default_response_class changes | Check standard filtering/serialization and codec boundaries separately; reparsing response bytes does not prove equivalent execution. Native primary selection requires application/json without media parameters; omit response_class to delegate to the standard default. Adapters return declared Content-Type for +json and similar cases; do not conflate this with request Body support for +json. Compare handwritten FastAPI with the same public declarations under both ordinary defaults and explicit user default_response_class changes, including body/media/served docs. Do not promise the latter matches the source specification or introduce private default recovery/runtime fallback. For T=str/PlainTextResponse, both bare text/plain values and explicit HTTPResult/ModelValue application/json responses execute and remain documented. Avoid unnecessary class arguments that disable the ordinary direct-JSON-byte path; do not claim an unmeasured speedup. Do not hide nullable/direction differences by broadening served schemas. Preserve explicit Response behavior for adapter/no-primary cases and raw Response validation boundaries. Model artifacts remain byte-identical to ordinary dcg; generated typing and imports also pass. |

These are unimplemented acceptance requirements for Pydantic v2 BaseModel/dataclass, not checks executed by reading documentation. Restricting server coverage to two backends does not eliminate nullable/direction/style differences or make every integration point native. Preserve separate client five-backend tests and existing dcg all-backend regressions.

## 3. Client combination acceptance

| ID | Combination | Required observation or expectation |
| --- | --- | --- |
| X01 | POST + 503/disconnection + no idempotency contract | No automatic resend without explicit safety evidence. Observe server arrivals. |
| X02 | Idempotent operation + one-shot iterator/non-seekable upload | Never resend an empty body. Without an explicit factory/seek capability, stop resending and retain the reason. |
| X03 | Idempotency key + 429 + Retry-After + deadline | Same key/payload, no shortening the required wait, retries only within the deadline, response closure. |
| X04 | Injected transport retries plus SDK retries | Detect or explicitly control duplicated retry configuration. Distinguish promised SDK sends from actual sends. |
| X05 | OAuth expiry + concurrent requests + 401 + retry | No refresh storm; one authentication retry; total budgets/cancellation; no resending a non-replayable body. |
| X06 | Pagination + empty page + next cursor + 429 | Empty items alone do not terminate traversal; cursor loops stop; fetching is lazy; secrets are never sent to a next URL with a different origin. |
| X07 | 202 polling + Retry-After + transient error + cancellation | Do not recreate the initial POST. Retain polling state and distinguish error retry delays from poll intervals. |
| X08 | SSE/NDJSON + split UTF-8/chunks + mid-stream ReadError | No automatic resume without an explicit contract. Even explicit resume does not invent deduplication or exactly-once delivery. Cover partial frames, empty/oversized events, close/cancel, and no reconnect after decoding/size failures. |
| X09 | WebSocket reconnect + authentication + sequence/resume | Enforce both WS-specific counts and finite parent OperationSession budgets. Do not resend messages without explicit resume semantics; expose close codes. |
| X10 | Strict unchanged model + new enum/field + raw access | Preserve model bytes, surface typed decoding failure, and retain information through explicit raw access. |
| X11 | Aliases + omission/null/default + request/response roles | Wire names/presence, readOnly/writeOnly, custom serializers, and no model mutation. Apply official backend presence information before nullable handling: omit absent keys and emit null only for explicit None. Preserve distinctions for PATCH and decode→echo. Test explicit bound-factory/envelope operations for dataclasses without presence information. |
| X12 | Borrowed HTTP client + small pool + retry/decode failure/cancellation/early stream termination | Release native responses before returning buffered raw data. Live streams release through with/async with or explicit close, not break/GC alone. Repetition does not exhaust pools; borrowed clients remain usable; owned clients close once. |
| X13 | Redirect/next URL + auth/query credentials + logging | Origin boundaries, secret redaction, URL percent encoding, no unintended network destinations. |
| X14 | Exceptions in retry hooks, credential providers, or custom transports | Do not mistake programming errors for connection failures and retry. Check hook order/counts and original exception causes. |
| X15 | Multipart + multiple files/forms/part metadata + retry | Every attempt's body and file start positions, owned-handle release, bounded buffers. |
| X16 | Status/media/headers + HEAD/204/205/206/304/range/default | Distinguish schema-free and empty bodies; enforce body-forbidden statuses including 205; preserve raw headers; handle unknown media/invalid JSON and typed errors. Server emits no 205 payload; client treats 205 as bodyless. |
| X17 | Old/new generation settings + custom code + package regeneration | Deterministic generated files, handwritten boundaries, no target ownership of dcg models, wheel/sdist/py.typed/docs snippets. |

Run every X case in sync and async variants. Test policies deterministically using fake clocks/sleepers/randomness. Separately use local fixture servers for actual send consumption, pooling, socket disconnections, and latency that MockTransport cannot establish. Prefer tests requiring no paid API calls, external sends, or credentials.

X05 includes cancellation/expiry of only the initiating refresh caller, continued progress of other callers, unknown outcomes after sending rotation tokens, 401 against an already updated generation, and max_retries=0. Observe resource and token-endpoint arrivals separately; do not combine the provider's independent budget with caller waiting/resend budgets.

Expected wire values, decoded values, and failure conditions must be literal fixtures tied to OAS/RFC/protocol clauses. Do not compute them through dcg parsers/codecs/shared implementation helpers. Validate clients against handwritten fixture servers and servers with handwritten raw requests; generated server/client round trips alone cannot pass acceptance. Derive expectations from normative text and original input before reading the implementation, and record a normative reason for changes. The same rule applies when LLMs help. For each issue, introduce a deliberately wrong behavior—such as inverted explode, unknown enums converted to None, or unlimited 401 retries—and verify the oracle rejects it. Separate these procedures within the current maintenance arrangement without requiring additional staff. Differences from another SDK are investigative clues, not an oracle by themselves.

## 4. Performance acceptance

Prefer existing benchmarks. Record baseline/candidate Python/dependencies, input/configuration, CPU/OS, formatter, warm/cold conditions, repetition count, order, variation, CPU/wall time, peak memory, and retained memory. Existing paths must not suffer reproducible regressions. Explain measurement noise; do not introduce a 1% or millisecond acceptance allowance.

| Path | Measurements | Additional fixed work to inspect in source |
| --- | --- | --- |
| Existing model-only | Cold import, CLI help/version, small inputs, ordinary/large schemas/references/cycles, reuse/collapse, single/multiple modules, formatters, repeated APIs/GC | No additional target/runtime imports, Pydantic fields, observers, callbacks, full graph/source scans, serialization, or index rebuilds |
| Legacy FastAPI | Normal API maintenance, help/deprecation guidance, generation, custom visitors/templates | No new selector/launcher/environment discovery. Separate dcg-update effects from legacy-tool changes. |
| New FastAPI/client generation | Operation/type-use counts, many media, large schemas, capture retention, freeze, target rendering, failure cleanup | Costs remain on selected new-target paths; do not duplicate source/graph copies. |
| Generated client runtime | Small-call fixed cost, pool reuse, serialization, large uploads/downloads/streams, concurrency, backoff/pagination/polling, close/cancel | Imports/state/allocations for unused auth/stream/WS/cache capabilities, bounded buffers, task/thread/response leaks |

An unchanged model-only path does not excuse whole-body buffering or unbounded retained responses in the new client. Measure the new feature's costs openly; do not invent performance guarantees.

Inspect source for absence of unused-target imports/state, unchanged graph fields/layout, and unchanged parse/name-reservation/mutation/render/formatter/callback/network counts. Record every permitted internal integration-point change; its existence alone is not proof of non-interference. Compare allocations by object type with the same measurement tool and GC conditions over repetitions. Do not call instrument-induced variation inherently deterministic.

For wall/CPU measurements, use existing benchmark warmup. In one machine/session, run 30 A/A pairs and 60 baseline-A/candidate-B pairs, with equal AB/BA ordering under a fixed seed. Use independent processes for pairs unless the case specifically measures repeated Python APIs; then align process lifetime. A/A uses the same commit in separate checkouts/environment names with blinded labels. Predeclare a 99% bootstrap interval for the median difference and a sign test with p<0.01. No percentage or millisecond regression allowance is introduced: these control false conclusions, not acceptable slowdown.

If the candidate's positive difference exceeds the upper side of A/A's 99% variation interval, its bootstrap interval excludes zero, and the sign test supports the same direction, repeat the procedure in another session. Reproduction in two independent sessions fails the performance gate. Directional A/A drift, mismatched thermal/process load, or intervals too wide to distinguish outcomes make the measurement inconclusive, not passing. Remove the cause and repeat. Do not dismiss source-visible extra fixed work merely because measurements are noisy. An improvement/equivalence conclusion is not a mathematical proof of zero effect; state measured scope, resolution, and source observations.

## 5. Closing the requirement register

Link each F/C ID to source evidence, its selected contract, generated output, target configuration, runtime ownership, independent oracle, test result, and implementation failure cases. The eight DECISIONS documents' B/MC/FA/CG/RT/P/TY oracles add specificity to G/X; passing G/X alone does not establish complete coverage. Conditional API features also need contracts, missing-input diagnostics, and independent oracles.

Entry points, configuration, contexts, diagnostics, defaults, supported scopes, and binding/codec/runtime ownership are selected in DECISIONS. Implement and test those capabilities before publication. Record research, design decisions, probes, implementation, and passing tests as different states. Empty review findings do not prove product quality. A new demonstrated counterexample requires an explicit design/oracle revision with its reason.

## Additional acceptance for selectors, typing, and business-code protection

Compare ENTRY's mutually exclusive server/client options on the existing CLI with ordinary dcg execution, using positive and negative cases. Check both selectors together, target-config alone, missing outputs, unknown targets, existing check/exit behavior, and configuration discovery/import/object creation when no target is selected. Do not add target fields to existing CLI Config/GenerateConfig, or exclude argparse additions from performance measurements. Compare every previously valid long-option abbreviation using both separate-token and equals forms; preserve them through the four specified legacy Action aliases. ENTRY's independent oracles also include mixed CLI utility modes, the existing SIGINT handler's exit 0 versus direct KeyboardInterrupt/SystemExit propagation, metadata/check rejection, and fixed remote-lock policy/acquisition-once behavior from pyproject.

TYPING's TY oracles are mandatory for new generated artifacts. In addition to successful checking of valid calls, independent negative fixtures reject mismatched media/bodies, return types, callbacks, unknown keywords, service method signatures, and sync/async usage. Do not pass by changing dcg model bytes or hiding implementation checking through casts, Any, or stubs.

Test server updates as specification v1 → service implementations in user modules → specification v2 → regeneration. Separately introduce operations, required arguments, type changes, deletions, and explicit renames. Check unchanged user-module bytes, updated owned routes/Protocols, type errors against the actual implementations, TypeError when instantiating a subclass that lacks a new abstract method, and startup signature errors for structural services. A renamed or replaced operation becomes a different Protocol method, so business logic is never silently connected to another operation. Distinguish the same pointer in another root document from a digest-only update of the same root. Check principal-bearing services through `<Group>Service[Principal]` implementations and the authorizer passed to one builder. Static typing does not prove business semantics; execute handwritten HTTP/business fixtures too.

In G11/F13 persistence comparisons, ProjectionManifest must contain no type strings, Python objects, or absolute source paths. Type changes appear through the signature fingerprint; source uses the existing SourceRef with document and pointer. Compare manifest bytes across checkouts with the same relative layout. Changing the model-output parent must not reinterpret old manifest URIs relative to the new parent.
