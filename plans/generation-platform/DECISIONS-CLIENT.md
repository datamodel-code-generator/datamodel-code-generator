# Final Contract for Client Generator Public Configuration, Naming, and Artifacts

2026-09-17. This document fixes C28–C32 and the associated contracts for operation selection, request media, response dispatch, and templates. Implement these decisions and validate them against the independent oracles at the end. Design decisions are distinct from implementation verification; see [evidence status](REFERENCES.md#evidence-status).

[DECISIONS-ENTRY](DECISIONS-ENTRY.md) is authoritative for public entry points, the CLI, shared configuration fields, model generation and verification, staging, publication, distribution roots, and dependencies. Use [DECISIONS-RUNTIME](DECISIONS-RUNTIME.md) for retry/auth/HTTP clients/response ownership, [DECISIONS-PROTOCOLS](DECISIONS-PROTOCOLS.md) for API-specific helpers, [DECISIONS-MODEL-CODECS](DECISIONS-MODEL-CODECS.md) for presence, type projection, and wire codecs across all five backends, and [DECISIONS-BINDING](DECISIONS-BINDING.md) for the correspondence between final types and sources. Do not redefine the same defaults or state machines here as separate implementations. Public annotations, overload correlations, and type-checking acceptance follow [DECISIONS-TYPING](DECISIONS-TYPING.md).

Types for headers, cookies, and similar uses also come from ordinary D with the user explicitly selecting `OpenAPIScope.Api = 'api'` (`--openapi-scopes api`), rather than substitute models specific to a new target. The scope covers typed components, every parameter and body in paths/webhooks, all response media/headers, encoding headers, and callbacks; traversal and naming follow BINDING §5.4. Do not change existing scopes/defaults/order without api, and do not have a new target additionally select a scope. Match ordinary model artifacts produced by the same D and the same explicit scope/configuration. Request only the types used by the selected target through `require_type_bindings(batch, use_ids)`; if any are missing, reject this client generation with `BND_MODEL_SCOPE_REQUIRED`. This supports all five backends and builtin wire/media from the outset, without reverting to a flat-JSON-only or Pydantic-v2-only profile.

## 1. Public Entry Points and Configuration Objects

`datamodel_code_generator.client` exposes `generate_client`, `render_client`, `ClientGenerationConfig`, and the new configuration records below. Define OperationRef/OperationSelector/OperationSelection once in ENTRY's shared `datamodel_code_generator.api_types`; `.fastapi` / `.client` re-export the same objects. Do not mix these target configuration fields into existing D top-level exports, GenerateConfig, or presets/metadata. The generated package root exposes `Client` / `AsyncClient`; generation configuration and runtime `ClientOptions` / `RequestOptions` are different types.

Python `generate_client` / `render_client` accept one ClientGenerationConfig per invocation and plan only that client using one ordinary D model generation and binding pass. generate publishes the models, explicit metadata, remote lock, and that target in one transaction; render returns the same candidates without writing to publication destinations. Use ENTRY for the precise single-target entry, locking, rollback, and model_mode contracts. When multiple consumers share models, run each target separately with `model_mode='verify'` against models generated by ordinary D. Do not discover, register, manage, or simultaneously update other targets; a mismatch between a target's expected models and the actual models is detected by that target's next check/verify. Retain `GeneratedTypeContractBatch` as the collection of type uses finalized by one model generation pass, and retain protocol client batch helpers as a separate runtime feature.

The CLI uses the existing `datamodel-codegen --generate-client httpx --target-config client.toml`. Reject simultaneous `--generate-server fastapi` and do not automatically discover target configuration files. `httpx` selects the generator and does not change the selected runtime's `transport='httpx2'`. The file is flat TOML representing one ClientGenerationConfig, with required schema_version=1 and output/package/model_package/model_mode, etc. at the top level. Pass input and model settings through existing D CLI/configuration; do not place models/options/input or client/fastapi/targets wrappers in the target file. Separate model `--output` from target output; `--target-output` overrides only the file's output. If neither supplies output, report a configuration error; package/model_package must be explicit. Add no new console/module main, combined Python API, retire facility, or cross-target registry. `--check` and CLI exits retain existing D meanings: 0 success, 1 differences, 2 error. Interrupts follow ENTRY: preserve the existing SIGINT handler's exit 0 and unchanged propagation of KeyboardInterrupt/SystemExit instead of uniformly converting them to enum value 3.

New configuration records are keyword-only frozen records. Freeze collections once into tuples or read-only mappings; changes to the original mapping after a call are not incorporated. Unknown/missing kwargs for Python functions/configuration constructors raise ordinary TypeError; invalid values after signature binding raise APIGenerationError with E_CONFIG_VALUE, and conflicts between settings use E_CONFIG_CONFLICT. Unknown TOML keys produce E_CONFIG_UNKNOWN before construction. Do not accept bool as an integer setting or out-of-range values. Values accepted by Python and TOML normalize to the same effective values. The only configuration/schema version is integer `1`; unknown versions produce E_CONFIG_VALUE without starting generation. ENTRY's mapping is authoritative for diagnostics and CLI exits.

`ClientOperationConfig` requires `ref: OperationSelector` and has `resource: str | None = None`, `name: str | None = None`, `parameter_names: tuple[ParameterName,...] = ()`, `request_media_type: str | None = None`, `response_media_type: str | None = None`, `runtime: RuntimeOperationMetadata = RuntimeOperationMetadata()`, `description: str | None = None`, and `api_change_reason: str | None = None`. `ParameterName(in_: path|query|querystring|header|cookie, name: str, python_name: str)` identifies the target by declared location/name. A querystring name is the identity relating a Python argument to its declaration, not a wire query key. Do not ignore overrides for nonexistent parameters, media, or operations.

The shared keyword-only frozen constructor is `OperationRef(*, pointer: str, document: str | None = None)`. `OperationSelector = OperationRef | str`; a string means only shorthand for a plain RFC6901 root-use pointer. `OperationRef(pointer='/paths/~1pets/get')`, configuration record `{pointer:'/paths/~1pets/get'}`, and plain string `'/paths/~1pets/get'` normalize to the same BINDING OperationId. Do not substitute a `#` fragment, a string concatenating a URI and pointer, or an operationId lookup. Validate pointer escaping and the referenced node's operation kind with the shared resolver.

An omitted/None document always means the root input's use-site. Path/ParseResult URL inputs use ENTRY's canonical root URI; raw schema strings/Mapping inputs use logical identity `urn:dcg:root`. Input digest and document identity are separate, so changes to an in-memory schema do not change selector notation. Canonicalize an explicit document once relative to the configuration file (caller's CWD for the Python API), accepting it only if it matches root identity. A mismatch is E_OPERATION_REF. Even when referencing an external Path Item, select using the root use-site pointer; do not expose the external document's declaration URI/pointer as an operation selector. Retain the original DeclarationId/source address separately for diagnostics and binding. The urn is a logical name for selectors and does not change D input filenames/ref bases/CWD, model headers, or ordinary outputs.

Apply this rule consistently to operation overrides, OperationSelection, ClientContractExample, helper operation references, and TypeUseRef.operation. SchemaRef is a separate contract identifying schema declarations and permits type-binding references into actual external documents. Do not apply OperationRef's root restriction to SchemaRef. To explicitly identify a root SchemaRef for Mapping/raw input, use the same `urn:dcg:root` and the schema pointer.

If any selected operation's effective server cannot be resolved to an absolute URL and no applicable default_base_url/server_base_url exists, raise `E_BASE_URL`. Do not defer the missing requirement until the first call after generation. Pass runtime ServerSelection variables with their declared names, defaults, and enums, and apply RUNTIME URL/origin validation to results of caller-supplied variable values as well.

## 2. Operation/Tag Selection and Exclusion Semantics

Ordinary generated endpoints are HTTP operations in root `paths`. Do not arbitrarily reverse webhook/callback direction and add them as sending methods; pass their facts and schemas to explicit protocol helpers and type uses. Finalize the shared identity and order of every operation before determining selection.

`OperationSelection` has `include_operations: tuple[OperationSelector,...]=()`, `include_tags: tuple[str,...]=()`, `exclude_operations: tuple[OperationSelector,...]=()`, `exclude_tags: tuple[str,...]=()`, and `reason: str | None=None`. If both include collections are empty, start with all root path operations; otherwise take the union of operations matching either, then subtract the union of exclusions. Tags match original values exactly, case-sensitively, without trimming. An operation with multiple tags is selected if any matches. Selection preserves original operation order.

Setting any selection collection requires a reason containing non-whitespace text. Nonexistent refs/tags, duplicates within a collection, and refs selecting non-path operations as ordinary endpoints are errors. Exclude an operation matching both explicit inclusion and exclusion, recording both grounds. Retain every operation present in the schema but excluded by selection as `S_OPERATION_EXCLUDED` in the manifest and generated reference, with the rule, source location, and user's reason. S denotes the user's explicitly chosen scope, not an automatic exclusion marker for unsupported implementation.

If an enabled protocol helper requires an excluded operation, raise `E_SELECTOR_DEPENDENCY`. Do not silently re-include it for the helper; reject the entire target until configuration is consistent. Do not apply selection to model scopes, presets, order, or artifacts. If explicit selection yields zero ordinary methods, show that fact and the exclusion reasons without claiming support for the entire API.

## 3. Resource, Method, and Parameter Names

By default create exactly one resource from the first tag; use `default` when there are no tags. Do not duplicate an operation because it has multiple tags. `resource_names` maps original tags to namespaces, with an explicit operation resource taking precedence. A namespace is a `.`-separated sequence of ASCII Python identifiers such as `pets` / `admin.users`. Each component matches `[a-z][a-z0-9_]*`; Python keywords and reserved names are prohibited.

Automatic snake conversion is fixed. Normalize the original string to Unicode NFKC, insert underscores at ASCII `([A-Z]+)([A-Z][a-z])` and `([a-z0-9])([A-Z])` boundaries, and lowercase ASCII alphanumerics. Convert each non-ASCII character code point to a token of `u` plus lowercase hexadecimal; treat other symbols and whitespace as separators. Collapse consecutive separators to one underscore and strip them at both ends. Prefix `n_` if the name starts with a digit, and append `_` for a keyword. An empty result is an error. Apply this operation only to Python names, leaving wire names, paths, operationIds, and original tags unchanged.

A method defaults to the snake name of a nonempty operationId. Without an operationId, combine the lowercase HTTP method and path segments. Literal segments use snake conversion; `{name}` becomes `by_` plus the wire parameter's snake name, and the root path becomes `root`. Example: `GET /pets/{petId}` → `get_pets_by_pet_id`. Do not infer and remove resource prefixes from method names. Use an explicit `ClientOperationConfig.name` unchanged when it conforms to the ASCII identifier rule above.

Parameters default to the snake names of effective parameters' declared names; explicit parameter_names take precedence. Resolve overrides between common and operation parameters first according to OAS `(in, name)` semantics. Names shared across locations and normalization collisions produce `E_NAME_COLLISION` without automatic numbered suffixes. Explicit mappings allow all locations to be generated in the same method.

Take effective parameter/header/encoding collections and ignored-item provenance from the shared plan finalized once by BINDING §5.2. Do not reimplement predicates involving the root OAS version, actual parent location, media, and wire name in the client; MODEL-CODECS §10 consumes this same result. Distinguish one shared `I_OAS_ENCODING_IGNORED` for an entire ignored encoding from shared `I_OAS_HEADER_IGNORED` for individual ignored headers, retaining the former even for an encoding with no headers. Do not resolve subordinate Headers of an excluded entire encoding or expand it into per-header diagnostics. Do not pass excluded uses to method arguments, RequestCodecs, required checks, typed header accessors, header codecs, credential/naming collision checks, or type requirements. Pass source/root use-site, formal reason, and operation presence/absence unchanged in the shared diagnostics into §10.1's immutable context; do not convert them to user selection S. Model artifact traversal/generation also follows BINDING: do not delete or alter models already generated for another effective use or an independent component.

Retain the input OAS 3.0/3.1/3.2 version in the plan and generate 3.2 `in: querystring` as a builtin parameter. A querystring is one argument representing the entire query through content's single media. Coexistence with query, multiple querystrings, or schema/style/explode on a querystring in an effective operation are generation errors. Use MODEL-CODECS §10 for wire percent encoding, Encoding Objects, and text/JSON handling; do not split it into ordinary query parameters or prefix `name=`. Also use querystring in TypeUseRef and fixture parameters[].in.

Reserved root/resource members are `close, aclose, with_options, with_response, with_raw_response, with_streaming_response, request_raw, reset_circuit, protocols` and all names beginning with an underscore. Do not shadow Client's `reset_circuit(group, *, origin)` or AsyncClient's coroutine of the same name with an operation. Reserved ordinary-method arguments are `self, body, media_type, response_media_type, options`. For operations exposed as helpers, additionally reserve `session_options, pagination_options, poll_options, stream_options, ws_options, cache_options, upload_options, batch_options, queue_options, source, items, state`. APIs using these wire names resolve them through explicit python_name mappings for the corresponding parameters. Do not subsequently rename ordinary methods or existing arguments silently for helper convenience.

At generation time check collisions among methods, methods and child resources, generated type aliases/helpers, and output paths after NFC/case-folding. Resources and paths use identical collision rules on every OS, also rejecting Windows reserved device names and trailing dots/spaces. Do not renormalize an explicit configuration name into a different name.

Include public base members fixed by RUNTIME/PROTOCOLS in the same collision set. Do not shadow shared APIs such as `reset_circuit` with operation/helper names; expand the entire helper namespace tree and reject as E_NAME_COLLISION any configuration reusing a public member name on the same object. Build this set from the public contract, not dynamic attribute discovery on actual HTTP clients or providers.

If an existing manifest maps the same OperationRef to a different public resource/name, a move caused by automatic rules is `E_PUBLIC_NAME_DRIFT`. Explicitly retain the old name, or configure the new explicit resource/name and api_change_reason. Record removals, additions, and type/required/media/security contract changes in generated `api-diff.json`. SDK version is ENTRY's explicit package_version; the generator does not choose major/minor versions from schema differences.

## 4. Order, Signatures, and UNSET

Preserve GeneratedTypeContractBatch operation order. Resources follow the first appearance of an operation belonging to them; methods within a resource also follow operation order. For a nested namespace, add each prefix once from left to right while reading each operation's membership; the first occurrence of admin.users creates views in admin → admin.users order, preserving the child entry point even when the parent has no direct methods. As in the shared contract, effective parameters follow operation declaration order, then path-level common parameter order for entries not overridden by `(in,name)`. Do not resort by name or required/optional status. Python keyword-only parameters permit required parameters after parameters with defaults; do not make a required parameter optional for ordering convenience.

Make every operation argument keyword-only. After the parameters, place body, media_type, response_media_type, and options as required by each surface. Every method has `options: RequestOptions | None = None`. `None` means no runtime options were specified and is a different argument from None in a wire parameter.

|OAS declaration|Generated signature and sending behavior|
|---|---|
|required, non-nullable|`x: OutboundType`, without a default. Reject UNSET/None before sending|
|required, nullable|`x: OutboundType \| None`, without a default. Send None only if the codec permits its wire representation|
|optional, non-nullable|`x: OutboundType \| Unset = UNSET`. UNSET is not sent|
|optional, nullable|`x: OutboundType \| None \| Unset = UNSET`. Distinguish UNSET from None|
|schema default present|Do not change required/optional rules or copy the value to the method default. Do not send an omitted value as the default|
|optional body omitted|`body=UNSET` sends neither a body nor Content-Type. Distinct from JSON null, an empty object, or empty bytes|

`Unset` / `UNSET` are the public type/singleton in `pkg.options`. Do not add them to model fields, bases, or configuration. Types finalized at generation time by MODEL-CODECS are separated by direction. Client request OutboundType is `T | ModelValue[T]` for native uses and `T | DecodedValue[T]` for envelope uses. Client response/header InboundType is final T for native uses and `DecodedValue[T]` for envelope uses. Compose nullable/optional rules from the table with those types. Do not identify an optional method argument's UNSET with the native missing sentinel generated by existing D under explicit settings. Do not switch to a dict or envelope outside the return annotation after a call because native validation failed.

Property presence within a model follows the shared MODEL-CODECS §5/§7 rules and is separate from method-argument UNSET. Apply explicit PresenceTree, then public native presence, then the rules for backends without a presence API. Omit a Pydantic BaseModel optional field when it is absent from model_fields_set regardless of nullability or default; validate only a present None as null (error if nonnullable). Nested objects use their own presence. TypedDict uses actual keys and msgspec uses its official UNSET; do not infer absence from serializers or equality to defaults.

Bare T for Pydantic dataclass / stdlib dataclass lacks the set of fields explicitly supplied to the constructor, so nullable None is sent as null. In PATCH and similar calls, a field intended to be unspecified can become a deletion request through null. Construct input preserving omission with, for example, `UpdatePetRequestCodecs.body().from_wire({'name': 'B'})` or `UpdatePetRequestCodecs.body().snapshot(value, presence=presence_of({'name': 'B'}))`. Generated README/reference must explain this difference for the relevant backend and include examples bound to actual uses. A field explicitly present as null remains null; do not fill absence with null. Do not conceal this difference by changing D defaults/types.

Build Python schema annotations from `FinalPythonType` and finalized imports; do not reparse type_hint strings to find classes. Handle primitives, containers, unions, aliases, roots, enums, recursion, multiple modules, and all five backends through the same type-use contract. Binary/file bodies under §5 and bodies whose schema itself is absent from the source use a media surface recorded separately from the declared type. Request/response envelopes belong to the target and do not change D model artifacts.

## 5. Request and Response Media Selection

Methods with a requestBody have reserved `body` and `media_type` arguments. A single concrete media is the default. Multiple media have no implicit first-entry preference: explicitly configure the operation's request_media_type or supply media_type on the call. A required body with no default requires media_type in each media's `Literal[...]` overload and rejects omission at runtime before provider/HTTP sending. Only calls omitting an optional body may also omit media_type. Specifying media_type without a body is an error.

Media type/subtype comparisons are ASCII case-insensitive; parameters are validated under the codec contract. Content declarations collapsing to the same normalized form are generation errors. For `*/*` / `type/*` declarations, specify concrete media with the bound media selector below and verify both a matching declaration and an available registered codec. Do not change media based solely on a Content-Type header, filename extension, or Python body type.

When body types differ across media, generate fixed overloads with each media's body type. Select finite concrete media by Literal or a bound selector, and concrete wildcard values by a bound selector. Do not expose a sending overload accepting `media_type: str` with a union of all body types, or a catchall inferring a free type variable from the body. JSON/+json uses the model codec; text/binary uses the corresponding media codec; form-urlencoded/multipart uses the part plan. Schema-bearing form/multipart without file uses expands ordinary OutboundType through the part plan. For multipart with any file use, fix the body type to synchronous `MultipartBody[PartT]` or asynchronous `AsyncMultipartBody[PartT]`. PartT is the union of nonfile OutboundTypes for named nonfile properties and additionalProperties schemas; include WireValue only for a true branch allowing untyped extras, and use Never for purely file-only cases where additionalProperties is false and there are no other nonfile candidates. Pass nonfile parts through `FieldPart[PartT]`, with read-only value type `PartT | Unset`. Omit UNSET on optional parts with zero wire serialization; the existing part plan rejects UNSET on required parts before sending. Represent file parts as `FilePart[SyncBinaryBody]` or asynchronous `FilePart[AsyncBinaryBody]`, using existing bytes/file/stream/factory inputs. Only read-only FieldPart/FilePart are covariant; MultipartBody/AsyncMultipartBody are invariant. File/binary additionalProperties use the existing FilePart branch; do not mix bytes into WireValue. This union alone does not prove name/value correlation; validate it with existing part dispatch. Do not put file objects into D models generated as str, or expose private BodySource in public method argument types. Check required/optional status, encoding, media, part names, and order with the part plan. Validate extra parts under the original schema's additionalProperties rules; do not insert parts for generator convenience.

The public whole-binary request body type is `bytes | FileBody | StreamBody | BodyFactory`, or asynchronously `bytes | AsyncFileBody | AsyncStreamBody | AsyncBodyFactory`. These are the same types as RUNTIME's SyncBinaryBody/AsyncBinaryBody; optional body omission remains UNSET. The binary builtin does not turn None into empty bytes or omission; it raises RequestEncodingError before sending. API-specific wire representations of null belong to explicit media adapters. Ordinary buffered binary responses and error payloads have public type bytes; streaming responses use RUNTIME's RawResponse/AsyncRawResponse. Do not change a declared D type such as str into a file/bytes type. Keep model binding and media surface in separate fields.

When content exists but the schema itself is absent in the source, public JSON/+json input/output is `pkg.model_codecs.WireValue`, text is str, binary response is bytes, and binary request uses the input types above. Schema-absent urlencoded uses `pkg.bodies.FormData = tuple[tuple[str,str],...]`, preserving key/value order and duplicates. Encode/decode UTF-8 under form rules without collapsing to a dict. Schema-absent multipart requests use MultipartBody[str]/AsyncMultipartBody[str], with FieldPart[str] and the corresponding FilePart[SyncBinaryBody]/FilePart[AsyncBinaryBody]. Schema-absent XML/custom media use the registered adapter's WireValue as input/output. WireValue is MODEL-CODECS' finite immutable JSON domain; this rule applies only when the schema itself is absent in the source. Do not route failed type binding for a declared schema, unresolved refs, or unimplemented codecs through it. Typed text/JSON and similar media use OutboundType for requests and InboundType for responses, applying the original schema's validation to values obtained from media syntax.

A multipart response with a schema and no file use decodes into InboundType. With file uses its public type is `pkg.bodies.MultipartData[PartValue]`. PartValue is the union of all declared nonfile parts' InboundTypes and file bytes; include bytes for untyped additionalProperties parts. Without a schema use `MultipartData[bytes]`. MultipartData has `parts: tuple[DecodedPart[T],...]`; DecodedPart is a frozen record with `name: str | None, value: T, filename: str | None, content_type: str | None, headers: HeadersView`, preserving part order and ordered headers. Validate declared parts' requiredness/duplicates/media/schema with the part plan, retaining file and schema-absent payloads as bytes. Decode all parts within the ordinary buffered-response limit and close the native response before returning. On failure do not return partial MultipartData; classify it in the ResponseDecodeError family. Store filename only as a value; do not automatically write a file.

Methods with a successful response body have `response_media_type`. An explicit value narrows Accept and permitted successful decode media to that concrete media while preserving every error-response media. If omitted, use explicit operation response_media_type; otherwise send Accept listing declared successful media deduplicated in original status/media order. If every success is bodyless, omit this argument and automatic Accept. A finite-media Literal or `ResponseMedia[R]` selection correlates ordinary/metadata-view return types to that successful media's R, including None for bodyless branches. Raw/streaming-view return types remain those in RUNTIME; do not force response-schema decoding.

Construct Content-Type/framing from explicit media; a conflicting RequestOptions patch raises ConfigurationError before sending. The same applies to an Accept patch conflicting with explicit response_media_type. Raw surfaces share valid request encoding/authentication/retry, but do not force the final response to decode into the selected media or typed schema. Do not assign an undeclared response to a different schema solely because its suffix is `+json`.

## 6. All Response Types, Errors, and Headers

For each operation preserve every exact status, hundreds range, default, media, header, and bodyless branch. Dispatch priority is exact → matching range → default. The actual successful-status set follows RuntimeOperationMetadata.success_statuses; a schema alone does not make 4xx/5xx successful. Do not expose 1xx as final responses; HEAD/204/205/304 use RUNTIME's bodyless rules.

Generate `<PascalMethod>Response`, `<PascalMethod>ErrorData`, `<PascalMethod>HTTPError`, and `<PascalMethod>RequestCodecs` in `pkg.types.<resource>`. The first two are type aliases, not classes duplicating existing D schema models. Response is the union of public types for every reachable successful branch (schema InboundType or the media surface finalized under §5), deduplicated in original status/media order; include None for bodyless branches. With no successful branch use NoReturn. ErrorData is the analogous union of failure branches, or None if there are no payload branches. Construct PascalMethod by joining nonempty tokens of the finalized snake name with initial capitals; diagnose collisions among public names defined by the target.

Always bind every model/external type import leaf to a target-side private alias. Within each artifact, traverse FinalPythonType in finalized use order and type-expression preorder, assigning `_dcg_type_0`, `_dcg_type_1`, etc. to first-seen ImportBindingIdentity/SymbolId values. Reuse only identical identities; do not merge same-named identities with different modules/keep_unaliased/re-exports. Use a structured alias map for type expressions rather than string replacement. Custom template/hook declarations may not use the reserved `_dcg_type_` prefix. Do not change model-side imports, symbols, or bytes.

Thus a D model `ListPetsResponse` and public `pkg.types.pets.ListPetsResponse` may share a name in different namespaces. For example import the actual model binding as `from api_models.pets import ListPetsResponse as _dcg_type_0` and define `ListPetsResponse = _dcg_type_0` or a type alias containing it. This shared name alone is not E_NAME_COLLISION and does not require renaming an operation/model. Apply the same private import plan to annotations, runtime codecs, HTTPError, RequestCodecs, and Enum/constraint expressions. Distinguish collisions among target public members, intrusion into the private reserved prefix, and actual artifact path collisions.

RequestCodecs is MODEL-CODECS' generated frozen facade instance, with `body` (overloads for declared Literals, corresponding RequestMedia, existing dynamic str, and default omission), `parameter(*, location: Literal['path','query','querystring','header','cookie'], name: str)`, and `part(*, name: str, media_type: str | None = None)`. Generate Literal overloads for actual model-codec uses, returning `NativeOutboundCodec[T]` for native uses and `EnvelopeOutboundCodec[T]` for envelope uses. The former's `from_wire(JSONValue | WireValue)` returns ModelValue[T], the latter's returns DecodedValue[T], and both return ModelValue[T] from `snapshot(T, *, presence: PresenceTree | None = None)`. The facade binds context/binding without requiring callers to assemble CodecContext. Codec T is invariant. If a factory's dynamic str selector is not statically known, return the union of actual subclasses (e.g. `NativeOutboundCodec[T1] | EnvelopeOutboundCodec[T2]`), not `OutboundCodec[T1 | T2]`. Preserve the factory's safe codec union, distinct from a sending-method str catchall that loses media/body correlation.

Generate `select_request_media(*, declared_media: Literal[m], concrete_media: str) -> RequestMedia[S_m, A_m]` and `select_response_media(*, declared_media: Literal[m], concrete_media: str) -> ResponseMedia[R_m]` on the same `<PascalMethod>RequestCodecs`. These are explanatory variables: m is one actual declaration, S_m/A_m its synchronous/asynchronous body surfaces, and R_m the union of all reachable successful values (including bodyless None) finalized by MODEL-CODECS §3 from the existing dispatch plan. Actual artifacts have each declaration's concrete Literal/types and no str fallback for unknown declared_media. With zero eligible media do not generate the corresponding select method; with one signature generate an ordinary typed method. [MODEL-CODECS §3](DECISIONS-MODEL-CODECS.md) is authoritative for public `RequestMedia` / `ResponseMedia` types, read-only fields, private binding identity, correspondence to the most-specific winner, and failure rules; type variance follows TYPING.

Bind selectors only to top-level body or Accept selection, using the existing media/Accept plan independent of schema presence. Binary/schema-absent media may have selectors, but body() returns only branches with model codecs. Do not reuse RequestMedia for parts; preserve the existing name/media → codec union. Overloads omitting an optional body require UNSET and no media specification; selector overloads require the corresponding body. The same `RequestMedia[S_m,A_m]` value can be passed to fixed sync/async overloads, but each method accepts only the body for its axis. Reject another operation/use/direction, stale fingerprints, or invalid concrete media with existing CodecSelectionError before provider/HTTP I/O. Creating a selector does not cast, construct, or validate a body.

Omitted media for body/part binds only to the sole or explicit default media under §5; with multiple media and no default, each Literal overload requires media_type. Generation still succeeds in this case; runtime omission, unknown selectors, and selecting a file part raise CodecSelectionError. Do not invent model codecs for bodyless/binary/schema-absent uses; use public `freeze_wire(JSONValue) -> WireValue` to construct schema-absent JSON. Parts follow MODEL-CODECS §3's named-property priority and binding to the existing additionalProperties schema plan. Parts with directional requiredness can likewise be constructed as `FieldPart(name='data', value=CreateRequestCodecs.part(name='data').from_wire(...))`.

`<PascalMethod>HTTPError` is an operation-specific subclass of `HTTPStatusError[<PascalMethod>ErrorData]`. Register it as error_class in the operation registry. It retains no native response, holding bounded body/info/cause and error_data when the complete error body can be decoded. Retain error-payload decode failure as error_decode_error on the same operation subclass; do not turn it into success or a transport retry. Undeclared statuses/media, successful-body decode failure, and raw raise_for_status follow RUNTIME classification.

Ordinary methods return the Response alias, `with_response` returns `Response[ResponseAlias]`, `with_raw_response` returns RawResponse, and `with_streaming_response` returns `ContextManager[RawResponse]`. AsyncClient ordinary/with_response methods are awaitables of the same typed values; with_raw_response returns `Awaitable[AsyncRawResponse]`, and streaming returns `AsyncContextManager[AsyncRawResponse]`. Do not reduce multiple statuses/media to one primary response. Overloads narrowing successful types through explicit media retain bodyless branches.

The escape hatch separate from typed operations is RUNTIME's `client.request_raw(method: str, url: str, *, body: BodyInput[WireValue] | Unset = UNSET, options: RequestOptions | None = None) -> RawResponse`. Async uses AsyncBodyInput[WireValue] and `Awaitable[AsyncRawResponse]`. Buffered raw closes the native response and stores bytes/info before returning, leaving no native-response release obligation for callers. `client.with_streaming_response.request_raw(...)` returns a synchronous ContextManager/asynchronous AsyncContextManager, sends on enter, and releases the native response on exit or close/aclose. Do not fabricate operation-specific types; use the same RUNTIME request_raw status/error/auth contract.

Typed access to declared response headers is provided by `pkg.types.<resource>.decode_<method>_header(info, *, name: Literal[...])`. It covers only headers remaining after shared OAS exclusions; generate no overloads/required checks for ignored Content-Type. Each name's overload returns the union of applicable header InboundTypes after status dispatch, adding `| Unset` if any branch is optional. Header-name comparison is case-insensitive. A missing declared optional header is UNSET. Missing required headers, invalid duplicates/values, undeclared names, or lack of that header declaration for the current status raise `ResponseHeaderDecodeError(ResponseDecodeError)`. This exception retains info/cause, has empty body_bytes and truncated=False, and excludes header values from repr/str. Preserve ResponseInfo's ordered raw headers, including Content-Type; the helper performs neither I/O nor response-ownership transfer. The target does not independently generate D models for headers.

### 7.2 RuntimeDefaultsConfig and TOML

Generation-side `RuntimeDefaultsConfig` and nested `RuntimeTimeoutDefaults` / `RuntimeRetryDefaults` / `RuntimeRedirectDefaults` are keyword-only frozen records; every constructor field defaults to UNSET. Define numeric effective defaults once in RUNTIME §2, recording omission distinctly from explicit specification of the same numeric value during generation. The following are all fields that may be saved as generated defaults.

|Record|Accepted fields|
|---|---|
|`RuntimeDefaultsConfig`|`timeout, total_timeout, retry, redirects, max_network_sends, max_response_bytes, max_error_body_bytes, max_stream_bytes, stream_idle_timeout, stream_total_timeout, cleanup_timeout, compression`|
|`RuntimeTimeoutDefaults`|`connect, read, write, pool`. Each value is finite seconds or permitted None under RUNTIME|
|`RuntimeRetryDefaults`|`max_retries, initial_delay, max_delay, jitter, statuses, max_retry_after, respect_retry_after, retry_on_pool_timeout`. Header names belong in operation metadata, not here|

Resolve effective compression with RUNTIME's single rule. Apply values inherited from generation defaults/client/views only when the call has an actual body and the operation declares the token in accepted_content_encodings; otherwise compression is off. Optional body=UNSET is bodyless, while explicit empty bytes and JSON null count as bodies. Turn inherited values off for request_raw without operation binding (including streaming request_raw) and WS handshakes. Ordinary-operation with_raw_response/with_streaming_response use the same operation metadata and body conditions.

A non-None value explicitly supplied to RequestOptions.compression at an ordinary-operation call entry raises ConfigurationError before sending for an undeclared operation, absent body, request_raw, or WS handshake. Explicit None means off; UNSET means inherit. Token-syntax or registered encode-capability mismatches are configuration errors when configuring the specified layer; do not use inherited-off behavior to rescue an unknown token. RUNTIME's private ResolvedCompression retains requested_token, origin (builtin_default/generation_default/client/view/call), effective_token, and ownership of validation. Passing resolved options from a helper to a child request does not promote origin to call. Do not add origin fields to public options or flatten inherited values into explicit call values for validation.

For compression explicitly supplied in global `options: RequestOptions` at a helper entry assembling multiple requests, run RUNTIME/PROTOCOLS helper-plan preflight exactly once. If no child operation can apply an explicit non-None token, raise ConfigurationError before the first send. If any child is eligible, apply it only to the subset of child requests satisfying the token declaration and actual-body conditions; turn it off for bodyless poll/status/HEAD requests and undeclared children. Retaining helper-call provenance does not make each forwarded child a new direct user call requiring repeated strict validation. None disables compression throughout the helper; UNSET preserves the original inheritance rules. Use the same authoritative RUNTIME/PROTOCOLS contracts for preflight child plans, body presence, and validated ownership information; do not create a separate compression state machine in the client generator.

runtime_defaults does not accept server/base_url, headers/query, auth, absolute Deadline, idempotency keys, transport, hooks, limiters, cancel_token, context, protocols, or provider/store/connector objects. ### 10.2 Shared Encoders and Structural Validation

Retain specification-derived URLs, paths, header/query/cookie names, defaults, enums, summaries, and descriptions as raw facts; pass them through one `python_literal(value)` encoder when producing Python code. Strings become complete string literals using the same escape rules as Python `ascii(str)`. Recursively encode bytes, None/bool, finite numbers, tuples/lists/ordered mappings by type, without calling arbitrary object repr/str. Reject nonfinite numbers, callables, and unknown objects. Do not insert paths into f-strings or format expressions; pass literal templates and parameter values to wire codecs.

A separate `python_identifier` encoder accepts only finalized Identifiers. `python_type` builds Python type expressions only from FinalPythonType. `python_docstring` returns a complete string literal; templates must not sandwich specification triple quotes or newlines between quotes. Combine necessary explanatory text as data before encoding.

Specification strings in custom Jinja context are SpecText wrappers; direct string conversion raises TemplateSafetyError. Do not expose raw string attributes, string methods, arbitrary attributes/calls, or safe filters to the template sandbox. Only the encoder filters above turn SpecText into render tokens. Enable StrictUndefined; raw output without filters and unknown context keys must not silently become empty strings.

Expose shared pure display filters `text_strip(SpecText)->SpecText`, `text_lower(SpecText)->SpecText`, and `text_equals(SpecText, SpecText | template-literal str)->bool`. The first two still return SpecText with source provenance, with no escape through str/repr/raw attributes/arbitrary methods. Do not rewrite Identifiers or wire facts through these display transforms. Trusted explicit Python hooks receive immutable plain facts; wrap their source-derived strings in SpecText when constructing render frames as well.

Do not reuse Python literals in non-Python artifacts. All encoders return `EncodedFragment(format, context, provenance)`, which templates cannot construct directly and which renders only in its matching format and syntactic position. Reuse across formats, surrounding a fragment with quotes again, or inserting body fragments into URL/tag/code positions produces E_TEMPLATE_CONTEXT. Builtin and custom templates use the same filters.
