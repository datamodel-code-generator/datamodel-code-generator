# Generated model and operation / property type bindings — Decision contract

2026-09-17. These are research and design decisions; the new classes, integration points, and tests below are unimplemented. The source used to check the design is pinned to dcg `4f96e22ea403a66faae96f3949d41dd61fc1186f` (main checked at 2026-09-17T13:03:27Z). Measurements from the earlier `3452dfbb428c4384f40cb16faf61aadfda58a3a8` are separate evidence. The earlier proposals to restrict support to Pydantic v2, disable reuse/collapse, or require a single module are not adopted. [DECISIONS-ENTRY.md](DECISIONS-ENTRY.md) owns public entry points and artifact staging/publication; [DECISIONS-MODEL-CODECS.md](DECISIONS-MODEL-CODECS.md) owns backend runtime codecs. This document owns capture, correspondence, acceptance, and lifetime.

## 1. Decision

**Run the existing model engine once, and retain the types and fields it actually creates, the replacements it actually adopts, and its final module output only at the new entry points.** Do not parse the same input with another parser and match names, copy the entire model graph, evaluate annotation getters again, or repair generated models.

To keep preprocessing and acceptance decisions under one owner, move the existing `_generate` body exactly once into `_run_generation(input_, config, caller_cwd, *, use_output_cwd, capture=None)`. Keep legacy `_generate` as a thin wrapper with its existing signature and return value. The new entry points use this same core for preparation, existing `_parse_generation` retry/acceptance, and ordinary emission. Only the new path passes the parser factory and `GenerationCaptureSession`. Do not create capture sessions, store ledgers, type snapshots, or source catalogs on the ordinary path. Internal changes that organize existing parser/store/copy calls into integration points owned by those components are in scope for implementation. This design does not call an unconditional observer when the new feature is unused.

Distinguish three kinds of type binding.

1. **Emitted types**: bind to actual `Reference` / model identities in the same attempt and to the module that generated their definitions.
2. **Types removed from output**: bind to the reuse target selected by existing processing, the expanded root value, or an explicitly specified external type. Do not keep deleted names alive.
3. **Uses for which the model engine creates no type**: distinguish uses that can refer to an existing type from those requiring a new explicit model-generation setting. Do not silently expand the scope; compare against ordinary model generation with the same explicit model settings.

Operation types alone do not complete a codec. From the first implementation, retain both the correspondence between original properties and final model fields and the facts from the original schema's required/null/default/direction/format and the generated model's configuration. An initial FastAPI implementation cannot pass acceptance at the shared boundary by omitting this field correspondence.

Public operation selectors/override keys use the keyword-only `OperationRef(pointer: str, document: str | None = None)` defined in [ENTRY's shared public records](DECISIONS-ENTRY.md). Do not confuse a `#`-prefixed fragment with this plain pointer.

`document=None` denotes a use site in the root input. `root_selector_document` is a canonical file URI for Path input, the existing loader's canonical root URL for URL input, and fixed `urn:dcg:root` for Mapping/raw-text input. This URI belongs only to the new API's selector namespace; it does not change existing parser source filenames, base URIs, ref resolution, or headers.

The initial separate server/client entry points are limited to **a single root OpenAPI document**. Paths must be files; reject directories/multiple-file lists with `E_INPUT_ROOT` before model parsing. One Mapping/raw-text/URL root may reference external documents; external refs are not additional roots. Preserve ordinary D directory input and explicit Api model-only directory processing. Do not conflate this legacy-input compatibility with the explicit single-root constraint of the new entry points.

Accept explicit `OperationRef.document` only when it matches this `root_selector_document`; otherwise return `E_OPERATION_REF`. Even for an external Path Item reference, select the root path/method use site. Do not substitute the external declaration URI and treat it as the same operation. Separately retain the external document URI/declaration pointer resolved by the actual loader as DeclarationId. After normalization, `None`, explicit root URI, and plain pointer identify the same operation-selection/override key. Do not expose internal parser paths such as `#/paths`, paths with removed leading slashes, or generated-name special paths as public selectors. Do not add network fetches or a second resolver to accept alternate URL spellings; share ENTRY's single input-identity normalization process.

## 5. Capturing sources, operations, and type uses

### 5.1 Capture locations

1. At entry to the capture mixin's `_parse_specification`, borrow the root mapping and source frame already created by the existing loader. Do not YAML/JSON-load again. Capture itself reserves no model names and calls the selected ordinary OpenAPI/Api engine's `super` once. The Api model engine itself owns its actual declaration frames.
2. For legacy scopes, capture the effective mappings and order actually passed by `_process_path_items`. For Api, read §5.4's traversal frames with declaration context and effective sequences. In both cases, do not reverse-engineer literal paths/original declaration IDs from internal naming paths. Record declaration mappings separately from inherited/effective mappings. Use the finite rules below for legacy-scope limitations.
3. Retain existing returns from `_parse_schema_or_ref`, `parse_request_body`, and `parse_responses`. Keep every status/media type rather than reducing to a primary response. Do not construct, copy, or register DataTypes for observation.

For new targets, explicitly measure added cost of source-node indexes, selected-type retention, validated-origin indexes, replacement edges, final-field views, finite Result-field indexes, and artifact validation. Explicit Api has costs for its walk with declaration context, resolver canonicalization, ordinary type generation once per declaration and ref-use types, external-file metadata processing, and dedicated wrappers. Compare the same model engine with and without capture. Do not transfer these costs to model-only generation. Capture strong retention is bounded by disposal; after freezing, reachable live-graph count is zero.
