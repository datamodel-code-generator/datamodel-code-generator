# Client runtime contract

Revised 2026-09-18. Covers C01–C18/C24–C27. **This document establishes design decisions; it does not report implementation or measurements of the new runtime.** Its contracts replace any remaining proposals, candidates, or deferred decisions for the same subjects in other documents. The client supports all five dcg builtin model backends from its first release. The new FastAPI builtins are the two established in [FASTAPI §2](DECISIONS-FASTAPI.md), Pydantic v2 BaseModel and Pydantic v2 dataclass; this is distinct from the client's five-backend support. The client HTTP transport uses native HTTPX2 sync/async. Model codec details have a separate binding contract; client runtime policy does not require inheritance from Pydantic or an SDK-specific BaseModel. Existing D bytes, ordering, APIs, side effects, performance, and model-only dependencies remain unchanged.

The defaults in this document are **selected values for the new client**. They are not performance measurements or tolerances for existing D. Public options below identify configurable values. Default changes are generated SDK behavior changes and must be recorded in the version and changelog. No value is delegated to an implicit HTTPX2 default.

Public and private annotations use the same shapes as the [typing contract](DECISIONS-TYPING.md). Only new packages declare `typing-extensions>=4.16,<5`, using Python 3.10-style Generic/Protocol, concrete Literal types, and Unpack[TypedDict] where required. Do not strengthen existing D model annotations or bytes, or introduce extra I/O, per-request reflection, or new validation traversals for typing. T and similar variables below are type arguments already bound to methods, decoders, or records; they do not denote functions that return arbitrary T from an operation name alone.

## 1. Public surface and model independence

For a generated package named `pkg`, the public entry points are fixed as follows. Generation naming rules diagnose name collisions instead of generating different runtime shapes for users.

```python
from pkg import Client, AsyncClient
from pkg.options import ClientOptions, RequestOptions, TimeoutOptions, RetryOptions, UNSET
from pkg.responses import Response, RawResponse, AsyncRawResponse
from pkg.bodies import FormData, MultipartData, DecodedPart
from pkg.errors import SDKError

Client(*, options: ClientOptions | None = None,
       http_client: httpx2.Client | Unset = UNSET,
       http_client_ownership: Literal['borrowed', 'owned'] = 'borrowed',
       transport_adapter: TransportAdapter | OwnedTransportAdapter[TransportAdapter] | Unset = UNSET)
AsyncClient(*, options: ClientOptions | None = None,
            http_client: httpx2.AsyncClient | Unset = UNSET,
            http_client_ownership: Literal['borrowed', 'owned'] = 'borrowed',
            transport_adapter: AsyncTransportAdapter | OwnedTransportAdapter[AsyncTransportAdapter] | Unset = UNSET)

client.resource.method(..., *, options: RequestOptions | None = None) -> T
client.resource.with_response.method(..., *, options: RequestOptions | None = None) -> Response[T]
client.resource.with_raw_response.method(..., *, options: RequestOptions | None = None) -> RawResponse
client.resource.with_streaming_response.method(..., *, options: RequestOptions | None = None) -> ContextManager[RawResponse]
```

The async ordinary, with_response, and with_raw_response methods are respectively `async def ... -> T`, `Response[T]`, and `AsyncRawResponse`; one await yields that result type. with_streaming_response is an **ordinary def** returning `AsyncContextManager[AsyncRawResponse]`, with no await required before `async with`. No provider or HTTP request starts before entering the streaming context. `T` is the success type statically bound to the operation, including actual existing D types, primitives, containers, unions, declared MODEL-CODECS envelopes, and explicit CLIENT media surfaces. Only ordinary methods and with_response perform typed success/error handling; raw methods do not automatically raise for the final HTTP status. Raw methods share the retry policy; use `max_retries=0` to observe the first 429 or similar response directly.

`client.with_options(options: RequestOptions) -> Client` returns an immutable configuration view. It shares the HTTP pool and providers without mutating the parent's configuration. view.close ends only that view's calls and handles; it does not close the shared HTTP client or providers. After the owner client that created the view closes, every new call through any view raises `ClientClosedError`.

Public types in `pkg.options`, `pkg.responses`, and `pkg.errors` use stdlib dataclass/Enum/Protocol/typing and the typing_extensions version above. The private runtime and native adapter are bundled in the generated package, which does not import the generator package at runtime. Backend dependencies appear only in the corresponding codec dependency closure. Do not add sentinels, request IDs, caches, auth state, or extra base classes to existing D models. Root Client/AsyncClient exports resolve lazily: `import pkg.models` alone must not import HTTP, auth, AnyIO, or unselected model backends.

Credentials, providers, and signers defined below are public in pkg.auth; bodies, factories, and parts in pkg.bodies; adapters in pkg.transports; and hooks, events, and limiters in pkg.hooks. These protocol definitions do not import unselected model backends. Actual HTTP clients and executors are created only when explicit instances are used; module import creates no network activity, threads, or pools.

The following table is authoritative for public module names. Common type modules other than pkg.webhooks.keys are always generated, allowing references from DeviceAuthorizationFlow and similar APIs even without protocol helpers. They are importable using only stdlib and typing_extensions type declarations, without optional HTTP, WebSocket, or model libraries. Actual adapters are imported when the selected capability starts.

| Public module | Public types / entry points |
|---|---|
| `pkg` | lazy `Client`, `AsyncClient` |
| `pkg.options` | `ClientOptions`, `RequestOptions`, `TimeoutOptions`, `RetryOptions`, `RedirectOptions`, `TransportOptions`, `ServerSelection`, `Deadline`, `CancelToken`, `UNSET`, `Unset`, `SessionOptions`, `ProtocolClientOptions` |
| `pkg.responses` | `Response[T]`, `ResponseInfo`, `HeadersView`, `RawResponse`, `AsyncRawResponse` |

SessionOptions has exactly three fields: `total_timeout`, `deadline`, and `max_network_sends`; omission means UNSET. Do not duplicate protocol-specific limits here. Each helper/Device flow merges effective defaults and explicit values under PROTOCOLS and §7. PROTOCOLS §1.1 is authoritative for ProtocolClientOptions fields/defaults and store/connector signatures.

Generated clients directly depend on `httpx2>=2.13.0,<3` and require Python `>=max(3.10, explicit model target Python)`. See [REFERENCES](REFERENCES.md#evidence-status) for the evidence scope. The runtime uses stdlib asyncio directly and does not directly import or declare a dependency on AnyIO; HTTPX2 transitive dependencies are separate. Initial AsyncClient I/O supports native asyncio only; generated capabilities and the README explicitly state that Trio and other backends are initially unsupported. Check in the constructor when the running loop can be detected and at the first await entry point; a different backend or loop raises UnsupportedAsyncBackendError before network or provider execution. This I/O condition is separate from support for all five model backends.

For exception-group classification on Python 3.10, only the new client runtime adds the direct dependency `exceptiongroup>=1.2.2,<2; python_version<'3.11'`. Python 3.11 and later use builtin BaseExceptionGroup. This enables reading multiple-address failures propagated by AnyIO through public `.exceptions`; it is not added to legacy D model-only dependencies.

Native `http_client` accepts only the matching HTTPX2 sync/async type; it does not accept HTTPX 0.28 objects by duck typing or fall back automatically. Specifying both `http_client` and `transport_adapter` raises ConfigurationError. Connecting HTTPX or another implementation requires an explicit TransportAdapter and conformance tests; similar API names do not establish compatibility. Adapters expose `send(request:PreparedRequest[BodyAttempt], context:AttemptIOContext) -> TransportResponse`, or async `async def send(request:PreparedRequest[AsyncBodyAttempt], context:AttemptIOContext) -> AsyncTransportResponse`, plus `close/aclose` and `capabilities`. Responses provide ordered headers/status, a content-coded byte iterator, and idempotent close. Context contains phase/remaining timeout, cancellation, and a trace sink, with no model or provider. Capabilities explicitly state internal retry presence/limit, delivery evidence, and HTTP versions; fixtures for sync/async, deadline, close, exception mapping, and actual send count are mandatory. Adapters are borrowed by default; only `OwnedTransportAdapter(adapter)` transfers ownership.

The following table exhaustively defines adapter-boundary types. Signatures omit self and contain no bare Callable/Generic or model type T. They type the existing phase evidence, retry ownership, stream handoff, and close contracts without adding decision rules.

| Public type | Exact type / method |
|---|---|
| `PreparedRequest[AttemptT_co]` | Frozen, readonly `method:str, url:str, headers:HeadersView, body:AttemptT_co \| None`. AttemptT_co is covariant and bounded by BodyAttempt or AsyncBodyAttempt. Represents one already-open attempt and holds no native model |
| `TransportAdapter` | `send(request:PreparedRequest[BodyAttempt], context:AttemptIOContext) -> TransportResponse`, `close() -> None`, readonly property `capabilities:TransportCapabilities` |
| `AsyncTransportAdapter` | `async def send(request:PreparedRequest[AsyncBodyAttempt], context:AttemptIOContext) -> AsyncTransportResponse`, `async def aclose() -> None`, the same readonly capabilities |
| `TransportResponse` / `AsyncTransportResponse` | Readonly `status_code:int, headers:HeadersView`. Sync: `def iter_raw_bytes() -> Iterator[bytes]` / `def close() -> None`; async: `def iter_raw_bytes() -> AsyncIterator[bytes]` / `async def aclose() -> None`. The iterator factory itself is not awaited. Returns only content-coded bytes before SDK decoding |
| `TransportCapabilities` | Frozen/readonly `internal_retry_limit:int \| None, delivery_evidence:bool, http_versions:tuple[str,...]`. Retry limit 0 means no internal retries; None means unknown and does not prove a finite bound. HTTP version strings or delivery declarations alone do not replace the actual evidence required by §5 |
| `OwnedTransportAdapter[AdapterT_co]` | Frozen/readonly `adapter:AdapterT_co`. AdapterT_co is covariant, bounded by the union of sync/async TransportAdapter. No rebinding methods or setters; preserves the ConcreteAdapter type. Does not change variance of the stateful adapter itself |
| `ResolvedTimeoutOptions` | Readonly `connect:float \| None, read:float \| None, write:float \| None, pool:float \| None`. Contains no UNSET; phase clamping and post-handoff application remain as defined in §4 |
| `AttemptIOContext` | Readonly properties `phase:IOPhase, timeout:ResolvedTimeoutOptions, deadline:Deadline \| None, cancel_token:CancelToken \| None, trace:TransportTraceSink`. | `TransportTraceSink` | `phase_started(phase:IOPhase) -> None`, `request_headers_started() -> None`, `response_headers_received(*, http_version:str, status_code:int, headers:HeadersView) -> None`, `wire_send() -> None`. Receives existing resource-only phase/header/optional wire-send evidence. Excludes proxy CONNECT; only adapters with evidence record wire_send. Does not forward raw values to user hooks or logs |

Untyped upstream trace information is checked at the adapter's object boundary and narrowed to these arguments; a type alone does not make its value trustworthy. The `OwnedTransportAdapter` constructor infers its input type. Client accepts only `OwnedTransportAdapter[TransportAdapter]`; AsyncClient accepts only `OwnedTransportAdapter[AsyncTransportAdapter]`. Positive typing fixtures must allow a wrapped ConcreteAdapter in the corresponding slot; negative fixtures fix rejection of the opposite mode.

## 2. Option values, defaults, and merging

All options are frozen; input mappings/lists are copied into immutable values at entry. External provider/client identities are not copied. `UNSET` is one public singleton meaning inheritance; `None` has the explicit meaning defined for each field. Only `options=None` is equivalent to an empty override. Do not accept bool as seconds or counts. Durations are finite nonnegative floats; count/byte limits are finite integers except where explicit `None` is allowed. NaN, Infinity, and negative values raise `ConfigurationError`.

Omitted constructor fields in ClientOptions/RequestOptions and nested TimeoutOptions/RetryOptions/RedirectOptions remain UNSET; the table gives effective defaults after merging. A caller explicitly passing the same number as a default still supplies an explicit value. This resolves stream read-default differences, clearing through None, and generated runtime_defaults overrides without inferring provenance from value equality. UNSET itself is never sent in wire JSON or headers.

| Public setting | ClientOptions default | RequestOptions / merge / meaning of None |
|---|---|---|
| `server: ServerSelection` / `base_url: str` | First effective OAS server. Without servers, generation requires an explicit base URL setting | Both UNSET inherit; specifying both in one layer is an error. Explicit server replaces lower-layer base_url; explicit base_url replaces lower-layer server selection. None is forbidden. Missing/undefined server variables fail during generation or before the call |
| `headers: HeaderPatch` / `query: QueryPatch` | Empty tuple | Empty tuple adds nothing. `HeaderPatch=((name,value),...)`; query has the same shape. Values are str; `None` removes every lower-layer value of that name. Mixing None and str for one name in one layer is an error. Multiple str values of one name form an ordered group replacing the lower-layer group |
| `auth: AuthConfig` | Explicit credentials for generated security requirements; no implicit environment reads | UNSET inherits; None disables authentication only for operations permitting anonymity. None for a required scheme raises AuthConfigurationError before sending. Do not mix credentials into generic headers |
| `timeout: TimeoutOptions` | connect=5s/read=30s/write=30s/pool=5s | Per-nested-field precedence: request > view > client > generated default. timeout=None disables all four phases; field=None disables only that phase. Neither disables the total deadline. Only streaming methods use stream_idle_timeout as the read default; an explicit read value is an additional cap, taking the minimum |
| `total_timeout: float \| None` | 60s | Relative total budget from call entry. None disables the relative cap inherited through this layer. 0 raises DeadlineExceededError before providers or sending. Cannot disable the parent OperationSession deadline |
| `deadline: Deadline \| None` | None | Monotonic absolute deadline created with `Deadline.after(seconds)`. UNSET inherits; None clears the client/view absolute deadline. Cannot clear the parent session deadline. Uses the earlier of this and the relative cap |
| `retry: RetryOptions` | Table below | Merge per nested field. None forbidden. `max_retries=0` disables retries |
| `redirects: RedirectOptions` | enabled=False/max_redirects=5/allow_303_to_get=False/allowed_origins=()/allow_https_downgrade=False | Nested merge. None forbidden. Empty allowed_origins allows only the initial origin. Redirect count accumulates across the logical call |
| `idempotency_key: IdempotencyKey \| None` | UNSET | UNSET generates automatically under the operation declaration; None suppresses automatic generation. Caller values take precedence. `IdempotencyKey.new()` contains UUIDv4 and first_used_at. Do not reuse one key for distinct logical operations |
| `max_network_sends: int \| None` | UNSET, calculated below | UNSET inherits. Explicit int limits all resource hops/token HTTP sends. None cannot remove a parent session cap; individual retry/redirect/auth limits remain |
| `max_response_bytes` / `max_error_body_bytes` | 16MiB / 64KiB | Buffer limits on decoded bytes. Only response permits explicit None for unlimited buffering. Error is 1..1MiB; None forbidden. The response limit also applies to buffered raw responses. Use streaming for large data |
| `max_stream_bytes: int \| None` | None | Inherited through client/view/request. None means no total stream cap; explicit nonnegative int limits total consumption after handoff. Applies to decoded bytes for iter_bytes/stream_to and content-coded bytes for iter_raw_bytes; excess raises ResponseTooLargeError. Read buffer caps, expansion ratio, and parent deadlines remain separate |
| `compression: str \| None` | None | None disables request compression. Requires a valid HTTP token other than identity and request capability from builtin gzip or a registered ContentCoding. Inherited generated/client/view values apply only with a body and an operation declaration; only explicit non-None call values are checked strictly. The authoritative resolution order follows |
| `stream_idle_timeout` / `stream_total_timeout` | 60s / None | Idle/total limits after handle handoff. None disables only that cap. Protocol idle precedence is explicit protocol Options > helper default > this resolved value. SessionOptions governs the whole protocol deadline; stream_total_timeout adds a per-connection cap, taking the minimum. Do not duplicate total_timeout in StreamOptions |
| `cleanup_timeout` | 5s | Independent finite cap for network resource cleanup after error/cancellation. Positive; None forbidden. Does not extend the original call deadline to send new requests. Sync blocking cleanup has the same physical limitations as §4 |
| `hooks: tuple[Hook \| AsyncHook,...]` | () | Request UNSET inherits view/client. An explicit tuple replaces rather than concatenates; users concatenate explicitly to add hooks. None forbidden |
| `limiter: Limiter \| AsyncLimiter \| None` | None | Explicit objects replace. None removes the lower-layer application limiter. Separate from connection pool limits. Cannot remove parent session send/deadline budgets |
| `cancel_token: CancelToken \| None` | None | Explicit token, OR-combined with the parent session token. None cannot clear parent cancellation. Async task cancellation remains active |
| `context: Mapping[str, JSONScalar]` | Empty | Shallow replacement by keys supplied by the request. None is JSON null, not deletion. Values reach hooks, so secrets are forbidden; total limit 8KiB |

Client-only `transport: TransportOptions` cannot change through requests/views. Fixed defaults are `verify=True`, `ssl_context=None`, `proxy=None`, `trust_env=False`, `http2=False`, `max_connections=100`, `max_keepalive_connections=20`, `keepalive_expiry=5s`, and `retry_owner='sdk'`. If ssl_context is specified, use its verification/CA/client-certificate settings and reject a simultaneous verify override. These choices make proxy/TLS/mTLS/environment dependencies explicit and reproducible; enterprise proxies are permitted. HTTP/2 requires explicit True and its dependency extra.

Client-only `protocols: ProtocolClientOptions | None` has effective default None and cannot change through views/requests. None means no protocol injection configuration. An explicit object supplies security context, a WS connector, cache/queue/circuit stores, and `content_coding_factories: Mapping[str, ContentCoding]`. Missing required helper metadata or factories raises ProtocolConfigurationError before sending; do not add undefined per-capability constructor arguments. Data-only RuntimeDefaultsConfig accepts max_stream_bytes/compression but no runtime objects such as protocols, transports, or providers.

**The authoritative request-compression resolution rules** follow. Merging retains value and provenance together; private `ResolvedCompression(requested_token, origin, effective_token)` uses origin `builtin_default | generation_default | client | view | call`. Constructor UNSET inherits; explicit None disables. origin=call applies only when compression is explicit in RequestOptions at the actual method/helper entry point; the same object type passed to with_options has origin=view. Passing a helper's resolved value into a child LogicalCall does not promote its origin to call. Explicit helper-entry values carry the HelperCompressionAdmission below, distinguishing them from direct calls to ordinary operations.

Token syntax and encode capability, from builtin gzip or declared custom registration, are validated when adopting a configuration layer. Unregistered tokens, missing encode capability, identity, and similar invalid values raise ConfigurationError; an inherited default need not apply to every selected operation. After body encoding and before auth/limiter/send, select effective_token only if an actual body exists and the operation binding's accepted_content_encodings contains the token. Omitted optional body UNSET means no body; explicit b'' or an encoded JSON null counts as a body.

If origin is generation_default/client/view and conditions fail, effective_token=None. For a **direct call to an ordinary operation**, origin=call with explicit non-None and unmet conditions raises ConfigurationError before sending. Direct request_raw calls, including streaming forms, have no operation binding; direct WS handshakes follow the same rule: inherited values turn off, explicit call values fail. Ordinary operation with_raw_response/with_streaming_response uses that operation's ordinary rules. OAuth token HTTP is independently configured form submission and does not inherit resource compression. If an allowed redirect such as 303 removes a body, that hop sets effective_token=None and removes body headers including Content-Encoding without repeating initial explicit-setting validation. Body-preserving hops and retries retain the same selection and replay contract.

An explicit non-None value at helper entry receives one strict preflight before all network activity, including resource/token HTTP. Under the PROTOCOLS entrypoint/state recipes, if zero reachable automatic-workflow child slots can prove an actual body and declare the token, raise ConfigurationError with send0. Create private `HelperCompressionAdmission(helper_fingerprint, token, child_slots)`, save it on the handle/session, and pass it to children with origin=call unchanged. child_slots maps (role, OperationRef) for children callable from this entrypoint/state; preflight checks its applicable subset. Thereafter, compress only table-listed children that have an actual body and matching declaration; bodyless poll/probe/next_url GET, undeclared entries, and similar children remain off. Do not treat children as user direct calls or rerun strict validation. Eligibility evidence, start/resume differences, bounded batch preparation, finite queue claims and lease return on rejection, and explicit control calls follow authoritative PROTOCOLS C33; never enumerate all inputs without a bound. An explicit non-None value for a new admission fails when there are zero applicable children even for empty input, max_items=0, or a new resume of completed state. Returning an existing handle's saved result creates no new admission. Omitted/None/inherited no-work behavior is unchanged. Do not persist Admission itself in ResumeState or queue payloads.

Borrowed http_client instances do not receive transport construction settings again. Combining http_client with nondefault transport construction fields raises ConfigurationError. The SDK explicitly applies request deadline, timeout, redirect, auth, header, and cookie behavior, without unintentionally falling through to borrowed-client defaults. Only connection pooling, proxy, and TLS remain owned by the borrowed client.

| RetryOptions field | Default / changes |
|---|---|
| `max_retries` | 2, configurable. At most 3 resource attempts including the first request. Reauthentication after 401 uses the same budget |
| `initial_delay`, `max_delay` | 0.5s / 8s, configurable. max_delay >= initial_delay |
| `jitter` | `'full'`; explicit `'none'` allowed. Full is uniform over `[0, min(max_delay, initial_delay*2**retry_index))`. retry_index is 0 for the first retry. Saturate after reaching the cap without further exponentiation; a zero cap means zero delay |
| `statuses` | `{408,429,500,502,503,504}`. Explicit replacement with an integer status set in 400..599. Reject 401/403/407 as status-retry settings. 409/501 and similar statuses are not defaults |
| `max_retry_after` | 60s. Positive value or None to remove this cap. The total deadline still applies |
| `respect_retry_after` | True. False is allowed only through explicit API configuration and must appear in the generated README |
| `retry_after_ms_header`, `should_retry_header` | None. Vendor-specific headers are used only when generated metadata declares their names; supplying a value alone does not implicitly enable them |
| `retry_on_pool_timeout` | False. Do not automatically amplify pool waiting. Explicit True still requires safety, body replay, and budget conditions |

HTTPX2 provides phase timeouts and connection retries; these do not establish a total logical deadline or safe POST retries. See [HTTPX2 timeouts](https://pydantic.dev/docs/httpx2/advanced/timeouts/) and [transports](https://pydantic.dev/docs/httpx2/advanced/transports/). The 5/30/60-second, 16MiB, and other defaults are design decisions providing finite defaults for ordinary short REST calls, with long-running or large-data use requiring explicit settings. Evidence scope is recorded in [REFERENCES](REFERENCES.md#evidence-status).

## 3. Header, query, and URL construction order

Wire-value layers are `generated default → client defaults → with_options view → explicit method parameters → RequestOptions patch`. The model/wirecodec contract first resolves schema defaults and omission within each scope. Patch header names compare ASCII case-insensitively; query names compare case-sensitively. A replacement group occupies the lower layer's first position; unknown names append in the layer's declaration order. Do not convert repeated query/header values into dictionaries. HTTP/2 changes to header casing are transport representation changes and do not change name comparison.

`Host`, `Content-Length`, `Transfer-Encoding`, multipart boundaries, and headers/query/cookies managed by auth schemes or signatures are reserved. Changing or deleting their values through generic patches raises ConfigurationError. Change auth through AuthConfig and body framing through BodySource/codec. A specification generating ordinary parameters at the same location/name as credentials receives a collision diagnostic. The `User-Agent` default is only `<distribution>/<sdk-version>`; no additional generator or vendor identification headers are added by default.

Cookies come from explicit parameters/AuthConfig. The native adapter sends a complete HTTPX2 Request and does not implicitly compose Cookie from the client's cookie jar. A borrowed HTTPX2 client may record received Set-Cookie as transport behavior; the SDK neither reads nor clears that jar.

The generated Accept-Encoding default is `gzip, deflate`. Registered ContentCoding instances with response-decode capability append their lowercase coding names once, in registration order. Typed/raw/streaming APIs use the same value and do not inherit native-client defaults. HeaderPatch may override/delete it, but an override may contain only identity or coding names with active decoders, and RFC q values in 0..1 with at most three decimal places. Duplicate names, `*`, or unregistered codings raise ConfigurationError before sending. Deletion means no header and does not guarantee the server's coding choice. Decoding an unsupported coding raises UnsupportedContentCodingError. Only streaming iter_raw_bytes may return unknown codings without decoding. Do not automatically advertise/import br, zstd, or similar codings based on the environment.

The base URL must be absolute http/https, without userinfo or fragment. Preserve its base path; a leading `/` in the operation path does not remove it. The wirecodec percent-encodes parameters exactly once; do not pass `%`, slashes, or Unicode through string concatenation. Validate server-variable declared names and enums.

Only `client.request_raw(method: str, url: str, *, body: BodyInput[WireValue] | Unset=UNSET, options: RequestOptions | None=None) -> RawResponse` accepts arbitrary URLs. Its async counterpart accepts AsyncBodyInput[WireValue] and returns a buffered AsyncRawResponse after await. The streaming escape hatch is `client.with_streaming_response.request_raw(...) -> ContextManager[RawResponse]`, with AsyncContextManager[AsyncRawResponse] for async; it takes the same arguments and sends only on entry. Ordinary operation path parameters or headers cannot switch to an arbitrary origin. The escape hatch does not infer typed-operation security/replay declarations and defaults to anonymous access. To attach auth, AuthConfig must explicitly permit that origin and explicitly select credentials using send_on_anonymous/anonymous_schemes.

HTTPX2 redirect following is disabled; the SDK processes each hop. Even when enabled, redirects default to the same origin only, and HTTPS→HTTP is forbidden. 301/302 allow GET/HEAD only. 303 changes to GET and removes body/content headers for GET/HEAD or explicit allow_303_to_get=True. 307/308 preserve method/body and require replayability and operation replay safety. Location must have exactly one value; resolve relative values against the current hop URL. Missing/multiple/invalid URLs, exhausted limits, repeated method+URL loops, forbidden origins, or unsafe bodies raise RedirectPolicyError. Never forward original credentials/cookies/signatures to another origin; authenticate and sign again using a provider independently authorized for that origin. Raw paths with redirects disabled return obtained 3xx responses unchanged. However, if HTTPX2 fails while constructing next_request from Location and returns no response, §5 maps this to RedirectPolicyError regardless of enabled/disabled or typed/raw mode. Do not fabricate a bodyless RawResponse.

## 4. Call state, time, cancellation, and counters

Private execution state is `LogicalCallContext`, per-send preparation is `AttemptContext`, and whole-protocol state is `OperationSession`. Generated models must not contain this state.

| State | Binding content |
|---|---|
| Logical call | UUIDv4 call_id, initial monotonic timestamp, effective options, operation ID, auth selection, idempotency key, body source, absolute deadline, resource_attempt_count, redirect_count, auth_exchange_count, network_send_count, network_send_budget_used, auth_exchange_budget_used, auth_refresh_ids |
| Resource attempt | First request or status/transport/auth retry. Increment `resource_attempt_count` immediately before native send. Preparation/hook failures do not increment it. A redirect hop stays within the same attempt and increments only network_send_count |
| Auth exchange | Actual HTTP send to a token endpoint. Default admission limit 2: initial/expiry refresh plus one invalidation response. Report separately from resource attempts. Shared refresh execution uses a provider-independent deadline; each call's wait uses its call deadline; send admission uses the triggering call/parent network budget. Token acquisition has no hidden retry loop |
| Network send | One native adapter send invocation, including OAuth and redirects. Distinct from retries inside an HTTP transport. SDK-owned transport internal retries=0 |
| Send admission | `network_send_budget_used`. A resource hop atomically consumes one triggering-call/parent slot immediately before send; shared OAuth refresh does so before starting the provider job. A reservation is not refunded if the caller leaves. Distinct from actual send count; max_network_sends checks this value |
| Parent OperationSession | Absolute deadline, max_network_sends, cancellation. Children cannot increase the parent's remaining slots or deadline. No new admission after expiry. Only already-admitted shared refresh may finish under its provider-independent deadline. Protocol defaults use SessionOptions from DECISIONS-PROTOCOLS |

`max_network_sends=UNSET` resolves to `1 + max_retries + (redirects.enabled ? max_redirects : 0) + (OAuth acquisition capability ? auth.max_token_exchanges : 0)`. Reauthentication resource sends already belong to max_retries and are not added again. Single-flight waiters do not duplicate shared-send accounting. Charge once to the admitting call/parent and retain related IDs in the provider-independent RefreshSession. Info/errors when a caller finishes contain counter snapshots; outstanding refreshes retain auth_refresh_ids and a pending count. Provider `refresh_snapshot(id)->RefreshInfo` exposes final state, actual send count, and a safe failure category, never tokens or bodies. Pending receipts persist until completion; completed snapshots are evicted oldest first, limited to 128 entries and 5 minutes.

The absolute call deadline is `min(call start+total_timeout, explicit Deadline, parent session deadline)`. Ordinary typed and buffered raw calls include encode/provider/limiter/backoff/send/read/decode. Streaming measures acquisition until handle handoff; afterward it applies stream_idle_timeout, handoff time+stream_total_timeout, and the parent session deadline. Whole-session deadlines for SSE/NDJSON and other protocols follow their protocol contracts.

The native HTTPX2 adapter creates a call-specific public request.extensions['timeout'] dictionary. During acquisition, read is clamped to the initial call's remaining time. After successful headers and before the first body iteration, switch read to min(explicit read cap, stream_idle_timeout, stream/parent session remaining time). Do not carry the completed acquisition call's remaining-time cap into this phase. The ordinary read default of 30s does not implicitly apply to streams. Detect responses whose body a native hook already consumed through public is_stream_consumed and raise AdapterContractError; do not retry transparently after partial consumption. Borrowed/custom adapters require the same handoff conformance.

This handoff uses the public [timeout extension](https://pydantic.dev/docs/httpx2/advanced/extensions/#timeout) and HTTPX2 2.13.0 commit f2951854442e78cb8f6d2256b7c1d83bd2b77d0b: [default transport](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpx2/httpx2/_transports/default.py#L233) → [core Request retaining the same extensions](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpcore2/httpcore2/_models.py#L338) → [first body-reader access](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpcore2/httpcore2/_sync/http11.py#L183). See [evidence status](REFERENCES.md#evidence-status). Do not manipulate private pools/sockets/streams. The HTTP/1.1 reader latches values at the first body iteration; subsequent sync total deadlines therefore use cooperative checks at SDK chunk boundaries and do not claim dynamic resetting for every socket read. Each async anext uses the common bounded-await below to apply idle/stream/parent remaining time. Include HTTP/1.1 and HTTP/2, sync and async, and initial remaining<idle socket acceptance in the dependency lower/latest matrix; verify that future versions support the same public path.

**Sync deadlines are cooperative total budgets, not guarantees that arbitrary blocking work terminates at an exact instant.** Check monotonic remaining time before and after every provider/hook/body factory/serializer/limiter, at every send/read/write chunk boundary, before and after sleep, and before and after decode. Native phase-start values are min(configured phase value, remaining time); do not claim to update native-latched values at every chunk. The SDK alone cannot safely interrupt CPU work or an HTTPX2 blocking operation that does not return control during DNS, header receipt, other HTTP/2 stream-event handling, custom transport work, or similar operations. If expired when control returns, raise DeadlineExceededError instead of returning a result; prohibit subsequent new send/refresh/factory calls. Do not simulate forced return with hidden threads, process termination, or background event loops.

For each native phase value, the adapter records configured cap, effective cap, and constraint source. When remaining logical/stream/parent time determines the cap because it is <= the configured value, including configured None, use `cap_source='deadline'`. If that phase timeout fires, raise `DeadlineExceededError(cause=phase timeout)` without retry even if return time precedes the deadline by a few microseconds. PhaseTimeoutError applies only when the phase's own configured value is smaller. Ties favor the deadline. If stream idle is the smallest limit, idle termination follows the protocol/stream idle contract and is not a logical deadline.

Sync header/body read caps are latched at send or handoff and cannot continuously track later remaining time. One stalled socket read may not return until its latched value. No uniform upper bound is promised for total overrun involving internal multi-read header processing, other HTTP/2 stream events, DNS, or custom blocking. RT02's oracle is DeadlineExceededError when control returns to the SDK and zero subsequent sends, not return at a forced instant.

On Python 3.10–3.14, common async bounded-await uses **an owned operation Task, a deadline timer Future, and `asyncio.wait(..., return_when=FIRST_COMPLETED)`**. The SDK does not inject cancellation into the caller task for deadlines and does not rely on wait_for or private task attributes. Wait for deadline/CancelToken/client-closing signals and operation completion; at expiry, cancel only SDK-owned operation tasks and proceed to release. Borrowed tasks such as shared refresh are merely detached from waiting, never canceled. Timers use loop.call_at; completed signal Futures never receive a second set_result; remove timers/callbacks on every terminal path. Without a deadline or signal monitoring, create no extra timer.

Native CancelledError delivered to the caller is always re-raised, including a race with operation completion in the same loop turn. Observed termination reasons take precedence in this order: native cancellation/KeyboardInterrupt, CancelToken, client closing, deadline, operation result. A successful result never overrides cancellation. External cancellation propagates only to the caller task and starts cleanup of owned operations. Keep cleanup tasks strongly referenced and observe them through the same non-owning asyncio.wait until cleanup_timeout, preserving the original exception. Owners retain and retrieve results of cleanup that exceeds the cap; a later aclose may wait again. Never abandon unobserved task exceptions.

This choice avoids the successful `fut.done()` return branch after `CancelledError` in the pinned CPython 3.10/3.11 wait_for implementations. Public wait has no such cancellation-to-result branch: [3.10 source:432,463](https://github.com/python/cpython/blob/3a19c2f0b3e91ce8f23d0cc64d4c9ee557823f24/Lib/asyncio/tasks.py#L432), [3.11 source:477,507](https://github.com/python/cpython/blob/cd1c3a6342869b7346c1b5c27b8de9c6ef9c4e69/Lib/asyncio/tasks.py#L477), [official wait API](https://docs.python.org/3.10/library/asyncio-task.html#asyncio.wait). Async APIs do not accept sync callbacks; async providers/hooks/limiters/body factories require async contracts. No event-loop preemption during CPU processing or instantaneous cleanup is guaranteed.

`CancelToken.cancel()` is thread-safe. Sync sleep can stop through Event.wait; async waits with a token combine native cancellation with checks at intervals of at most 50ms. Without a token, add no polling allocations/wakeups. Sync KeyboardInterrupt/SystemExit and async CancelledError are neither wrapped in SDKError nor retried. Explicit CancelToken interruption raises `RequestCancelledError`. Once cancellation has been observed, perform cleanup and prioritize cancellation over deadline errors.

## 5. Retry, 401, and redirect state machine

```text
RESOLVE → CALL_START → ENCODE_BODY → AUTH_READY → LIMITER_ACQUIRE
→ BODY_OPEN → BUILD_UNSIGNED → SIGN → ATTEMPT_START → BUDGET_RESERVE → SEND
→ RESPONSE_HEADERS / TRANSPORT_FAILURE
→ [typed read/decode / raw handoff / status-error / retry decision / auth decision / redirect decision]
→ ATTEMPT_END → [BACKOFF → AUTH_READY | RETURN | RAISE]
→ CALL_END (once)
```

Hooks in this diagram observe only; they do not rewrite requests. Check deadlines and cancellation at §4 boundaries. Failure to open a body, sign, or run a hook is a pre-send failure; do not consume retry budget and advance to another attempt.

Retry only when every condition holds:

1. `resource_attempt_count < 1 + max_retries`, with network/parent-session budget remaining and before the deadline.
2. The body source can recreate the same payload; an absent body is replayable.
3. The operation is replay-safe or the native adapter conclusively proves that the application request was not sent.
4. The failure is a retry candidate below and is not prohibited by operation settings or server headers.

| Decision | Fixed rule |
|---|---|
| Operation safety | Default safe methods are GET/HEAD/OPTIONS/PUT/DELETE. POST/PATCH/others require `retry_safety='idempotent'` or an explicit, valid server idempotency contract in generated metadata. HTTP method alone never bypasses payload replay requirements |
| Delivery state | `NOT_SENT` / `MAYBE_SENT` / `RESPONSE_STARTED`. SDK-owned native connect/pool failures derive NOT_SENT from phase/trace evidence below, separately from errno-based transient classification. Custom transports and ambiguous errors without evidence use MAYBE_SENT. Receipt of an HTTP status means the request was sent |
| Transport candidates | ConnectTimeout, transient ConnectError, ReadTimeout/ReadError, WriteTimeout/WriteError, RemoteProtocolError. Read/write and similar failures are generally MAYBE_SENT. TLS certificate/SSL configuration failures, invalid URLs, UnsupportedProtocol, LocalProtocolError, and permanent DNS nonexistence are excluded. Do not infer that unclassified exceptions are transient |
| Status candidates | RetryOptions.statuses. 409 only when explicitly selected by the API. 401/403/407 are excluded from ordinary status retries |
| Authentication retry | Standard trigger: 401 plus Bearer WWW-Authenticate error="invalid_token". Parse multiple challenges and quoted strings; substring matching is insufficient. APIs using challenge-free 401 must declare this in generated auth metadata. Refresh is possible only when the selected provider explicitly has RefreshableTokenProvider capability; StaticTokenProvider and similar providers yield HTTPStatusError(retry_stop_reason='auth_unrefreshable'). Do not refresh for insufficient scope, 403, or invalid credential configuration |
| 401 budget | At most one forced reauthentication per logical call, also subject to the same max_retries/resource-attempt/**operation-safety**/body-replay/network/deadline conditions. 401 is RESPONSE_STARTED and cannot use the NOT_SENT exception. Unsafe POST/PATCH only invalidates the old version locally; no token exchange or resource retry. `max_retries=0` also forbids token acquisition/retry after 401. Necessary token acquisition before the first request is allowed because it is not a retry |
| Decode/arbitrary callbacks | JSON/model validation, presence/codec failures, provider/signature/hook/body-factory programming exceptions, and cancellation are not retried. Typed decode failures after response receipt never reissue the request |

Even when an unsent connection failure would permit POST retry, do not retry if a body factory has lost previously consumed input. `NOT_SENT` is limited evidence from the SDK-owned native adapter; a ConnectError class name from a borrowed/arbitrary transport does not establish it.

Delivery classification is fixed below. RESPONSE_STARTED means HTTP response headers have been observed. Failures after giving the body to the caller are separate stream terminations and never reenter this retry loop. [HTTPX2 public exception classification](https://pydantic.dev/docs/httpx2/api/exceptions/) establishes exception names; the retry-safety rules below are SDK design decisions. See [evidence status](REFERENCES.md#evidence-status).

| Observation | Delivery / automatic retry |
|---|---|
| PoolTimeout or ConnectTimeout from the SDK-owned default native transport | NOT_SENT if resource-request header writing has not started. Pool is a candidate only with retry_on_pool_timeout=True; connect is a candidate. First classify timeouts caused by deadline-derived caps as DeadlineExceededError under §4, without retry |
| ConnectError from the same native transport | NOT_SENT requires evidence that resource headers have not started and the native connect/TLS phase is active. Unknown errno does not change delivery to MAYBE_SENT. Apply the all-leaf transient rule below; SSL/certificate, permanent DNS, and unclassifiable failures are not retried |
| WriteTimeout/WriteError, or ReadTimeout/ReadError/RemoteProtocolError before headers | MAYBE_SENT. Candidate only if method/declared idempotency is safe. Do not retry POST/PATCH on a guess that it was probably unsent |
| ReadTimeout/ReadError/RemoteProtocolError after headers | RESPONSE_STARTED. Candidate under the same safety gate only if a typed/buffered API has not delivered any payload to the caller. No retry after stream-handle handoff |
| Redirect-request construction failure in native HTTPX2 client | RemoteProtocolError/InvalidURL meeting the header-evidence and provenance conditions below becomes RESPONSE_STARTED plus RedirectPolicyError. No retry for enabled/disabled redirects or typed/raw APIs. Do not classify as the user's URL configuration defect |
| InvalidURL, UnsupportedProtocol, LocalProtocolError, ProxyError, DecodingError, SSEError, CloseError | No automatic retry. Map to the appropriate public syntax/configuration/codec/cleanup error; ProxyError is not unconditionally NOT_SENT |
| Borrowed-client/custom-transport exceptions | MAYBE_SENT without adapter-conformant delivery evidence. Exception class name alone does not establish NOT_SENT. Even known I/O exceptions require operation safety |
| Arbitrary ValueError/TypeError/unclassified exception | No retry. Adapter programming exceptions become AdapterExecutionError(cause); callbacks/codecs use their dedicated errors. Do not parse cause strings to infer transience |

The SDK-owned native adapter sets the public request `trace` extension for each attempt. `http11.send_request_headers.started` / `http2.send_request_headers.started` records resource-header start; afterward delivery never returns to NOT_SENT. Distinguish HTTP-proxy CONNECT preparation from the original resource request by checking target-request method/target or forward-proxy absolute-target. Do not forward information objects or headers/bodies to logs/hooks; retain only delivery enums/booleans and the private response-processing snapshot below. Absence of observations alone never makes arbitrary exceptions NOT_SENT; combine native Pool/Connect exceptions with phase contracts. Nonconforming or failed trace handling raises AdapterContractError; do not guess safety. Use the [public trace contract](https://pydantic.dev/docs/httpx2/advanced/extensions/#trace) and pinned [HTTP/1.1:78](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpcore2/httpcore2/_sync/http11.py#L78), [HTTP/2:127](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpcore2/httpcore2/_sync/http2.py#L127), and [proxy:183](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpcore2/httpcore2/_sync/http_proxy.py#L183); lower/latest conformance tests must detect event-name changes.

Privately retain the resource's final-header snapshot from the same trace's `http11.receive_response_headers.complete` return_value `(http_version,status,reason,headers)` or the HTTP2 event's `(status,headers)`. Do not mix in proxy CONNECT headers. Public HTTPX2 send constructs next_request even with follow_redirects=False and closes the response if Location parse/join/copy fails: pinned [_client.py:497,1049,1888](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpx2/httpx2/_client.py#L497), [http11.py:90](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpcore2/httpcore2/_sync/http11.py#L90), [http2.py:131](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpcore2/httpcore2/_sync/http2.py#L131).

Classify this client-processing failure immediately after cancellation/close/deadline precedence. If trace shows 301/302/303/307/308 and a Location, the exception is HTTPX2 RemoteProtocolError or InvalidURL, and the valid cause graph defined in §5 contains no httpcore2-origin exception, raise RedirectPolicyError. Do not restore context suppressed by HTTPX2 with `from None`, or parse exception text. Build ResponseInfo from obtained status/headers, with delivery_state=RESPONSE_STARTED, body_available=False, and the cause preserved. Notify the SDK response_headers event exactly once at catch time in its normal sanitized form, then terminate as a policy error. Never reacquire or resend the response already closed by native code.

For this RemoteProtocolError/InvalidURL classification, an unknown/over-limit cause graph yields AdapterExecutionError with evidenced delivery and cause; do not proceed to transport retry. A known graph with httpcore2-origin RemoteProtocolError follows the existing I/O classification. Other HTTPX2 client-side RemoteProtocolError/InvalidURL with missing trace or 3xx/Location conditions also yields AdapterExecutionError; without provenance evidence, never promote to I/O retry. Only explicit URL validation before sending produces ConfigurationError. The same precedence applies to identically named exceptions from custom hooks/transports on borrowed clients.

Transient inspection traverses the exception cause graph to maximum depth 16 and maximum 64 nodes; identity cycles or excess are unclassifiable. Prefer explicit `__cause__`; use `__context__` only without a cause and when context is not suppressed. For BaseExceptionGroup, recursively inspect every `.exceptions` branch instead of short-circuiting through its cause. Follow other wrappers with causes to terminal leaves. ConnectError is transient only if every leaf is OSError with errno in ECONNREFUSED/ECONNRESET/ETIMEDOUT/EHOSTUNREACH/ENETUNREACH/EAI_AGAIN. Any SSL/certificate node, including intermediate nodes, EAI_NONAME/EAI_NODATA, or unknown leaf makes it false. Do not recover errno from strings. An aggregate OSError without errno or cause is **NOT_SENT but nontransient**.

AnyIO 4.10 wraps multiple connection failures in OSError with an ExceptionGroup cause; direct CPython connection paths may return the last OSError or an aggregate without errno, depending on version/path: [AnyIO:238](https://github.com/agronholm/anyio/blob/27abc2c47526feca2c1ba29a2f48d65f4281c6c2/src/anyio/_core/_sockets.py#L238), [CPython3.10:1067](https://github.com/python/cpython/blob/3a19c2f0b3e91ce8f23d0cc64d4c9ee557823f24/Lib/asyncio/base_events.py#L1067). The same classification evidence uses the same sync/async policy; do not reconstruct errno lost by the OS merely to equalize apparent attempt counts. A NOT_SENT refresh failure does not move rotation state to UNCERTAIN. Local IPv4/IPv6 multiple-address socket fixtures compare POST arrivals, bodies, and refresh state; MockTransport exception names alone do not prove that no request was sent.

Retry-After accepts RFC nonnegative integer seconds or HTTP-date. Fractional seconds are invalid as a standard value and fall back to ordinary backoff. Past dates and 0 mean zero server delay. Invalid values, overflow, NaN, and Infinity are invalid. For repeated raw headers, parse each independently and take the largest valid value; do not split an HTTP-date on its comma. A configured retry_after_ms_header uses nonnegative integer milliseconds; a present valid value takes precedence over the seconds header, again taking the maximum among duplicates. Use wall clock once at receipt to compute a date difference, then convert the wait to monotonic time.

With a valid server delay, wait max(server delay, jittered backoff). Never shorten the server request through jitter or max_delay. If server delay itself exceeds max_retry_after, or the combined wait is >= remaining time, immediately end the call and attach retry_stop_reason='server_delay_exceeds_limit'|'deadline_insufficient' to the last HTTPStatusError/TransportError. max_retry_after does not apply to backoff without a header. If the deadline has actually arrived, return DeadlineExceededError. Close failed responses before waiting; never read unlimited error bodies.

A configured should_retry_header accepts only case-insensitive true/false after stripping leading/trailing ASCII whitespace. False suppresses retries; true enables only status candidacy within 400..599. Conflicting duplicates favor false. Neither overrides safety, body replay, count, or deadlines; true on 401/403/407 still does not enable ordinary status retry.

With `retry_owner='sdk'`, native internal retries=0. `retry_owner='transport'` is available only with an explicitly injected adapter, disables SDK retries and 401 replays, and requires the adapter's contract to satisfy internal count/deadline/body-safety constraints. Do not promise at most three actual network sends for borrowed clients with undeclared custom internal retries. Public metadata defines `network_send_count` as adapter invocations; `wire_send_count` has a value only if the adapter provides evidence.

## 6. Idempotency, body replay, and upload ownership

Generated idempotency metadata requires `header_name`, target operations, `replay_safe_with_key=True`, `retention_seconds`, and key scope. A header name alone does not permit retries of unsafe operations. Create a key once before logical-call encoding and retain it through all attempts/hops. Apply retention relative to a caller key's first_used_at; never retry with an expired key. Do not replace the key to retry the same operation. A caller key with unknown exact prior-use time may be sent but does not establish automatic-retry safety.

`BodySource` is the common contract owned by the private executor. Public inputs are defined below.

Public generic aliases are `BodyInput[PartT] = bytes | FileBody | StreamBody | BodyFactory | MultipartBody[PartT]` and `AsyncBodyInput[PartT] = bytes | AsyncFileBody | AsyncStreamBody | AsyncBodyFactory | AsyncMultipartBody[PartT]`. PartT is invariant and bound to type_params of Python 3.10-compatible TypeAliasType; emit neither PEP 695 syntax nor bare aliases. ClientMediaCodecAdapterV1 `encode -> BodyInput[WireValue]` / `async def encode_async -> AsyncBodyInput[WireValue]` runs exactly once per logical call. It transports field values already converted from model to wire; do not model-encode returned wire-ready FieldPart values again. The runtime converts it to private BodySource and never reruns the encoder on each retry. Re-creatable streaming encoders return BodyFactory/AsyncBodyFactory; one-shot encoders explicitly return StreamBody/AsyncStreamBody. Do not use a lone BodyAttempt as codec output and lose replay evidence.

| Public input | Replay / close / mutation |
|---|---|
| Immutable bytes / JSON encoding result | Retain once-encoded bytes throughout the call and reuse them. Do not rerun serializers per attempt. State that JSON encoding output scales with call input size, separately from response limits |
| `FileBody(file, *, ownership='borrowed')` | Record the current offset at call entry and seek there for every attempt. Without seek/tell, one-shot. Borrowed files are not closed or restored to their starting offset at call end. Their position changes as the SDK reads send chunks |
| `FileBody.from_path(path)` / `AsyncFileBody.from_path(path)` | The SDK opens and closes for each attempt. Differences from initial stat device/inode/size/mtime_ns raise BodyChangedError. The explicitly created async path adapter owns one worker, delegates only disk I/O, and limits in-flight reads to one chunk. This is not async fallback for sync HTTP/providers. File immutability is the caller's contract; equal stat data does not guarantee cryptographic identity |
| `StreamBody(iterator, ownership='borrowed')` / async counterpart | One-shot; no retry after consumption. No implicit SDK buffering/spooling. Owned iterators are closed with close/aclose; borrowed ones are not closed |
| `BodyFactory(factory:BodyAttemptFactory, *, content_length:int \| None=None, content_type:str \| None=None, fingerprint:bytes \| None=None)` / `AsyncBodyFactory` | The factory returns a new BodyAttempt for each candidate attempt and is responsible for identical payloads. Returned BodyAttempt is always SDK-owned and closes on send success/failure/interruption. Factory exceptions are not retried. fingerprint declares/checks payload identity; it is not a feature that fully buffers content to verify it |
| Multipart | `MultipartBody[PartT](parts=...)` / `AsyncMultipartBody[PartT]` are invariant. Only frozen/readonly `FilePart[ContentT_co](name,content,filename,content_type,headers)` and `FieldPart[PartT_co](name,value,content_type=None,headers=())` are covariant. Parts are restricted to the matching sync/async content and PartT below. FieldPart uses the declared part's UseType/UNSET rules and shared codec. The whole body is replayable if every part is replayable. Generate and fix the boundary once per logical call; preserve part order, headers, filename encoding, and field values across attempts. Async field values use the same CPU codec |

Aliases `SyncBinaryBody = bytes | FileBody | StreamBody | BodyFactory` and `AsyncBinaryBody = bytes | AsyncFileBody | AsyncStreamBody | AsyncBodyFactory` name existing binary-input unions; they do not add send paths. FilePart's ContentT_co is bounded by the union of both. Sync parts are `tuple[FilePart[SyncBinaryBody] | FieldPart[PartT], ...]`; async parts are `tuple[FilePart[AsyncBinaryBody] | FieldPart[PartT], ...]`. Fields are name:str, filename:str|None, content_type:str|None, and ordered headers `tuple[tuple[str,str], ...]`. FieldPart value is `PartT_co | Unset`; its other fields are name:str, content_type:str|None, and the same header tuple. Public operations restrict PartT to the OutboundType union for named nonfile parts and nonfile values permitted by additionalProperties schema. Include WireValue only for untyped additionalProperties=true extra values. Use Never only for purely file-only cases with additionalProperties=false and zero nonfile candidates; existing forms without schema use str. Extra binary/file values use the FilePart branch; do not add bytes to WireValue. Explicit value=UNSET uses the existing part plan to omit optional parts or reject required parts, never reaching the wire. Do not mix Unset or model mirror types into PartT itself, or claim a single union statically proves every name/value correlation. Narrower part types may first be created in separate variables and then passed into this union. Only generic raw and post-codec paths use PartT=WireValue.

Read multipart/files in chunks of at most 64KiB, never with a full read. If signing requires a body digest, accept only bytes, seekable sources, or digest-providing factories. Restore the original offset after hashing a seekable source; hashing also consumes the call deadline. Do not prehash one-shot sources or spool implicitly; fail before sending with `BodyNotReplayableError`/`SigningConfigurationError`.

The public BodyAttempt Protocol has readonly properties `content_length:int | None` and `content_type:str | None`, plus `def iter_bytes() -> Iterator[bytes]` and `def close() -> None`. AsyncBodyAttempt has the same properties, `def aiter_bytes() -> AsyncIterator[bytes]`, and `async def aclose() -> None`; aiter_bytes itself is not awaited. BodyFactory's factory argument uses dedicated `BodyAttemptFactory` Protocol `def __call__(context:BodyAttemptContext, /) -> BodyAttempt`; AsyncBodyFactory uses `AsyncBodyAttemptFactory` with `async def __call__(context:BodyAttemptContext, /) -> AsyncBodyAttempt`. Context is a frozen value with only readonly `call_id:str, attempt_index:int, hop_index:int, remaining_timeout:float | None`; remaining_timeout snapshots remaining seconds at callback entry. Pass no secrets or mutable requests. A factory returning the same already-used object raises BodyNotReplayableError. Reject concurrent reads of one borrowed FileBody by multiple calls at call entry; close an owned FileBody once when its final call ends. Explicit adapters such as AsyncFileBody also support close/aclose. SDK client close does not stop a borrowed adapter's worker; its caller closes it.

Concurrent user modification of a file or a factory returning different payloads violates the caller contract; the SDK does not guarantee exactly-once execution or identical bytes. The runtime performs available length/fingerprint/stat checks, maps detected mismatches to BodyChangedError, and does not succeed by generating a new key.

## 7. Auth, OAuth, and signature contracts

`TokenVersion` is public in pkg.auth with exactly this type. This is the contract shape, not an implementation addition.

```python
from dataclasses import dataclass
from typing import final


@final
@dataclass(frozen=True, slots=True, eq=False)
class TokenVersion:
    pass
```

It has no fields or ordering and inherits object-identity equality/hash. Do not attach UUIDs, RNG values, timestamps, or strings. A builtin provider creates one instance when first publishing material and one when committing new material; get for the same published material returns the same instance. Ownership is retained separately. Unknown, old, or other-owner versions passed to `invalidate(version: TokenVersion)` do not invalidate current material. Do not copy, persist, reconstruct, or compare it across providers; TokenSet.revision and store CAS versions remain int/str. An empty dataclass with eq=True would make all instances equal and is prohibited. The scope-knowledge None/tuple distinction, grant normalization, family ownership, refresh counts, and state transitions follow the rules below.

Auth callback annotations are restricted to the dedicated Protocols below. The table omits implicit self. `CredentialMaterial = ApiKeyCredential | BasicCredential | BearerCredential`; it is not an arbitrary-object credential bag. Async def entries give the result type after one await. Existing borrowed/owned ownership, refresh capability, and callback-failure classifications are checked independently of typing.

| Protocol / public value | Binding signature |
|---|---|
| `CredentialProvider` / `AsyncCredentialProvider` | `def get(context: CredentialContext) -> CredentialMaterial` / `async def get(context: CredentialContext) -> CredentialMaterial` |
| `RefreshableTokenProvider` / `AsyncRefreshableTokenProvider` | Extends the corresponding CredentialProvider and narrows get to `get(context:CredentialContext) -> BearerCredential`. `invalidate(version:TokenVersion) -> None` / `refresh(context:CredentialContext) -> BearerCredential`. All three async methods are async def |

Availability of multiple alternatives does not send every credential. Once selected, never silently switch alternatives to different credentials after 401 or another failure.

Anonymous operations send no credentials by default. Even with an explicit auth override, sending credentials not required by an operation requires AuthConfig.send_on_anonymous=True and an anonymous_schemes tuple naming the schemes to send. Unknown schemes/name collisions fail before sending. Signer-only usage also requires send_on_anonymous=True; True with neither credentials nor signers selected is an error. Path matching alone does not authorize an authentication destination. Multiple Clients borrowing one provider still perform each call/hop's security/anonymous/origin/redirect/signature checks; sharing token state does not authorize sending it to another origin.

The public Protocols are `CredentialProvider.get(context: CredentialContext) -> CredentialMaterial` / `async def AsyncCredentialProvider.get(context: CredentialContext) -> CredentialMaterial`. `CredentialMaterial` is frozen and its repr excludes secrets. Builtins cover API key in header/query/cookie, Basic, Bearer, and OAuth token providers. Basic defaults to UTF-8, explicitly overridable through API metadata; Bearer/API key values are not transformed. Read environment variables only during provider execution when the user explicitly selects `EnvironmentCredentialProvider(variable_name)`. Never embed values in generated code.

Public static provider names are `StaticCredentialProvider(material)` / `AsyncStaticCredentialProvider(material)`. Material is `ApiKeyCredential(value: str)`, `BasicCredential(username: str, password: str)`, or `BearerCredential(token: AccessToken, version: TokenVersion)`; get returns the same frozen material. Async get is async def and does not delegate to a thread. Bearer convenience forms are `StaticTokenProvider(token: AccessToken)` / `AsyncStaticTokenProvider(token)`, each with one immutable internal version and no refresh capability. They do not change token.scopes None/tuple. `EnvironmentCredentialProvider(variable_name: str, *, kind: Literal['api_key','bearer']='api_key')` and its async counterpart read that environment variable once per get and create matching material. Bearer creates `AccessToken(value, scopes=None)`; do not infer grants from environment strings, JWTs, or operation requirements. Missing variables raise AuthConfigurationError; never infer Basic credentials from one environment string.

Public CredentialMaterial variants are ApiKeyCredential(value), BasicCredential(username,password), and BearerCredential(token:AccessToken,version:TokenVersion). Location/name come from generated security bindings, never token values. Public frozen `CredentialContext(*, scheme:str, required_scopes:tuple[str,...], audience:str|None, origin:str, deadline:Deadline|None, cancel_token:CancelToken|None)` belongs to pkg.auth. origin is the normalized HTTP(S) origin string, with no path/query/fragment, of **the HTTP request currently being authenticated with this credential**. For ordinary resource authentication it is the current hop; for WS it is the ws→http/wss→https mapped origin from PROTOCOLS. audience is an opaque value required by resource metadata/explicit settings; None means no additional audience requirement. Do not infer audience from the origin string. required_scopes/deadline/cancel_token also belong to that caller. RefreshableTokenProvider adds `invalidate(version: TokenVersion) -> None` and `refresh(context: CredentialContext) -> BearerCredential` to get; builtins implement provider-owned single-flight below. Custom providers must demonstrate declared refresh capability, ownership, and cancellation contracts through conformance tests; merely calling get twice does not establish refresh.

If a caller supplies non-None audience to a builtin refresh provider, get/refresh first checks exact equality with the constructor's fixed audience. Mismatch, including configured audience=None, raises AuthConfigurationError(condition='audience_mismatch'), with zero load/job admission/token/resource sends. Never create another family/key/token request using the caller's value. Caller audience=None imposes no additional requirement. Before using acquired material, also verify that non-None AccessToken.audience matches the fixed audience; mismatch gives the same configuration error without changing provider state. Material audience=None makes no additional claim; do not parse opaque tokens to fill it. Different audience/identity requires an explicitly configured provider for a separate independent token family; do not copy an existing RT into another provider.

Providers are borrowed by default; transfer ownership only with `OwnedCredentialProvider(provider)`. Client.close closes/acloses only owned wrappers. Never pass auth/signing information to SDK logs/hooks.

In public frozen `AccessToken(value: str, token_type: str='Bearer', expires_at: datetime | None=None, scopes: tuple[str,...] | None=None, audience: str | None=None)`, **scopes=None means unknown scope information; a tuple means a confirmed grant**. Empty tuple is confirmed information, distinct from None. Undeclared static/env/custom values use None; users with confirmed grants may supply explicit tuples. Do not parse JWTs from token strings or manufacture grants by adding selected-operation/constructor scopes. Neither unknownness nor scope values are added to repr/str/automatic hooks/logs. Explicit attribute reads and persistence remain allowed.

Apply one canonical rule to every scope tuple. First copy input tuples or explicit lists; each element must be a nonempty ASCII scope-token from RFC6749 §3.3, using only 0x21, 0x23–0x5B, and 0x5D–0x7E. Reject a lone str, arbitrary iterators, and non-str elements. Deduplicate and sort by ascending ASCII to produce the tuple used for public values, request snapshots, wire order, and comparison. Preserve case; do not split commas or trim whitespace. Response scope strings must satisfy the same ABNF; split on single SP and normalize identically. `read read write` becomes (read,write); `read,write` is one token; empty strings, double SP, or leading/trailing SP are invalid. Use the same rule for AccessToken, configured scopes, CredentialContext.required_scopes, code-flow scopes arguments, and scopes sent by device begin. Only AccessToken.scopes accepts None; None for known requirements/configuration raises AuthConfigurationError(condition='invalid_scope'). Local scope type/syntax defects give the same error and fail in the constructor or entry preflight before jobs/HTTP. authorization_request validates scopes before creating state/verifier/request state. Invalid token-response values map to the grant-specific response errors below, never local configuration errors.

Caller scope preflight is common to every bearer provider: raise InsufficientScopeError only when `token.scopes is not None and not set(required_scopes).issubset(token.scopes)`. required/granted/missing are canonical tuples. For None, skip containment checking and send the token to the resource server for its decision. This claims neither unrestricted permission nor successful authorization; anonymous/AND/OR/credential-type/origin/audience/signature/expiry/budget checks remain. An insufficient known tuple fails before sending, regardless of explicit static/env material, custom provider, client credentials, or refresh. Unknown scopes alone do not trigger extra token acquisition/refresh; 403 or insufficient-scope rejection never expands scopes automatically. [Pinned RFC6749 §7](https://www.rfc-editor.org/rfc/rfc6749.txt) requires resource-server token/expiry/scope checks; SDK preflight based only on known information is its own convenience contract.

OAuth automation is fixed below. Every capability requires explicit calls and metadata declarations; never start browsers, callback servers, or persistent stores implicitly.

An AuthorizationCodeFlow request atomically transitions CREATED→EXCHANGING exactly once within its owner, then commits SUCCEEDED/EXCHANGE_REJECTED/REAUTH_REQUIRED/UNCERTAIN/FAILED_NOT_SENT. ### Closed TokenSet and persistence contract

`TokenSet(access_token: AccessToken, refresh_token: str | None, revision: int=0)` is frozen and excludes secrets from repr. revision is a nonnegative integer, monotonically increasing with each replacement in the same family. Here usable/READY denotes validity of token material itself, independent of scope containment for a particular operation. Builtins require **one provider owner per token family**; multiple Clients borrow that same provider. Concurrent refresh of one family by separate providers, separate sync/async instances, or multiple processes is outside the builtin load/store callback contract. Distributed ownership requires an explicit injected RefreshableTokenProvider with an external coordinator. CAS below detects persistence conflicts; it does not guarantee distributed exclusion of token-endpoint sends.

AccessToken/TokenSet equality compares canonical fields. Inputs differing only in scope order/duplicates normalize to the same constructor tuple and do not cause load/CAS conflicts at the same revision solely for that reason. None and () are different; changing between them at the same revision follows existing conflict rules. TokenLoad/TokenStore must preserve that distinction round-trip. In callback JSON AccessToken representations, `"scopes": null` means unknown, `"scopes": []` means known empty, and known nonempty uses canonical string arrays. Never omit scopes and restore an empty grant; adapters reading legacy missing fields must explicitly migrate only to None. This differs from the token endpoint's singular `scope` member; token response `scope:null` is not accepted as unknown. Also distinguish outer load result None, meaning no stored record, and expected_revision=None, meaning create-only. reload/replace uses the received TokenSet's own None/tuple, without filling from earlier cache/configured scopes. PERSIST_PENDING/retry_store persists the same resolved None/tuple/revision with no token HTTP.

**One builtin RefreshTokenProvider/AsyncRefreshTokenProvider instance owns exactly one private FamilyState.** FamilyState is the sole storage for current TokenSet, confirmed_store_revision, PERSIST_PENDING slot and expected revision, forbidden-RT set, initial-load completion, terminal state, active load/refresh/store job, version invalidation, waiters, and lock. Do not copy constructor token_set into caller/origin caches. All get/refresh/invalidate/reload_token_set/replace_token_set/retry_store entry points reference the same FamilyState and serialize concurrent load/rotation/store into one job. Callers from different resource origins join the same family job after passing usage authorization. If a persistence slot exists while its active job remains alive, callers still await that job; only PERSIST_PENDING after a store-failed job terminates waits for explicit retry_store. Persistence/state/version publication completes under the same lock before per-caller scope/audience checks.

Immutable family identity comprises the owner instance and constructor-fixed normalized token_url, including its fixed token-endpoint origin, client_id, client_auth_method, configured audience, and configured scope set. Resource origin, CredentialContext audience/required_scopes, response grants, scheme aliases, Client/view, and call/session IDs are not family identity. Never partition FamilyState/jobs by these values. Configured values remain fixed for the lifetime; explicit TokenSet replacement does not change identity.

Public persistence callbacks are `TokenLoad.load(context: TokenPersistenceContext) -> TokenSet | None` and `TokenStore.store(token_set: TokenSet, *, expected_revision: int | None, context: TokenPersistenceContext) -> None`; async counterparts are async def AsyncTokenLoad.load / AsyncTokenStore.store. Frozen TokenPersistenceContext fields are `provider_id:str, cache_key:str, session_id:str, deadline:Deadline, purpose:Literal['initial_load','before_refresh','invalid_grant_reload','reload','store','retry_store','replace']`. provider_id is an instance-specific UUIDv4; cache_key is the fixed-family configuration fingerprint below and contains no resource-caller origin/audience. Store atomically verifies expected revision and saves durably; already-stored identical revision/TokenSet counts as success. Conflicting different values raise AuthTokenStoreConflictError. The SDK never implicitly retries callbacks or their I/O.

cache_key is `'oauth-refresh-v1:' + sha256(canonical_config_bytes).hexdigest()`. canonical_config_bytes is UTF-8 JSON, ensure_ascii=False and separators=(',',':'), for `[normalized token_url, client_id, client_auth_method, configured audience or null, sorted(set(configured scopes))]`, excluding tokens, secrets, and caller-derived values. This fingerprint is **not a global identifier for a persistent token family**. The caller prebinds load/store callbacks to one persistent-family namespace and selects the same namespace after restart. Different users/grants with identical configuration require distinct namespaces; never use the fingerprint alone as a global store key. The SDK neither parses tokens nor makes the first caller an owner to choose namespaces. Even if a new instance changes provider_id, it can load persisted values from the same namespace/configuration.

expected_revision comes from private `confirmed_store_revision: int | None`, separate from cache.revision. Initially None; update only to the revision of a valid load result, or None for load result None, and to the saved revision after store success. Constructor token_set, memory-only replace, failed load/store, and unknown outcomes never update it. Even when a valid loaded value is older than cache and is not adopted, update this baseline as confirmed external-store state. Both initially unknown and confirmed empty use expected_revision=None; None is not unconditional overwrite.

TokenStore atomically evaluates the same cache key in this order: (1) if destination already has exactly the same TokenSet, idempotent success regardless of expected revision; (2) expected_revision=None creates only if destination is absent; (3) an int replaces only if existing revision matches. Otherwise raise AuthTokenStoreConflictError. Do not automatically store constructor TokenSet on first get. Persistence immediately after initial authorization belongs to the caller; the first refresh storing into an empty store uses expected_revision=None. Memory revision0 does not fabricate an existing persisted revision0.

The fixed constructor is `RefreshTokenProvider(token_url: str, *, client_id: str, token_set: TokenSet | None=None, load: TokenLoad | None=None, store: TokenStore | None=None, client_secret: CredentialProvider | None=None, client_auth_method: Literal['none','client_secret_basic','client_secret_post']='client_secret_basic', scopes: tuple[str,...]=(), audience: str | None=None, options: OAuthProviderOptions | None=None, token_transport: TransportAdapter | OwnedTransportAdapter[TransportAdapter] | Unset=UNSET)`. At least one of token_set/load is required. **Store requires load**; any configuration without load, including token_set+store alone, raises AuthConfigurationError in the constructor, with zero callbacks/workers/token HTTP. Memory-only token_set without store and load-only configurations are allowed. client_secret is an explicit provider returning ApiKeyCredential; required for basic/post, forbidden with none. Generated factories pass these arguments from explicit flow metadata; OpenAPI alone does not infer client authentication. Constructor scopes are syntax-validated/canonicalized fixed-family configuration, not AccessToken's actual grant. They are not a containment gate for operation requirements and never fill known/unknown token.scopes. Default configured scopes=() does not reject tokens with eligible actual grants or unknown scopes. Refresh grants do not send configured scopes; actual-grant preflight uses only token.scopes as above. ClientCredentialsProvider configured scopes are also token-request requirements; caller permission derives only from returned AccessToken. Async variants accept only matching async callbacks/providers/transports, including async-capability checks inside OwnedTransportAdapter. Constructors perform no I/O.

Initial load failure enters LOAD_FAILED with AuthTokenLoadError; later get returns new instances of the same category without automatic repeated loading. Explicit `reload_token_set() -> TokenSet | None`, awaitable in async, performs load once with purpose='reload'. Missing load gives AuthConfigurationError; active job/PERSIST_PENDING/CLOSING/CLOSED gives AuthStateConflictError. Normally use initial-load revision comparison; successful read clears LOAD_FAILED, and absence of both valid usable access and refresh token enters REAUTH_REQUIRED. EXCHANGE_REJECTED/UNCERTAIN/REAUTH_REQUIRED recover only with a usable newer revision that does not restore forbidden tokens. Valid load also updates confirmed_store_revision; preserve the prior terminal state if recovery is impossible. Return cache after adoption, or None if absent, rather than the obsolete external value itself. Never put raw store/load values or token responses in exception strings. Provider close follows the lifetime contract for retrieving admitted rotation/store results and does not claim to supply external-store durability itself.

Map expiry to wall-clock/monotonic time at receipt. expires_in becomes receipt monotonic+TTL; expires_at converts the difference at receipt. Refresh margin is `min(30s, TTL*0.1)`. Zero/negative/invalid expiry has validation cause TokenExpiredError; never refresh indefinitely. Consumable-exchange response validation uses the table's outer exception/state. Cache/single-flight/persistence uses only the one FamilyState and fixed fingerprint; do not add caller origin/audience or granted scopes as keys. Secrets/tokens never enter cache keys, repr, or observations.

For OAuth token-success responses, inherit grant-specific snapshots below **only when JSON member `scope` is absent**. Fix snapshots in private flow/job state without adding public method arguments, return types, or TokenSet/AccessToken fields. Do not add scope to code/device token requests to manufacture an inheritance source, or fill from resource required_scopes, another latest request, or constructor scopes.

Flow/provider response builders must explicitly pass resolved `scopes=...` to AccessToken. client_credentials/code/device pass known tuples and never fall through to AccessToken's None default. Only refresh passes None or a known tuple according to its selected snapshot. Manual/static/env/custom defaults and acquisition-flow omitted responses are distinct paths.

Code/device snapshots belong to each request/flow; creating another authorization request or another device flow's begin never changes an existing snapshot. Initial client_credentials/code/device scope requirements are known tuples: with empty tuple, omitted request scope and omitted response scope preserve known empty tuple. Never change a flow-resolved empty tuple into unknown None; scoped operations treat it as known insufficiency. Only refresh of a manually supplied unknown seed preserves None when response scope is omitted; token/RT/new revision persist normally. Explicit response scope across all grants becomes a known grant after shared validation/normalization, including transition from None to known. Do not union it with snapshots or replace it with requested scopes. `scope=null`, empty strings, and invalid syntax are not omitted members; they take grant-specific token-response validation failure paths, with no fallback to None or snapshots.

Scope reduction alone does not invalidate TokenSet. Code/device success returns valid TokenSet with resolved known grant; reduction does not turn exchange into failure. After refresh store succeeds/READY is published, or client-credentials acquired cache is published, apply the same per-caller scope check as static/env/custom. A known read-only token succeeds for read callers and gives insufficiency for write callers, independently of triggering-caller order. None skips scope preflight; unknown scopes never fail a shared job. Shared-job persistence failures take precedence over scope errors, preserving rotated RT in PERSIST_PENDING. Do not add refresh solely to resolve scope insufficiency or automatically expand scopes after 401/403. External CredentialProvider also declares None or confirmed tuples in CredentialMaterial and receives the same per-caller checks. Builtin injection accepts only Bearer token_type; unknown types require an explicit auth adapter. OAuth client_secret_basic applies OAuth form encoding to id/secret before Basic, separately from general HTTP Basic's UTF-8 contract.

Sources are [pinned RFC6749 §3.3](https://www.rfc-editor.org/rfc/rfc6749.txt), [authorization request](https://www.rfc-editor.org/rfc/rfc6749.txt), [code token request](https://www.rfc-editor.org/rfc/rfc6749.txt), [client-credentials request](https://www.rfc-editor.org/rfc/rfc6749.txt), [§5.1 scope omission](https://www.rfc-editor.org/rfc/rfc6749.txt), [§6 refresh](https://www.rfc-editor.org/rfc/rfc6749.txt), and [pinned RFC8628 §3.1](https://www.rfc-editor.org/rfc/rfc8628.txt), [§3.4](https://www.rfc-editor.org/rfc/rfc8628.txt), [§3.5](https://www.rfc-editor.org/rfc/rfc8628.txt). Code/device uses authorization-start request scopes. Preventing omitted refresh responses from expanding previously reduced known grants, and distinguishing initial-flow known empty requirements from supplied-material unknown None, are SDK choices; they do not claim to determine an opaque token's actual permissions.

Builtin refresh grants omit scope from form data and use prior scope knowledge; they do not re-request constructor or triggering-operation scopes to expand reduced grants. Handle terminal/PERSIST_PENDING/LOAD_FAILED state first. In READY, a caller missing required scopes from tuple-valued cache.scopes terminates with insufficiency regardless of expiry; that insufficiency never starts refresh. With cache.scopes=None, skip the insufficiency check and refresh only when existing expiry/invalidate rules require it. A permitted read caller may likewise refresh expiry using retained RT2. Scope expansion through new consent requires explicit authorization and TokenSet replacement; unknownness never adds constructor/required scopes.

Shared refresh runs as a provider-owned `RefreshSession`; the first caller does not own its worker, deadline, or cancellation. Fixed public defaults are `OAuthProviderOptions(refresh_timeout=30, phase_timeout=TimeoutOptions(connect=5,read=15,write=15,pool=5), max_concurrent_refreshes=1, max_pending_refreshes=32, max_waiters=1024, allow_insecure_loopback=False, transport=TransportOptions())`. Every value is explicitly configurable: timeouts positive finite, counts positive integers, None forbidden. refresh_timeout is the total budget from job admission through reload/HTTP/validation/store/cached-state publication and is not shortened to a caller's deadline. Nonnetwork sessions such as load-only/retry_store use the same finite limit and concurrency/waiter limits.

Providers own token HTTP clients independently of resource clients. OAuthProviderOptions.transport has the same fixed §2 defaults: verify=True, proxy=None, ssl_context=None, trust_env=False, http2=False, pool100/20/5s. Enterprise CA/proxy/mTLS use this explicit configuration. Changing resource configuration does not implicitly affect token configuration; the same immutable TransportOptions may be passed to both. Disabling TLS verification or using transport-owned retries raises an auth configuration error. Explicit token_transport injection requires TransportAdapter/AsyncTransportAdapter, borrowed/OwnedTransportAdapter ownership, and internal-retry=0 conformance. Combining it with nondefault transport construction settings raises AuthConfigurationError. A native http_client alone does not prove absence of internal retries.

Builtin refresh families coalesce to one job; origin or other values never create separate keyed jobs. max_concurrent_refreshes limits the shared executor; values above 1 still permit at most one active job per family. Job-waiting callers are FIFO; exceeding max_waiters raises AuthConcurrencyLimitError. Keep the shared max_pending_refreshes limit, but a family's same next job coalesces into one slot; never create one pending refresh per caller. Before job start, waiting follows each caller's deadline/cancellation; remove an unadmitted job once all waiters leave. At job start, atomically reserve auth/network/parent budgets from the oldest remaining eligible caller and transfer admission to the provider. With neither usable cache nor an already-admitted job, a caller unable to reserve receives **immediate AuthBudgetExceededError** with budget_kind=auth_exchange/network/parent_network; never wait indefinitely for a future eligible caller. Do not add callers unable to reserve as waiters to queued unadmitted jobs. After admission, caller departure never cancels or reelects the shared job; the provider's finite deadline governs completion. Even if all waiters leave, never abandon rotation/store processing of an already-sent refresh.

Builtin sync OAuth providers lazily own a dedicated ThreadPoolExecutor with max_concurrent_refreshes workers. Submit only admitted jobs; no implicit unlimited queue. Each caller waits on Condition under its own remaining deadline/CancelToken; KeyboardInterrupt propagates only to that caller. Never copy caller cancellation, ContextVars, or deadlines into workers. This explicit worker ownership exists only when selecting this authentication; it is not a hidden worker pretending to enforce ordinary sync-call deadlines. If a blocking sync callback/DNS/custom transport never returns, provider deadlines/close cannot force termination and have §4's physical limitations.

Builtin async OAuth providers create jobs with asyncio.create_task on their first-use loop and strongly reference them through completion. Callers use §4 bounded-await borrowed-task mode within their own deadline; departure removes only that waiter. Jobs use independent refresh_timeout and provider-owned HTTPX2 AsyncClient. Never enter/exit AnyIO TaskGroup across tasks, or call a shielded caller task an independent job. Using the provider from another event loop raises UnsupportedAsyncBackendError before sending. Providers always retrieve job results/exceptions; never leave unobserved task exceptions.

On provider-job failure, notify every waiter with **a new exception instance of the same concrete §9 category**, without reelection inside that logical call. Never flatten AuthReauthorizationRequiredError and similar categories into AuthRefreshError itself; callers can catch concrete classes. Do not return another caller's CancelledError. Explicit provider close rejects new jobs and ends queued jobs with AuthProviderClosedError; drain active jobs until their remaining refresh deadline, then close owned token HTTP clients/executors. close/aclose is idempotent. Even if an async aclose caller is canceled, provider-owned cleanup tasks remain strongly referenced and continue; another aclose can await completion. Do not kill sync workers or close borrowed HTTP clients/providers. Provider sync/async caches/workers are separate and must not concurrently own the same refresh-token family.

Invalidate only the token version used by the attempt receiving 401. If another call already published a newer version, use it without duplicate refresh. Even after token update, resource retry must pass §5 budget/safety/body gates.

Local invalid_token version invalidation may run with max_retries=0, but no token HTTP exchange/retry follows. An old 401 never removes a newer version published by another call. External-provider invalidate callback failure is a secondary cause of HTTPStatusError; it cannot turn 401 into success or transport retry.

Signing uses explicit `RequestSigner.sign(request:SigningInput) -> SignatureFields` / `async def AsyncRequestSigner.sign(request:SigningInput) -> SignatureFields` adapters in AuthConfig.signers tuple order. SigningInput contains final method/URL/query/headers/body digest and attempt/hop information; URL and origin identify the current resource hop being signed, never the token endpoint or family fingerprint. Signer capabilities declare allowed_origins/managed_headers/managed_query/requires_body_digest; reject overlapping managed names across signers during configuration. SignatureFields may return only ordered tuples for declared signature headers/query. Order is provider → body framing/Content-Type → signature → readonly attempt hook → send. Refresh nonce/date/short-lived credentials per attempt/hop while retaining idempotency key/body bytes. Never resend the signed request object unchanged. Signer programming exceptions are not transport-retried.

Existing SigningInput observations are readonly `method:str, url:str, origin:str, query:bytes, headers:HeadersView, body_digest:bytes | None, attempt_index:int, hop_index:int`. query is final raw query bytes; do not decode/re-encode for signing. SignatureFields is frozen `headers:tuple[tuple[str,str],...], query:tuple[tuple[str,str],...]`. Readonly signer capabilities are `SignerCapabilities(allowed_origins:tuple[str,...], managed_headers:tuple[str,...], managed_query:tuple[str,...], requires_body_digest:bool)`, with the same managed-name/destination checks and body-digest rules. Add no credential types or arbitrary callback bags here.

## 8. Limiters, pools, ownership, and close

Dedicated Protocols are `Limiter.acquire(context:LimiterContext) -> Permit` and `async def AsyncLimiter.acquire(context:LimiterContext) -> AsyncPermit`. Permit exposes idempotent `def release() -> None`; AsyncPermit exposes idempotent `async def release() -> None`. Frozen/readonly LimiterContext contains only `operation_id:str | None, origin:str, call_id:str, parent_session_id:str | None, remaining_timeout:float | None, cancel_token:CancelToken | None`. remaining_timeout snapshots remaining seconds at entry; existing executors own common deadline/cancellation enforcement. No credentials/headers/bodies. Default is no limiter; do not create a global token bucket. Users or protocol adapters explicitly configure scope/tenant rate limits. Holding a resource permit while awaiting token exchange could deadlock on the same limiter, so the order is fixed:

1. Obtain a token before acquiring a resource permit.
2. Wait for the resource permit under deadline/cancellation.
3. If the token expired during waiting, release the permit and return to auth, applying auth-exchange limits.
4. Open the body, sign, and send; retain the permit until response or stream-handle close.
5. Release response/body/permit before retry/backoff.

Preserve rate-limit headers such as those on 429 in metadata/raw responses; only Retry-After feeds shared retries. Never infer global waits from API-specific remaining/reset headers. Protocol poll intervals, limiters, and retries use the maximum of the same not_before timestamps, without adding the same server wait twice.

SDK-created HTTP clients are owned. Injected http_client is borrowed unless ownership='owned' transfers it. HTTP-client and response ownership are independent; the SDK closes responses from borrowed clients on pre-handoff retry/decode/error/cancel paths.

Client lifecycle is OPEN→CLOSING→CLOSED. At close()/aclose() start, set CLOSING and client_closed signal under lock; reject new calls/admissions/retries/redirects/body factories. Active calls raise ClientClosedError at the next SDK boundary; force-close-induced ReadError or similar failures become its cause and are not retried. Already-observed external native cancellation retains original CancelledError/KeyboardInterrupt under §4 precedence. The SDK never injects cancellation into caller tasks; it may stop only SDK-owned async operation tasks.

Close waits for normal active-call/lease release until cleanup_timeout, closes remaining network handles, and closes the owned resource HTTP client exactly once. Exceeding the cap returns CleanupError with unfinished call/lease counts and safe causes; the owner retains cleanup while continuing to reject new calls. Never claim to forcibly end physical blocking in sync native close/DNS/custom callbacks. Do not close borrowed HTTP clients themselves; release only SDK-owned responses obtained from them. Caller close does not cancel independent OAuth jobs; notify owned providers of closing and let rotation/store drain until remaining refresh deadlines. If they exceed cleanup_timeout, record pending providers in CleanupError without prematurely forcing their token HTTP clients closed. Existing builtin-provider workers/tasks own draining and final close.

Repeated close/aclose during CLOSING waits on the same cleanup for another cleanup_timeout without closing already released resources again. Enter CLOSED when all work finishes; repeated close in CLOSED is a no-op. If an aclose caller is canceled, retain cleanup tasks strongly so another aclose can await them. view.close applies the same rules only to that view's calls/leases, without closing its parent, other views, providers, or pool. Closing the owner parent applies closing to every view's calls/leases.

Internal builtin OAuth-provider notification is `_request_close() -> None`: set closing and terminate the queue under lock, with no caller-side I/O. If unused and without resources, immediately signal completion. Otherwise start exactly one finalizer once admitted-job count reaches 0, or at notification if already idle. Sync submits one finalizer to the existing provider-owned executor, closes the token client, calls `executor.shutdown(wait=False)`, then signals completion. Never join the worker itself using wait=True or create new executors/threads/unlimited queues. Async creates one strongly held finalizer Task on the same provider loop and signals completion after token-client aclose. Retrieve finalizer failures too, making them observable as CleanupError on repeated close. Client waits for the signal only within its cleanup deadline. Custom owned providers require explicit close/aclose capabilities; sync blocking has §4 limitations. Never notify borrowed providers this way.

Executors use only public shutdown APIs. wait=False ends workers after the current finalizer returns and does not kill running callbacks: [official API](https://docs.python.org/3.10/library/concurrent.futures.html#concurrent.futures.Executor.shutdown), pinned [CPython3.10:216](https://github.com/python/cpython/blob/3a19c2f0b3e91ce8f23d0cc64d4c9ee557823f24/Lib/concurrent/futures/thread.py#L216). The completion signal means token resources are released and executor shutdown was requested; it does not guarantee an exact OS-thread termination time. See [evidence status](REFERENCES.md#evidence-status).

After successful stream-handle handoff, the caller must release early when appropriate, but live network handles cannot outlive their issuing client's lifecycle. New read/iteration/text/json/stream_to/raise_for_status after client CLOSING raises ClientClosedError; explicit close/aclose remains idempotently allowed. Fully buffered RawResponse and Response[T] values whose native response/permit are already released survive as values; saved bytes/data/info remain readable after client close. Do not invalidate buffered values as closed handles.

Cleanup failure before normal return raises CleanupError. With a primary exception/cancellation, preserve it; record cleanup failures in SDKError.secondary_errors or, for foreign exceptions, available add_note() and sanitized CALL_END cleanup information. Never overwrite the original failure with cleanup exceptions. GC/__del__ is not a guaranteed normal release path.

## 9. Responses, status/media, and errors

`Response[T_co]` is a frozen value with readonly `data:T_co` and `info:ResponseInfo`; T_co is covariant. It does not change native-model mutability. ResponseInfo contains status_code, ordered duplicate-preserving HeadersView, request_id from a generated-metadata-declared header, call_id, resource_attempt_count, redirect_count, auth_exchange_count, network_send_count, network_send_budget_used, auth_exchange_budget_used, auth_refresh_ids, auth_refresh_pending, elapsed, and content_type. Do not mutate original models to add metadata. No native response/socket is included.

Protocol ResponseInfo is the same `pkg.responses.ResponseInfo` class; do not create separate status/attempt_count records. auth_refresh_pending is a nonnegative int count, not bool. A fresh cache hit creates a new UUID call_id, all counts/budget_used=0, auth_refresh_ids=(), pending=0, and elapsed=lookup+decode time; status_code/headers/request_id/content_type come from the stored representation. 304 revalidation combines the current fetch's call_id/counters/auth/elapsed with the merged representation's status_code/headers/request_id/content_type; actual HTTP304 remains in CacheResult.network_status. Cache-specific policy follows authoritative PROTOCOLS.

`pkg.bodies` exposes media values `FormData = tuple[tuple[str, str], ...]`, `MultipartData[T](parts: tuple[DecodedPart[T], ...])`, and `DecodedPart[T](name: str | None, value: T, filename: str | None, content_type: str | None, headers: HeadersView)`. The latter two are frozen records preserving part order and ordered duplicate headers. Do not freeze/mutate existing models inside T; record repr/str excludes payload, filenames, and header values. DECISIONS-CLIENT §5 owns schema-free form ordering/duplicates, declared multipart part-type/file-byte unions, and schema-free `MultipartData[bytes]` selection/validation. These media value types differ from transport BodyInput/AsyncBodyInput. FormData goes through its media encoder; never automatically turn MultipartData into request BodySource.

Decode and validate every buffered multipart part within ordinary buffered-response size/deadline limits; release native response/permit before returning MultipartData or Response[MultipartData[T]]. Successful-response decode failure returns no partial value and maps to the ResponseDecodeError family after native cleanup. For HTTP error payloads, retain HTTPStatusError under bounded-error rules and store decode failure in error_decode_error. File parts also retain bytes; never use filenames as paths or transfer file/response/socket ownership into returned values. FormData/MultipartData/DecodedPart use the same sync/async value types, usable after client close.

Status schema precedence is exact status → same hundreds range → default. Only actual 2xx statuses are typed successes by default; APIs treating 3xx or other statuses as success must explicitly declare generated success_statuses metadata. 4xx/5xx schemas provide typed error payloads; presence of a schema does not make them successes. HEAD/204/205/304 have no body under HTTP rules. Never return 1xx as a final response.

Compare Content-Type type/subtype case-insensitively and handle parameters separately. Prefer exact declarations, then declared wildcards. Although +json can be parsed as JSON syntax, never apply an undeclared schema automatically. Body without Content-Type raises UnexpectedMediaTypeError even with a single declared media type. Actual body where the declaration requires no body raises BodyProtocolError; bodies stripped by transport for HEAD and similar cases remain subject to raw-byte observation. Invalid/nonconforming success JSON raises DecodeError/ResponseValidationError without retry.

Buffered typed/raw responses default to at most 16MiB decoded bytes; excess raises ResponseTooLargeError. Final error responses retain at most a 64KiB decoded prefix; excess sets truncated=True. Decode declared error schemas only with a complete error body; on failure preserve HTTPStatusError and set `error_decode_error`. Unreadable error JSON is not a connection failure. Intermediate retry responses need not be fully read; close them.

Generated operation bindings register DECISIONS-CLIENT error_class, `<Method>HTTPError(HTTPStatusError[<Method>ErrorData])`. Typed error decode success/failure/unknown media all construct the same operation subclass through the common constructor, preserving error_data/error_decoded/info/bounded body/cause. request_raw lacks an operation binding and uses HTTPStatusError itself.

**The following table is authoritative for all 48 public exceptions owned by this document.** Always generate exactly one of each in pkg.errors. Constructors are keyword-only and accept only inherited fields plus listed additions. Additional fields without defaults are required; properties are not constructor parameters. A narrowed/fixed inherited field uses the same attribute, never a duplicate definition. Classes without extra fields remain independently catchable.

Exceptions own no response/socket/file/permit and are published after required cleanup. Preserving a cause does not automatically log its string.

Clone every additional field, concrete subclass, and cause into separate waiter exception instances; never flatten to AuthRefreshError itself. Never turn None scope knowledge into empty tuple to construct it.

PhaseTimeoutError is catchable with `except TransportError`. SDK/WS adapters set delivery_state from NOT_SENT/MAYBE_SENT/RESPONSE_STARTED evidence and retain native timeout as cause. Internal pre-retry instances use retry_stop_reason=None; final publication uses §5/§9 decisions such as disabled/max_retries_exhausted/unsafe_operation/deadline_insufficient. Deadline-derived phase caps publish DeadlineExceededError instead of PhaseTimeoutError. After stream handoff there are no retries; timeout stop reason is transport_not_retryable. [Pinned HTTPX2 TimeoutException(TransportError)](https://github.com/pydantic/httpx2/blob/f2951854442e78cb8f6d2256b7c1d83bd2b77d0b/src/httpx2/httpx2/_exceptions.py#L143) establishes native classification; the table defines the SDK's own explicit public hierarchy.

For consumable refresh/code UNCERTAIN, failure_kind is deadline for provider expiry, stopped for explicit stop, transport for I/O failure before a complete response, http_status for complete disallowed statuses such as 429/5xx/3xx, malformed_response for permitted-status JSON/§5.2-format/size defects, or invalid_token_response for parseable 2xx values with invalid access_token/expiry/scope syntax/token_type. Valid reduced scopes, unknown-scope inheritance, and caller insufficiency are excluded. Preserve the first cause established in this order and do not rewrite it on later get. Resource-caller-only cancellation/deadline never changes shared-provider state. A terminal refresh provider's get/refresh returns new instances with the same concrete class/state/status/category and no HTTP. Code/device reentry and client-credentials next logical calls follow §7.

Every public exception owned by PROTOCOLS §1.3 is always generated in the same pkg.errors; that table is authoritative for direct bases/additional fields. ProtocolError derives from SDKError, ProtocolStoreError from ProtocolError, and ProtocolConfigurationError from ConfigurationError. UnsupportedContentCodingError derives from ProtocolError, DecompressionLimitError from ProtocolSizeError, ContentCodingProtocolError from AdapterContractError; CRC/trailer/incomplete coding yields ProtocolDataError(condition='malformed'). WebSocketHandshakeError/WebSocketProxyError derive from TransportError. HandshakeResponse is a ProtocolError-derived connector-boundary signal transformed into HTTPStatusError or similar errors for ordinary calls. Do not create separate classes/aliases in pkg.protocols.

Generated operation `<Method>HTTPError` is a **nongeneric** direct subclass fixed to `HTTPStatusError[<Method>ErrorData]`, with no added fields and the same constructor/properties. Do not create a public reparameterizable `<Method>HTTPError[E]`. CLIENT binds the type name; runtime registries consistently use that class. Do not export native ValueError/TypeError/OSError/HTTPX2 exceptions/CancelledError/KeyboardInterrupt/SystemExit as new SDK classes in this table. Native cancellation retains its original type.

`DeliveryState` values are NOT_SENT/MAYBE_SENT/RESPONSE_STARTED. `RetryReason` is the closed Literal set `status | connect_timeout | connect_error | pool_timeout | read_timeout | read_error | write_timeout | write_error | remote_protocol | auth_invalid_token`; attach the actual reason only to retry_scheduled. `RetryStopReason` is the closed set `status_not_retryable | transport_not_retryable | auth_unrefreshable | retry_owned_by_transport | operation_never | server_forbids_retry | disabled | max_retries_exhausted | auth_recovery_exhausted | auth_exchange_budget_exhausted | body_not_replayable | unsafe_operation | network_budget_exhausted | parent_budget_exhausted | server_delay_exceeds_limit | deadline_insufficient | client_closed | cancelled | decode_failure | callback_failure`. Successful results with no retry decision have stop reason None.

When multiple stop reasons apply, first process §4 cancellation/close/deadline and return their dedicated exceptions. Other retry decisions take the first failing condition in this order: excluded failure category/no refresh capability → retry owner → operation never → server false → max_retries=0/exhausted attempts → auth recovery/exchange limit → body → operation safety → call network → parent network → server-delay limit/deadline headroom. For 401, perform every token-independent gate **before refresh**; never start token exchange before unsafe/body/budget rejection. Decode/callback failures use decode_failure/callback_failure respectively; this decision process never creates new attempts for them.

Auth-exchange limits apply only when new HTTP acquisition is needed. Local retrieval of a new token published by another call or of an admitted job's result remains possible with max_token_exchanges=0, but resource retry still requires max_retries/body/safety/remaining network budget. The limit of one forced auth recovery per logical call always remains.

SDKError and all metadata repr/str exclude bodies, credentials, query values, and concrete path parameters. Users may explicitly access body_bytes/raw headers, but the SDK never automatically sends them to logs/hooks. HTTPStatusError strings contain only status, operation ID, request ID, call ID, and retry stop reason.

Because cause retains the original exception, do not claim complete redaction by rewriting caller-defined exception strings. The SDK itself never automatically emits cause strings/tracebacks; hooks receive only safe categories. Explicit caller logging of the entire exception chain belongs to the caller. Request IDs come only from declared diagnostic headers, never guesses from arbitrary headers.

## 10. Raw/stream responses, content coding, and downloads

RawResponse has readonly `info:ResponseInfo`, `read() -> bytes`, `text() -> str`, `json() -> JSONValue`, `iter_bytes() -> Iterator[bytes]`, `iter_raw_bytes() -> Iterator[bytes]`, `raise_for_status() -> None`, `close() -> None`, and context-manager support. Import the same public JSONScalar/JSONValue/WireValue aliases from pkg.model_codecs; do not redefine them in responses. Validate untyped JSON-parser values at an object boundary; never cast to arbitrary T. Buffered raw stores original content-coded bytes as raw_body_bytes and once-decoded bytes as body_bytes. Each is <=max_response_bytes, for a default combined maximum 32MiB plus decode/chunk workspace. Identity coding shares the same immutable bytes. Close native response/permit before return; saved-byte read/text/json/iteration may repeat. Close releases native resources without discarding saved bytes.

AsyncRawResponse has the same info/body_bytes/raw_body_bytes and `async def read() -> bytes` / `text() -> str` / `json() -> JSONValue` / `raise_for_status() -> None` / `stream_to(...) -> None`, `def iter_bytes() -> AsyncIterator[bytes]` / `def iter_raw_bytes() -> AsyncIterator[bytes]`, and `async def aclose() -> None`. Buffering does not change public awaitable shapes. Response[T]/ResponseInfo are the same sync/async value types.

Streaming RawResponse is a one-consumption handle. Choosing read() first buffers raw/decoded bytes under the same limits and then permits rereads. Choosing iter_bytes()/iter_raw_bytes() does not retain consumed portions; switching consumption APIs, reiterating, or reading midway raises ResponseConsumedError. Select the method only before iteration starts. text uses Content-Type charset or UTF-8 if absent; decode errors raise DecodeError. JSON syntax decoding is separate from model decoding. Never discard parsed values and silently switch to raw.

Only §2 max_stream_bytes governs streaming total size. Default None prevents identity-coded large downloads from stopping at 16MiB. iter_bytes/stream_to count decoded bytes; iter_raw_bytes counts content-coded bytes. Before passing a chunk that would exceed the cap to the caller, terminate and close with ResponseTooLargeError(representation='decoded'|'content_coded', limit, observed_bytes, info). read/text/json also applies buffer limits. Finite expansion-ratio/codec-workspace caps remain even when total size is None; do not create disconnected DownloadOptions.

Native adapters receive every response with stream=True and pass content-coded bytes from iter_raw/aiter_raw to codecs. iter_raw_bytes preserves content coding; iter_bytes/read/text/json removes it exactly once. DECISIONS-PROTOCOLS C33 is authoritative for gzip/deflate/identity, expansion limits/ratios, and request compression; do not duplicate HTTPX2 automatic decoding. Read chunks are at most 64KiB; decoded buffer/error limits follow §9.

Raw final 4xx/5xx never raises automatically. `raise_for_status()` uses typed-path status classification: success returns None without reading a body; 4xx/5xx produces typed HTTPStatusError from the bounded error prefix; undeclared 3xx produces UnexpectedStatusError. Close the response on failure. After partial iteration, do not read more or infer an error schema; construct the status exception with body_bytes=b'' and truncated=True. Return raw final 304 without a body. Ordinary typed 304 raises UnexpectedStatusError unless generated success metadata declares it; never disguise it as T. C25 cache helpers explicitly merge raw304 with existing representation and decode the original T. Disabled caching creates no cache state/allocations. Cache keys/Vary/tenant isolation/CacheResult follow DECISIONS-PROTOCOLS.

`stream_to(path: str | PathLike[str], *, overwrite: bool=False) -> None` owns its file, writes decoded bytes incrementally to a temporary file in the same directory, and moves to the final path only on success. With an existing file and overwrite=False, raise FileExistsError before consuming the body; HTTP acquisition of RawResponse has already happened. Commit also uses an exclusive no-replace operation so a newly racing file is not overwritten; only overwrite=True uses atomic replace. On failure delete the temporary file and preserve existing files. `stream_to(file_object: BinaryIO) -> None` borrows the file and never closes/seeks/truncates it; partial failures do not roll back bytes already written. Never automatically use Content-Disposition as a save path.

Breaking iteration alone does not establish close. Callers must use with/async with or close/aclose. The SDK releases response/permit at normal EOF too. Midstream decode/size/idle/total-timeout/cancellation releases resources, with no transparent retry duplicating delivered bytes/events.

## 11. Hooks and secret handling

Public hooks use separate Protocols: `Hook.on_event(event: CallEvent) -> None` and `async def AsyncHook.on_event(event: CallEvent) -> None`. Hook return values never modify requests. Mutation uses dedicated public RequestOptions, CredentialProvider, RequestSigner, and BodyFactory contracts.

Each immutable event contains only call_id, operation_id, parent_session_id, candidate-attempt index, sent flag, phase, status, duration, retry_reason, and safe counters. URLs contain only operation path templates and origins; no query/header/body/credential/token values. Request-ID headers are passed only if generated metadata marks them public diagnostics. context is a caller-declared secret-free scalar map of at most 8KiB.

| Order | Event / count |
|---|---|
| 1 | `call_start` once; only a nonsecret effective-options summary |
| 2 | When needed, `auth_start`→`auth_end` covers the caller's auth-wait interval; single-flight waiters use `auth_wait`. Charge shared-job admission only to the triggering call; provider-job completion after caller departure never notifies hooks of an already-ended call |
| 3 | When needed, `limiter_wait`→`limiter_acquired` |
| 4 | `attempt_start` after body/signing, still sent=False. If it fails, do not send |
| 5 | Reserve budget → send. Receipt emits `response_headers`; I/O failure emits `transport_failure` |
| 6 | `attempt_end` after response close/typed decode or raw handoff. Even an aborted prepared attempt emits exactly one end with sent=False |
| 7 | `retry_scheduled` only when retrying, with delay/reason; after waiting return to step 2. Redirect stays in the same attempt: `redirect` → new-hop signing/send/headers |
| 8 | `call_end` exactly once, with success/error/cancel/handed_off and terminal counters. Streaming-handle termination emits one separate `stream_end` |

Pass each event to all hooks in registered tuple order. Even if one raises, run the remaining hooks for that event to collect information, but stop subsequent network actions. If the main operation still counts as successful, return the first hook failure as HookExecutionError(cause) and put remaining failures in secondary_errors. If a primary exception/cancellation already exists, preserve it. Never recursively renotify call_end when call_end fails. Terminal-hook failure after success makes the call raise HookExecutionError. There is no default that ignores hook failure and continues to another attempt.

`HookExecutionError[T]` retains `event_name`, `sent: bool`, `delivery_state: DeliveryState`, `info: ResponseInfo | None`, `has_completed_result: bool`, `completed_result: Response[T] | Unset`, `cause`, and `secondary_errors`. sent means a resource adapter send was invoked at least once; OAuth-only sends do not make it True. If a hook fails after completed typed-success decoding, save original data/info in completed_result, obtainable through `require_result() -> Response[T]`. A successful None value still gives has_completed_result=True. Undecoded/failed/raw/stream results use completed_result=UNSET; require_result raises ResultUnavailableError. Preserve acquired headers in info, but the SDK releases live response/permit ownership instead of transferring it into the exception. repr/str excludes data/headers/bodies. Even call_end failure after nonidempotent POST201 allows callers to distinguish sent success, with zero automatic retries.

Ownership transfer of raw/stream handles occurs only after attempt_end/call_end succeeds and the method/context enter returns. Earlier hook failure makes the SDK close handle/permit. stream_end hook failure at normal EOF/explicit close yields HookExecutionError; with an existing stream failure/cancellation, it is secondary.

Without registered hooks, do not construct event objects/lists/context summaries. Logging/metrics/tracing exporters are not mandatory runtime dependencies. SDK internal logs exclude bodies, URL queries, and header values; never enable HTTPX2 logging automatically. Separately user-configured native HTTPX2 event hooks are transport-owned callbacks; the SDK does not guarantee redaction of their output.

## 12. Backend and wirecodec boundary

C10/C11/C27 uses existing models and the established wirecodec unchanged. The private request boundary uses operation/use-bound input-only `RequestEncoder[ArgumentsT_contra]` Protocol with `encode(arguments:ArgumentsT_contra, *, presence:Mapping[str,PresenceTree]) -> EncodedRequest`. ArgumentsT_contra is contravariant and fixed to each operation's established Arguments TypedDict; presence references existing PresenceTree values for those argument names. Bind output to readonly `ResponseDecoder[T_co].decode(body:bytes, info:ResponseInfo) -> T_co`; `execute(request:EncodedRequest, decoder:ResponseDecoder[T]) -> Response[T]`, with async def returning the same result type in async. Do not erase Arguments into generic kwargs/Any; use Unpack[that Arguments TypedDict] only for necessary forwarding. Do not create entry points returning free T through string registry lookup alone. The runtime never scans model __dict__ or field order to repair values.

For every builtin backend—Pydantic v2 BaseModel, Pydantic dataclass, stdlib dataclass, TypedDict, and msgspec—the codec owns presence, aliases, custom serializers, strictness, extra/enum/union behavior. Unknown enum/discriminator/field behavior follows model settings; typed decode failure is ResponseValidationError(ResponseDecodeError). The runtime adds no Literal→str, forbid→allow, or alternative-union-branch fallback. Explicit raw APIs are available for every backend. T is statically declared by codec binding; use DecodedValue[T], the union of public ModelValue[T]/ModelInput[T], only for uses requiring envelopes. Arbitrary validation failures never switch to this envelope.

Request Content-Type follows declared method media and explicit body/media_type selection; a header string alone cannot relabel JSON as XML or another body format. With multiple media and no generated default, require explicit media_type. response_media_type narrows Accept and success-decode bindings while retaining every declared error media type. Conflict between Content-Type patches and selected codec/framing, or Accept patches and explicit response_media_type, raises ConfigurationError before sending. Validate the codec capability table for JSON vendor media, text, binary, form, multipart, XML/custom media during generation; missing required codecs stop that client generation with a diagnostic. This validates media capabilities without reducing builtin model-backend support.

Generation configuration maps to `ClientGenerationConfig.runtime_defaults: RuntimeDefaultsConfig` and `operations[].runtime: RuntimeOperationMetadata`. The former permits only timeout/total_timeout/retry/redirects/max_network_sends/max_response_bytes/max_error_body_bytes/max_stream_bytes/stream_idle_timeout/stream_total_timeout/cleanup_timeout/compression. Do not embed provider/callback/client/protocols/transport instances in generated code. TOML one-key None tags and closed nested-field sets follow authoritative DECISIONS-CLIENT; this document governs effective defaults/merging.

| RuntimeOperationMetadata field | Type and default |
|---|---|
| retry_safety | Literal['method_default','idempotent','never']='method_default'. never prohibits resource retries including NOT_SENT/401 |
| idempotency | None or a record with header_name:HTTP token / replay_safe_with_key:bool / retention_seconds:positive finite seconds / scope:nonempty opaque string. Applies to that operation |
| request_id_header | str or None, default None. str must be an HTTP token |

Security is a **derived RuntimeOperationPlan field** containing AND/OR/flow resolved from OpenAPI, not an input in operations[].runtime. Overrides never make required security anonymous. Unknown fields fail during generation. Generated README identifies configuration locations for vendor headers/401 exceptions.
