# Final contract for the dcg FastAPI target

These are **design decisions for implementers to adopt**, not a record of implementing or publishing a new generator, runtime, or public API. This document fixes the design choices for [F01–F13](FASTAPI-REQUIREMENTS.md). Verification uses the independent oracles below; tests that have not been run must not be treated as passed. The original research sources cited are D=`3452dfbb428c4384f40cb16faf61aadfda58a3a8` and F=`b3b9bd66e0b0c4d8c686fda700258104615a1332`. The **implementation baseline for this plan is D=`4f96e22ea403a66faae96f3949d41dd61fc1186f`**, distinct from the original research SHA. See [REFERENCES](REFERENCES.md#evidence-status) for the published evidence scope and [IMPLEMENTER](IMPLEMENTER.md) for implementation prerequisites.

D owns the new implementation. It must not depend on the old F code/parser/templates/runtime, nor provide a bridge that invokes the new D from old F. Old F continues ordinary maintenance of its existing generator and deprecated notices in docs/help. This contract does not reproduce old F's generated bytes; it provides the existing practical capabilities under the new rules below. D's existing behavior and all model artifact bytes for the same D and the same explicit model settings remain unchanged.

Each generation selects either the server or the client. There is no dedicated API/CLI for simultaneous generation, and FastAPI must not invoke the client generator. Each target uses the same source specification, D, and explicit model settings, and independently uses the neutral binding/codec. The new explicit `OpenAPIScope.Api='api'` is an additional ordinary D scope defined in BINDING; targets must not silently enable it when needed. Compare all model bytes with ordinary D generation using that same explicitly selected scope.

## 1. Entry points, configuration, and execution phases

[DECISIONS-ENTRY](DECISIONS-ENTRY.md) is authoritative for public entry points, TOML, distribution, CLI exit codes, model generate/verify, and publication. Export `FastAPIConfig`, `generate_fastapi`, and `render_fastapi` from `datamodel_code_generator.fastapi`. The existing datamodel-codegen CLI explicitly selects `--generate-server fastapi`, mutually exclusive with `--generate-client httpx`. Required `--target-config PATH` uses flat TOML with schema_version=1; `--target-output` overrides its output. Existing `--output` controls model output. The existing CLI also owns input/profile/model settings; do not duplicate them in target TOML. Add no new dedicated console/module main or simultaneous-generation entry point. Protect the existing CLI path when no target is selected.

`FastAPIConfig` is a frozen, keyword-only record. Common fields are ENTRY's `output/package/model_package/model_mode/package_mode/distribution_name/package_version/model_dependency` and common selection/format settings. Capture input mappings/sequences as immutable values at config construction, retaining callable identity. Use only ENTRY's common config rules for unknown fields, invalid types/values, and the mapping between Python constructor and TOML/CLI diagnostics/exit codes; do not create server-specific TypeError conversion rules. Model options belong only in GenerateConfig.

Path bases, CLI overrides, and package roots follow ENTRY. Do not mutate the original config passed to the Python API. Do not rewrite model output/scope/backend/Python version for the target's convenience. OperationSelector is a plain RFC6901 pointer or OperationRef(pointer, document=None); both resolve to the same root use-site OperationId. Path/URL inputs use the canonical root URI; Mapping/raw-string inputs use the logical identity urn:dcg:root. An explicit document is accepted only if it matches the root; the declaration URI of an external Path Item is not an operation selector's target. External URIs in SchemaRef identifying type declarations have a separate contract. Selector syntax, source existence, and common binding use the same implementation in [DECISIONS-BINDING](DECISIONS-BINDING.md); do not create a separate FastAPI resolver.

The fixed phases are: (1) new config/path collision validation and the backend check below; (2) ordinary D's same accepted attempt, ordinary emit/formatter/stage, and binding validation; (3) explicit selector validation/selection and selected-operation wire/native/adapter capability validation; (4) naming and route planning; (5) hooks; (6) revalidation of hook changes and all template rendering; (7) server format/encode/compile; (8) all artifact ownership, partial-update, and model-verify comparisons; (9) ENTRY's single publication batch. Never fall back to another parser or old F on source/template/hook failure. Published output remains untouched until (9). Release the source lease/graph by the common contract's deadline; frozen server plans retain no live parser/graph.

Only the new coordinator specified in ENTRY §5.2 performs the backend check, exactly once. Immediately after existing GenerateConfig validation and warn→preset→missing sentinel→metadata checks in their existing order, the new coordinator checks effective output_model_type. Server selection permits only §2's two enum values; client selection permits all five. An excluded valid enum produces one APIGenerationError diagnostic with E_FASTAPI_BACKEND_UNSUPPORTED, stage='config', option_path='model_config.output_model_type', target_id=null, and existing D CLI ERROR=2. This is a semantic failure for a valid enum, not a usage syntax error. Earlier existing model-config violations take precedence, retaining their original exception type and ENTRY's E_MODEL_CONFIG. This check precedes the remote lock helper, staging, _run_generation preparation/parse/backend factory, and target hook/adapter loading. Do not insert it into existing D helpers or the server runtime. Use the same check for generate/render, model generate/verify, and --check. CLI success/difference/error follow existing Exit values 0/1/2. Interrupts retain ENTRY's existing SIGINT handler and control-exception semantics; do not equate KeyboardInterrupt enum=3 with the actual SIGINT exit value. After rollback, do not convert the original KeyboardInterrupt/SystemExit to another code; the Python API must not import the CLI's __main__.

## 2. The server's two backends and generated layout

The new server's builtin model backends are limited to **Pydantic v2 BaseModel and Pydantic v2 dataclass**. The exact [D enums:53](https://github.com/datamodel-code-generator/datamodel-code-generator/blob/3452dfbb428c4384f40cb16faf61aadfda58a3a8/src/datamodel_code_generator/enums.py#L53) are DataModelType.PydanticV2BaseModel (pydantic_v2.BaseModel) and DataModelType.PydanticV2Dataclass (pydantic_v2.dataclass). DataclassesDataclass, TypingTypedDict, and MsgspecStruct are outside the server's builtin support; routing them through adapters does not make them supported server backends. The client retains all five backends, including their common codecs/bindings. **Determine native or adapter handling at generation time for each parameter, request body, and bare primary response; use one FastAPI system for app/router/DI/security/errors/lifecycle.** Do not split whole operations into two backends or switch approaches on failure.

Native handling uses FastAPI's public Annotated/Path/Query/Header/Body/Form/File/UploadFile/response_model. Adapters connect types, styles/media, directional projections that standard handling cannot represent, or explicit custom codecs, to the same route through Depends or Response conversion. Under ordinary generation settings, native primary responses are limited to source media application/json with no parameters, distinct from request support for a single JSON/+json media type. Native parsing/coercion/validation/filtering follow the FastAPI/Pydantic contract; do not claim equivalence for every input with the client's and adapters' strict wire codec. Preserving schema/model bytes is separate from routing every server path through the same codec. Body/response business types are actual types within the selected two backends; only native primitive parameters use §5.1's wire-value surface, while codec-adapter parameters use common T/DecodedValue[T]. None changes the model's own annotations/base/fields/defaults/aliases. If ordinary D emits a RootModel, use that actual type; if ordinary D collapses or aliases it, use the finalized type expression. Do not port F's model deletion through [`_collapse_root_model`:1008](https://github.com/koxudaxi/fastapi-code-generator/blob/b3b9bd66e0b0c4d8c686fda700258104615a1332/fastapi_code_generator/parser.py#L1008) or discriminator removal through [`get_field_extras`:726](https://github.com/koxudaxi/fastapi-code-generator/blob/b3b9bd66e0b0c4d8c686fda700258104615a1332/fastapi_code_generator/parser.py#L726).

Primitive/container/enum/union/RootModel types and ordinary D alias/collapse results are types used within those two backend settings, not selections of another model backend. Never implicitly convert model_config.output_model_type from the three unsupported server backends to Pydantic; do not skip the backend check even for primitive-only schemas, empty operation selections, or body_mode=request. Reuse of custom model templates/bases or existing Python types is an extension through MODEL-CODECS §12's explicit compatibility/export/codec contract, tested separately from automatic compatibility of the two builtins. These registrations do not change the allowed backend set or bypass exclusion of the other three backends.

The package's Python root is written as `pkg/`. Actual embedded/standalone roots follow ENTRY. Model files remain at the separate model_config.output explicitly chosen by the user; do not move them into the tree below.

|Artifact|Ownership and role|
|---|---|

|`routers/__init__.py` plus `routers/<group>.py`, or `routes.py`|Owned. HTTP endpoint adapters and build functions in declaration order. Not a place for business code|

|`responses.py`, `errors.py`, `auth_types.py`|Owned. HTTPResult below, `<PascalOperation>ResponsePayload` type aliases / `<PascalOperation>ResponseCodecs` facades in operation order, HandlerConfigurationError/AuthConfigurationError/OpenAPIConfigurationError, and §7's typed AuthContext/Authorizer/Credential, etc. Separate from generated models|
|`services.py`|Owned. One `<Group>Service` Protocol per router group in §3's group order, with an abstract method per operation in operation order (see below). Business logic lives in user modules that implement these Protocols; the target generates no business stubs, application module, or authorizer module|
|`py.typed`, dependency documentation/README/standalone pyproject, etc.|Owned artifacts for ENTRY's package modes. Do not require a fixed seven-file layout. Explicit selected operations, groups, backend/media, and template settings determine the tree. Default target order follows the table; routers and service Protocols follow §3's group order, their operations follow operation order, and runtime files use ascending str order of relative paths within the dependency closure. ENTRY takes precedence for commit order of shared distribution files and manifests.

Every target artifact is generator-owned and rewritten on every run; the target has no create-only files. Users keep service implementations, authorizers, and the module that builds the application in their own modules outside target-owned paths; the generator never reads, imports, adopts, or writes them. An existing file at a planned path that the previous valid manifest does not own is ENTRY's E_OUTPUT_CONFLICT; an owned file that was edited or deleted is rewritten like a model file, and regeneration never merges handwritten edits into owned files. Do not infer generator ownership merely from an existing ordinary file's name.

Each `<Group>Service` is a `typing.Protocol` whose methods are `@abstractmethod` instance methods named by the operations' finalized Python names, taking `self` and then §3's keyword-only arguments and returning §6's return type; async operations declare `async def`. The group name `service`, the single layout's default, yields `Service`; other group names yield `<PascalGroup>Service`. Only groups with an operation receiving a principal are generic, as `Protocol[PrincipalT_contra]` with one contravariant TypeVar declared in services.py; operations with an anonymous alternative take `PrincipalT_contra | None`, and unauthenticated operations omit the principal argument. Users implement a group by subclassing its Protocol, so type checkers report missing or mismatched methods at the class and Python refuses to instantiate a subclass while an abstract method is missing, or by passing any object with the same methods, which type checkers check structurally where it is passed to a builder. The generator neither infers the user's Principal type nor emits conformance assignments, casts, or types erased to object; the generated README's implementation example subclasses the Protocols and passes the instances, with a matching authorizer when an operation is secured, to one builder call. Follow [TYPING §5](DECISIONS-TYPING.md)'s generic/variance rules. The builder's startup checks (§4) complement type checking but verify shapes only. Type-checking CI includes actual implementation modules and typed builder calls, not just services.py, and checks body type errors, signature differences, missing methods, and imports of user-added helpers. Generate no `.pyi` beside services.py or other generated modules: a stub takes precedence over its `.py`, so a stale stub would hide Protocol changes from implementations. See the [official mypy stub precedence rules](https://mypy.readthedocs.io/en/stable/stubs.html#creating-a-stub) (checked 2026-09-17).

### 2.1 Generation-time decisions at each boundary

Use the first applicable reason in the order below. Decisions use BINDING's final type/field/alias/constraint facts and source schema semantics; the generator must not import generated modules and experimentally register them with FastAPI. Even with explicit MODEL-CODECS compatibility for a custom template/base, do not infer that opaque validators/serializers or unmatched aliases are native. Implementation conformance tests must substantiate this table itself.

|Boundary and condition|Generated path|
|---|---|
|body_mode=request / explicitly applicable codec registration|Give priority to raw_request / codec_adapter respectively. Do not propagate the choice to other boundaries|
|Ordinary parameter|Builtin scalar (str/int/float/bool, date/datetime/UUID, corresponding enum/const/Literal) or a one-level list of those for query. path=simple scalar; query=form scalar or repeated list with explode=True; header=simple scalar. All cookie styles, including form, always use the common adapter; do not make an exception selecting native for values requiring no percent encoding. Native applies only when an ordinary FastAPI location declaration represents the actual style. See §5.1 for nullable/optional. Other styles/compound parameters use an adapter with the same common codec|
|JSON body|Single JSON/+json media, projection_mode=native, the selected Pydantic v2 BaseModel/Pydantic v2 dataclass and their primitive/container closure. Support object/nested/array/map/ref/enum, plus allOf that the common layer has finalized as simple inheritance/field composition. Use an adapter for T construction blocked by directional differences, opaque/custom types, shape/required/alias mismatches, required nullable whole bodies, or uses requiring absence/null distinction for an optional whole body. Pydantic RootModel/pure aliases are native when wire shapes match; shape differences such as a Pydantic v2 dataclass root-field wrapper use an adapter|
|Typed form/file|Native under §5.2's flat-property, standard-repetition, ordinary File/Form conditions. Never automatically change other cases to raw; diagnose the need for a supported adapter or explicit Request/custom template|
|Bare primary response|Use response_model=T when the selected normalized media is application/json without parameters, with the same native type closure above, no directional-exclusion/required/alias/shape/nullable/presence mismatch, and no required response header that a bare value cannot supply. Ordinary Pydantic v2 BaseModel models whose fields_set can feed standard exclude_unset, and Pydantic v2 dataclasses without presence differences, are native candidates. +json and media parameters send only that primary to an adapter with unsupported_wire_shape. Do not claim that all Pydantic output is native|

Standard Form media extraction follows FastAPI-specific rules, including empty field→missing/default, separate from conformance to a strict raw form codec. Native assertion matching below concerns type/constraint projection after that extraction. Explicitly document this difference in the generated README, NativeDeclarationView.api=Form/File, and F06; require explicit body_mode=request when exact source-wire empty values/presence matter.

Native-candidate schema assertions are limited to type/properties/required/items/additionalProperties, enum/const, minimum/maximum/exclusive bounds/multipleOf, min/maxLength, min/maxItems, and formats allowed in the next table. For body/primary responses, verify that actual builtin output annotation/constraint/extra settings preserve the same assertions; for parameters/forms, verify §5.1's public FieldInfo projection. Type coercion need not equal the strict codec. However, known validation-mode differences where validate_json accepts schema-valid JSON but FastAPI's request.json→validate_python rejects it, such as a Pydantic date field with Field(..., strict=True), always use an adapter with opaque_native_semantics. Matching type/alias/nullable alone must not hide this difference. Known serialization settings that map a nonnullable number to null, for example, are also not native; opaque settings that formal backend facts cannot resolve use the same reason. The native/codec rules below apply to the two selected Pydantic v2 server backends. Client support for the other three backends does not expand server support. This example uses D field extras; do not assume the pinned D has a strict ConfigDict option. anyOf/oneOf other than nullable, not/if/then/else, dependent*/unevaluated*/patternProperties/propertyNames/contains/prefixItems, uniqueItems=true, pattern, unknown assertions/vocabularies, and unprojected constraints use adapters. Annotations such as title/description/examples/deprecated/$comment do not change the decision. If an explicit parameter/form default is not a same-typed literal of the native surface (such as a string default for date/UUID), use an adapter; do not pretend an unvalidated framework default has the correct type. additionalProperties=false requires native settings that actually forbid extras; ignore is not equivalent. Even simple allOf uses an adapter if unprojected assertions remain. A format that does not match its corresponding native type requires an adapter. Ordinary datetime also accepts values without a timezone, so it alone does not satisfy date-time's mandatory RFC3339 offset. It is a native candidate only when the final annotation/constraint formally represents the required timezone or other requirement; otherwise use an adapter with source_assertion_not_projected. Do not add timezone guards to force native handling.

Format and existing-sentinel decisions are fixed below. Use format names after common normalization; do not infer new assertions from unknown names. Compare numeric ranges using only existing boundary facts, without implementing arbitrary schema implication. The table does not waive other shape/required/alias/nullable/direction/validation-mode conditions. A Form cell requiring an adapter does not instruct double decoding with native Form; send the entire body to §5.2's media capability decision. Use an existing explicit media adapter only if it applies and there are no files; otherwise report F_MEDIA_UNSUPPORTED and require explicit body_mode=request. Existing WireValue adapters do not constitute support for special cases containing files.

Current D permits use_missing_sentinel only for PydanticV2BaseModel; preserve the existing Error when specified for PydanticV2Dataclass. MISSING type checking uses upstream's Pyright 1.1.402-or-newer and enableExperimentalFeatures conditions; do not fabricate mypy or pickle support. Do not change D-generated models to Any/cast to make tests pass.

Field wire keys and formal validation/serialization aliases must correspond one-to-one; requiredness that is weakened or strengthened requires an adapter. For both requests and responses, expanded null acceptance from optional nonnullable→D Optional, narrowed nullable acceptance, or indeterminate unions sends that use to an adapter. Do not simulate equivalence with BeforeValidator guards or nullable changes only in the served schema. Do not rewrite model imports to make them native.

Internal `FastAPIProjectionDecision` is a frozen value containing `use_ids:tuple[PersistentTypeUseId,...]` (common declaration order; empty without a schema; enumerate actual uses for all media when choosing one handling mode for the whole body), `site='parameter'|'body'|'primary_response'`, `transport='fastapi_native'|'codec_adapter'|'raw_request'`, `reason`, and `source: SourceLocation | None` (the first actual source location causing the reason, expressed with BINDING's existing document ID, pointer, and role). Parameters separately retain bound_type (D's final type) and surface_type (handler/standard annotation type). Reason precedence is explicit_raw, explicit_adapter, unsupported_wire_shape, envelope_required, opaque_native_semantics, native_shape_mismatch, native_required_mismatch, native_nullable_mismatch, native_alias_mismatch, source_assertion_not_projected, response_presence_or_nullable_mismatch, native_supported. Give each candidate exactly one reason; source is null only when unavailable. All cookie styles, contentless primary responses, required response headers that bare values cannot supply, and primary +json/media parameters always use unsupported_wire_shape. A contentless response calls model/media encode zero times even with transport=codec_adapter. Choose among multiple reasons using this precedence, breaking ties by common source/use declaration order. Missing decision facts use opaque_native_semantics with an existing explicit codec; if that also cannot apply, stop with common MC_/BND_ diagnostics. Do not turn this into a new generic plugin IR or runtime registry.

Save this decision in context/manifest without changing common projection_mode/converter_strategy. Only uses choosing adapters require the runtime codec closure (codecs for §6 APIs such as explicit HTTPResult are a separate actual need). A single ordinary FastAPI route can combine native ordinary parameters and body with an adapter only for a response having Pydantic model nullable/directional differences. Expansion of native support after passing tests also requires an explicit revision of the decision table.

## 3. Operation, router, and argument names and order

The common OperationId identifies origin/use-site; the public operation key is the root document's plain RFC6901 pointer. An external Path Item ref also has a root use-site key and separately retains its declaration pointer. A callback is a separate context record with a parent operation and expression; never automatically mix it into ordinary routes.

Function names take operation_names first, then operationId, then `<lowercase method>_<path>`. Default normalization is NFKC→insert underscores at ASCII CamelCase boundaries (`([A-Z]+)([A-Z][a-z])`, then `([a-z0-9])([A-Z])`)→replace runs outside ASCII alphanumerics/underscore with one underscore→lowercase→strip leading/trailing underscores. Empty results become operation/router/value; leading digits receive op_/router_/p_; Python keywords receive a trailing underscore. Use this normalization only for new server names, not existing D model-name reservations/aliases.

Explicit names must be ASCII Python identifiers, non-keywords, and must not start with `__`. Two operations/groups yielding the same filename under casefold, Windows reserved device stems, or collision with `__init__` produce `F_NAME_CONFLICT`. A group name is also the builders' keyword for the group's service, so group names equal to the builders' other keywords (`authorizer`, `credential_extractors`, `dependencies`, `operation_dependencies`, `prefix`, `fastapi_options`) or to names the application module defines (`build_router`, `create_app`, `install_openapi`, `operation_keys`, `app`, and its route/info constants) also produce `F_NAME_CONFLICT`. Avoid automatic numbering that could silently move an operation to another method name or group between runs; require resolution through operation_names/router_names.

The routers layout uses only the first tag as the group and retains the full tag sequence, including remaining tags, in route metadata. Untagged operations use the untagged group. Router file stems use explicit router_names, otherwise the first raw tag normalized by the rules above; only operations without tags use untagged. An empty-string tag retains its original value as a separate `tag:` group with default stem router. Group order is first occurrence among selected operations in common declaration order; each group preserves that relative operation order. single places the same operation sequence in one router whose group key is `all` and whose default group name is `service`. Do not change operation order through tag sorting or template filesystem enumeration. Preserve the purpose of old F's [first-tag router:7](https://github.com/koxudaxi/fastapi-code-generator/blob/b3b9bd66e0b0c4d8c686fda700258104615a1332/fastapi_code_generator/modular_template/routers.jinja2#L7), with [untagged and other naming:338](https://github.com/koxudaxi/fastapi-code-generator/blob/b3b9bd66e0b0c4d8c686fda700258104615a1332/fastapi_code_generator/cli.py#L338) made explicit under the new rules.

Service methods take `self` and then keyword-only arguments. Argument order is: `request` when Request is injected; `principal` for operations that may authenticate; path parameters in first-occurrence order in the URL; remaining effective parameters in common declaration order; body or form/file properties in declaration order; `media_type` when multiple media exist. Treat location and wire name as identity; do not merge query/header parameters sharing a name. Required arguments have no default; optional arguments default to `UNSET`, distinct from explicit null. An optional parameter's explicit schema default is the value the HTTP decoder validates and supplies on omission; do not put mutable objects in function defaults. Do not extend this completion to body/form properties; their absence follows the ordinary UNSET/native-constructor contract.

Parameter Python names use explicit parameter_names or normalize the wire name with the value rules above. For collisions with `request/principal/body/media_type`, or between different parameters, prefix every element of the colliding set with `<location>_`. Require explicit mapping if a collision remains. A trailing underscore for a keyword does not change the wire alias. Build service method signatures, endpoint calls, and template argument records from the same finalized sequence. Noncolliding item_id/file/note/id remain unchanged; do not always add location prefixes. Only a collision such as path id and query id within one operation produces path_id/query_id, both retaining the original wire-name alias id. form_extra is neither a generated argument nor a reserved name.

Keep a URL-template placeholder unchanged when its wire name is an ASCII Python identifier, a non-keyword, occurs once, and does not collide with finalized endpoint arguments/reserved injection names (for example `/items/{item_id}` with `Annotated[int, Path()]`). Otherwise replace only those slots, in path first-occurrence order, with the lowest available `dcg_p0, dcg_p1,...` not colliding with existing wire names or finalized arguments, and save the original-name mapping as values. Do not pass non-ASCII/hyphenated names directly to Starlette's identifier rules or convert ordinary paths to internal names. Repeated identical placeholders in OAS 3.2 input produce F_ROUTE_INVALID with zero publication. Only 3.0/3.1 inputs give repetitions separate internal slots and return 422 unless their values are equal. This does not relax 3.2's one-occurrence-per-expression rule. See [OAS 3.2.1 Path Templating](https://spec.openapis.org/oas/v3.2.1.html#path-templating) (checked 2026-09-18). Unclosed braces, converter syntax, or routes with the same method and shape differing only in placeholder names are generation errors. Ordinary literal-path/parameter precedence reflects OAS's concrete-path precedence: register two groups, first paths without placeholders, then those with placeholders, each in declaration order. Do not change the source operation sequence or model generation order. This registration order is an intentional new-server rule.

## 4. Connecting service implementations to FastAPI

The generated application's public signatures are fixed below. `<group>` stands for one required keyword per router group in §3's group order, named by the group name and typed with the group's service Protocol. An operation's handler is the method of its group's service named by the operation's finalized Python name. `Dependency` aliases the type `fastapi.params.Depends` that FastAPI itself uses in its public APIRouter signature; do not use the `fastapi.Depends` function as a type.

```python
build_router(*, <group>: <Group>Service[PrincipalT], ...,
             authorizer: Authorizer[SecretT, PrincipalT] | AsyncAuthorizer[SecretT, PrincipalT],
             credential_extractors: CredentialExtractors[SecretT] | None = None,
             dependencies: Sequence[Dependency] = (),
             operation_dependencies: OperationDependencies | None = None,
             prefix: str = "") -> APIRouter
install_openapi(app: FastAPI, *,
                operation_keys: tuple[OperationKey, ...] | None = None) -> None
create_app(*, <group>: <Group>Service[PrincipalT], ...,
           authorizer: Authorizer[SecretT, PrincipalT] | AsyncAuthorizer[SecretT, PrincipalT],
           credential_extractors: CredentialExtractors[SecretT] | None = None,
           dependencies: Sequence[Dependency] = (),
           operation_dependencies: OperationDependencies | None = None,
           prefix: str = "", fastapi_options: FastAPIOptions | None = None) -> FastAPI
```

Each group keyword is required and has no default; a group's Protocol takes `[PrincipalT]` only when it is generic (§2). A method is get_pet, for example, not /paths/~1pets/get. authorizer and credential_extractors exist only when a selected operation has security, and then authorizer is required; packages whose selected operations are all anonymous have neither keyword. There is no handlers mapping, service registry, default service, or dynamic import of user modules. [TYPING §5](DECISIONS-TYPING.md) is authoritative for correlations among service Protocols, PrincipalT, and credential SecretT, distinct from P for §6's bare primary. At startup, the builder resolves each operation's handler on its group's service and raises HandlerConfigurationError when the attribute is missing or not callable, when a sync operation's method is a coroutine function or an async operation's is not, or when its signature cannot bind exactly the generated keywords. This dynamic check alone does not prove static argument/return types. Custom apps can use `app.include_router(build_router(...))`, followed by `install_openapi(app)`. OperationKey is a Literal union of the generated package's final selected root operation keys (Never for an empty selection). Define OperationKey and SchemeKey in existing _generated/contract.py and re-export the identical types from application.py and the package root; services.py alone defines the service Protocols. SchemeKey is a Literal union of original scheme names, also exported from auth_types.py. OperationDependencies is a non-generic functional TypedDict with NotRequired pointer keys and Sequence[Dependency] values; define it and the total=False FastAPIOptions TypedDict below in application.py and export them from the root. Do not use invalid identifiers as generic TypedDict field names. operation_keys=None means all those keys; an explicit tuple is the subset actually included; an empty tuple intentionally selects none. Unknown/duplicate keys raise OpenAPIConfigurationError. When including only group build functions, explicitly supply that subset; do not infer selection by inspecting app.routes. create_app builds/includes/installs all selected operations, then evaluates public app.openapi() once to check document integration before returning. Do not return FastAPI objects to the common kernel.

prefix is empty or a literal prefix starting with / and not ending with /. Reject query/fragment/braces. The sole definition of FastAPIOptions' 32 allowed keys, exact types, and omitted defaults is [TYPING §5.1's closed table](DECISIONS-TYPING.md). Explicit values override defaults derived from source info; distinguish None from omission. If default_response_class or generate_unique_id_function is absent, omit the constructor argument itself to preserve ordinary FastAPI defaults. Validate JSON metadata against JSONValue and copy it to ordinary dict/list values. Unknown keys, invalid types, and non-JSON metadata raise OpenAPIConfigurationError before constructing FastAPI; do not forward arbitrary upstream extras unchecked. Load services/authorizers/dependency callables as application code at startup, never during generation. Runtime inconsistencies in services/principal/etc. fail fast with the errors module's HandlerConfigurationError/AuthConfigurationError/OpenAPIConfigurationError, without silent per-request fallback.

exception_handlers, lifespan, on_startup/on_shutdown, model classes inside responses, arbitrary extras, etc. are outside this convenience entry point. Users construct ordinary FastAPI(...) and connect build_router/install_openapi. The FastAPI features themselves remain supported. Include the following path in the generated README; do not require users to replace their standard app to fit the convenience entry point. This is an illustrative fragment; lifespan/exception_handlers/Pets are values the user has defined with exact types.

```python
app = FastAPI(lifespan=lifespan, exception_handlers=exception_handlers)
app.include_router(build_router(pets=Pets()))
install_openapi(app)
app.openapi()  # Check public document integration after all includes/installs.
```

Include this authenticated implementation example in the generated README, assuming the only selected operation is get_pet in the pets group and the user has defined Principal/Pet/authorize. Pets subclasses the generated Protocol parameterized with Principal, and get_pet accepts principal:Principal in addition to the Protocol's keyword sequence; authorize returns Principal from AuthContext[Never]. Only builtin credentials are used, so SecretT=Never; replace it with the union of custom types when multiple custom types are used. Subclassing is recommended, not required: any object with matching methods is checked structurally at the builder call.

```python
class Pets(PetsService[Principal]):
    def get_pet(self, *, principal: Principal, pet_id: int) -> Pet: ...


def authorize(context: AuthContext[Never]) -> Principal: ...


app = create_app(pets=Pets(), authorizer=authorize)
```

The generator writes neither this module nor any other application module; the README example is documentation, and users own the module that builds the application.

handler_mode=sync calls the synchronous service method exactly once from an ordinary `def` endpoint; FastAPI runs that endpoint in its thread pool. async awaits the coroutine method exactly once from `async def`. An async function in a sync slot, a sync callable returning an awaitable, and similar cases are explicit configuration errors; add no hidden event loop or automatic execution of arbitrary awaitables. The builder uses inspect.signature to check acceptance of generated keywords and absence of extra required arguments, but never evals annotation strings to construct models.

Routes are ordinary APIRoute instances. Add no generated MultipartRoute, ASGI child task, cancellation gate, reserved request.state lease, forms.get_form, or dedicated multipart reader. Custom templates using public route_class need no generator-specific base class. Delegate sync/async execution, response/stream completion, and dependency cleanup to FastAPI/Starlette; add no extra-task ContextVar boundary. See [official sync/async](https://fastapi.tiangolo.com/async/#path-operation-functions) and [request-scoped dependencies](https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/#early-exit-and-scope) (checked 2026-09-18).

Native arguments use ordinary Annotated declarations; adapter arguments use explicit Depends. Fix one body acquisition method per operation; do not place native Body/Form/File beside an adapter reading the same body. Other parameters/primary responses may choose independently of the body. For a native bare primary, explicitly set response_model to actual T, response_model_by_alias=True, and response_model_exclude_unset=True; omit response_class and defer to ordinary FastAPI defaults. Adapter primary and no-primary cases use response_model=None and response_class=Response and return Response. Do not create standard JSONResponse's automatic schema={} or expand anyOf with the source schema to unconditional acceptance. See [pinned response generation](https://github.com/fastapi/fastapi/blob/0.141.1/fastapi/openapi/utils.py#L403). HTTPResult/ModelValue/ModelInput/explicit Response handling is fixed in §6. Always specify response_model so FastAPI does not infer HTTPResult or similar as a response model from the endpoint return annotation. See the [official response model](https://fastapi.tiangolo.com/tutorial/response-model/) and [direct Response contract](https://fastapi.tiangolo.com/advanced/response-directly/) (checked 2026-09-18).

dependencies are preprocessing for all operations, passed directly to FastAPI's public dependency API; operation_dependencies adds dependencies for the corresponding operation. Order is global→operation. Do not inject results into unknown handler keywords; users can use Request.state or explicit Depends arguments in custom templates. The generator neither invokes user dependencies nor owns a custom DI container. Execution/completion order and overrides of user dependencies follow FastAPI's contract; do not independently reorder side effects relative to builtin request preparation.

The target generates no business stubs, so no generated code answers 501 for an unimplemented operation: every service method must exist before an application can be built. NotImplementedError and other exceptions from service methods remain 500 errors preserving the original exception. Never substitute a stub for unsupported wire/codec/binding functionality. Require no per-operation Result classes.

Use the finalized common codec contract. Do not fabricate values for required readOnly fields or bypass required constraints with model_construct. A nullable native None is ModelValue.value=None; None does not mean construction failed.

Declare custom bases/templates preserving builtin construction/serialization contracts through `builtin_codec_compatibility` and map different exports through `export_bindings`. Target flat TOML uses `[[builtin_codec_compatibility]]` / `[[export_bindings]]`; MODEL-CODECS §12 alone defines the closed schema of each value. The generator performs module/import/field/artifact comparison and fixes digests; users must not repeatedly update handwritten digests. Missing/incompatible declarations stop with that section's common MC_/BND_ diagnostics, without a server-only fallback.

### 5.1 Parameters

Native parameters use Annotated[SurfaceType, Path/Query/Header(...)] with the public wire name as alias. Explicitly set Header convert_underscores=False; never silently change underscores to hyphens. Delegate integer/number/boolean/date/etc. coercion and validation exactly once to FastAPI/Pydantic, without additional common decode_parameters. Project supported source-schema constraints into public FieldInfo kwargs: minimum/maximum→ge/le, normalized exclusive bounds→gt/lt, multipleOf→multiple_of, string/one-level-list minimum/maximum length→min_length/max_length, and title/description/deprecated/examples→same-named kwargs. Use §2.1's same int32/int64 range and query-list-item projection table, shared with Form. Number surfaces use allow_inf_nan=False. Represent const/enum through type-level Literal/existing enums; do not project pattern to native. Unspecified kwargs use FastAPI defaults; do not change model strict settings. Styles/compound values/explicit codecs that standard handling cannot express use Depends with common decode_parameters. See [official parameter validation](https://fastapi.tiangolo.com/tutorial/query-params-str-validations/) and [Header](https://fastapi.tiangolo.com/tutorial/header-params/) (checked 2026-09-18).

Native surfaces derived from builtin primitives/roots are string→str, integer→int, number→float, boolean→bool, date/date-time/uuid→corresponding Python types, enum/const→corresponding existing enums or Literal, and list→list of the corresponding element type. Even if Api scope generates an independent RootModel, the server parameter can use its purely structural inner-value surface without deleting that model. Do not flatten actual body/response T using this rule. For type overrides, opaque enums/constructors, or custom model codecs, do not arbitrarily reduce to str/int; use the existing codec and final T/DecodedValue[T]. Distinguish bound_type and surface_type in context; the manifest stores only signature_sha256 incorporating the type and projection records, never raw type values.

Required parameters have no default. For an optional parameter without an explicit default, do not make its SurfaceType annotation nullable; use public Query/Header(default_factory=_absent_parameter). _absent_parameter is one shared, small private target function taking no arguments and returning None, without adding default:null to the schema. Only when the framework returns None for a missing value, check presence through public Request.query_params/headers/path_params before passing it to the handler. Omitted with no explicit schema default becomes UNSET; an explicit default becomes the same-typed default checked against source/type during generation; actual input values pass unchanged. This is ordinary default specification through public FieldInfo, not a new validator/Body marker. Scalar explicit schema defaults use function =literal; list defaults use public Query/Form(default_factory=a generated function returning a fresh list, json_schema_extra={"default":original JSON value}), avoiding shared mutable lists between calls. Defaults requiring conversion, such as date/UUID, use §2.1's adapter. Do not conflate nullable and omission or hide missing/default in arbitrary objects. Presence checking is not a second decode of raw values. Do not replace standard query/header duplicate-value or percent-representation rules with custom strict rules at native boundaries; document differences in the generated README's native contract.

The effective sequence uses only common results from [BINDING §5.2](DECISIONS-BINDING.md) and MODEL-CODECS §10; do not reimplement the same predicate in the server. Decisions have already proceeded in this order: root's adopted OAS version × actual RequestBody ownership→encoding media→headers media→wire name. For 3.0/3.1 non-RequestBody locations (including Parameter.content/Header.content as well as response/components.responses), ignore the whole encoding first. Even at valid locations, every version ignores whole encoding for media other than multipart or application/x-www-form-urlencoded. When both conditions apply, retain only the first reason; do not descend into encoding values/headers or perform extra Header/schema resolution or type acquisition. For remaining valid encoding, common rules exclude all headers for non-multipart or the Content-Type wire name for multipart. Parameter headers Accept/Content-Type/Authorization and response header Content-Type also follow those common results. When whole encoding is ignored, do not restore children, including contentType, to effective MediaView; retain contentType of valid encoding. This does not ignore securityScheme itself.

Whole encoding produces one field-level I_OAS_ENCODING_IGNORED; per-header exclusions use existing I_OAS_HEADER_IGNORED. Do not add child-header diagnostics to the former. Pass common Diagnostics unchanged to report/CLI/ENTRY's portable manifest, with severity=info, stage=binding, target_id=None and source/use location/order. Preserve common diagnostics for components with no operation membership; do not invent operations. Ignored regions are excluded from type acquisition, signatures, required/style validation, header codecs, typed accessors, credential collisions, and require_type_bindings. Original source remains in the common lease, but do not delete/roll back independently generated models. Ordinary D's Api scope and capture use identical rules.

Only adapter parameters pass RawParameters preserving original location/name/occurrence order/duplicates once to decode_parameters(ParameterPlan, RawParameters, context). Query uses ASGI query_string; header/cookie uses the original ASGI headers byte sequence, without prior dict conversion. Path adapters obtain raw fragments from public ASGI raw_path and matched literal/prefix/slot mappings; do not reconstruct percent representation by guessing from decoded path_params. A 400 for missing raw_path applies only to this path adapter, not ordinary native Path. Limitations such as encoded slashes yielding 404 before standard Starlette dispatch remain separate from the client's encoding capability. See [ASGI scope](https://asgi.readthedocs.io/en/latest/specs/www.html#http-connection-scope) (checked 2026-09-18).

cookie=form always uses the existing adapter applying common percent rules to the entire string. Standard Request.cookies/Cookie does not percent-decode; do not pass a valid value sent by the client as a%20b / %25 / UTF-8 percent encoding to the handler as an unchanged, different string. Add no new decoder, runtime fallback based on percent presence, or native exception for enums/etc. Cookies use the same finalized T/DecodedValue[T] as other codec adapters. ModelValue.value passes as T, so T=RootModel[str] gives the handler RootModel[str]; primitive T gives the primitive. Do not unwrap to native-only SurfaceType or create a new projector/helper. Preserve D RootModel. Generate neither native None default_factory nor NativeDeclaration for cookie arguments. Users' own Cookie DI retains ordinary FastAPI behavior; conflicts with an adapter-owned field of the same identity follow §8.

Adapters use MODEL-CODECS' support table and handwritten wire vectors for path label/matrix, query space/pipeDelimited/deepObject, header list/object, cookie form/3.2, querystring, etc. Nested deepObject and combinations defined as n/a by the specification are generation errors without an explicit custom codec. Native/adapter selection is fixed at generation time; codec failure never falls back to FastAPI coercion. Unknown ordinary query/header fields not constrained by the source specification do not become handler arguments but remain accessible through Request. After OAS exclusions, an ordinary parameter and security credential owning the same location/name cause a generation error; do not automatically copy secret values into business arguments.

### 5.2 Bodies, forms/files, and resources

Each body uses exactly one generation-time choice: native, adapter, or explicitly selected body_mode=request. Do not catch runtime validation failures and route to another method. Native JSON uses Body; native forms use Form/File/UploadFile; pass FastAPI-created values to the handler. Only adapters use the common codecs below; never re-decode native values with a common codec. Native body parsing can occur before security dependencies, so do not guarantee zero body reads on authentication rejection. Preserve public FastAPI's authentication/dependency/body-validation order; generate no ASGI framework dedicated to early authentication. See [pinned routing body acquisition:406](https://github.com/fastapi/fastapi/blob/0.141.1/fastapi/routing.py#L406) and [solve_dependencies:481](https://github.com/fastapi/fastapi/blob/0.141.1/fastapi/routing.py#L481).

## 6. Responses, statuses, and headers

Choose the bare-return primary response in this order: explicit primary_responses→exact 200→lowest exact 2xx→lowest exact numeric status. Select content as application/json→first +json→first remaining content in declaration order; no content means None. If only range/default exist, do not invent a primary; handler return types use HTTPResult/Response and users supply a concrete status. Do not add an invented 200 to a 201-only route. Without a primary, register status 200 if default is declared, otherwise the lowest range's lower bound (for example 4XX→400). This represents the declared allowed set and does not change bare P=Never or explicit HTTPResult's required status. Served docs list the original range/default and an identical representative exact response; do not delete FastAPI's registration value or infer provenance of user responses.

Fix each response/media branch's server payload type with the table below. T is the branch's entire FinalPythonType; even a union T must not be narrowed to just the primary type. Direction is response; use projection_mode finalized by MODEL-CODECS.

|Branch|Server payload type|
|---|---|
|Schema present, projection_mode=native|`T \| ModelValue[T]`: bare T or a snapshot retaining presence|
|Schema present, projection_mode=envelope|Outbound is `T \| DecodedValue[T]` (complete T, or `ModelValue[T] \| ModelInput[T]`). Distinguish already having valid T from directional differences preventing complete T construction. Never fabricate nonexistent required values|
|Source schema itself absent, or binary|§5.2's fixed media surface (WireValue/str/bytes, etc.). Add no imaginary schema envelope|
|No content, HEAD, or a status prohibiting an HTTP body|No payload candidates. HTTPResult.body is UNSET|

P, the allowed bare-return type, is the primary branch's payload type above; it is None for a bodyless primary, and Never when there is no primary or the primary response requires a header, which a bare value cannot supply. Traverse all declared exact/range/default responses and each media in original order; A is the union of the table's payload types, deduplicated by first occurrence. Contentless/body-prohibited branches do not add None to A; no candidates means A=Never. Preserve None in schema-explicit nullable T. The handler return annotation is **`P | HTTPResult[A] | Response`**. This allows bare 200 Pet alongside an HTTPResult containing 404 ErrorDetail, for example. A is the set of candidates for all branches, not a discriminated union statically proving status/media/payload correlation. Explicit response_model validates bare native primary values; the common schema/codec for actual status/media validates HTTPResult and similar values.

`responses.HTTPResult[BodyT_co]` is a frozen `Generic[BodyT_co]` record with `BodyT_co = TypeVar('BodyT_co', covariant=True)`, required `status_code:int`, `body:BodyT_co | Unset=UNSET`, `media_type:str|None=None`, and `headers:tuple[tuple[str,str],...]=()`. Add no body-mutating method/setter. Its generic parameter is the **actual payload type**, not the schema type, so an envelope is expressed as `HTTPResult[ModelValue[Pet]]`, etc., without changing ModelValue/ModelInput variance. `HTTPResult[ErrorDetail]` is assignable to `HTTPResult[A]` when A includes ErrorDetail. Distinguish None from UNSET; omitted media uses the chosen response's default above, or None for a bodyless response. Use one wrapper shared by all operations, without per-operation Result classes. See [Python typing variance rules](https://typing.python.org/en/latest/spec/generics.html#variance) (checked 2026-09-17).

For an envelope-required primary, P is T | DecodedValue[T]; retain all of T if it is a union. Only when a bodyless primary makes P=None does bare None map to omitted-body UNSET. ## 10. Selective regeneration, ownership, and publication

Old F varies selection using [include strings in existing main:350](https://github.com/koxudaxi/fastapi-code-generator/blob/b3b9bd66e0b0c4d8c686fda700258104615a1332/fastapi_code_generator/cli.py#L350) and [creates missing routers even when unselected:393](https://github.com/koxudaxi/fastapi-code-generator/blob/b3b9bd66e0b0c4d8c686fda700258104615a1332/fastapi_code_generator/cli.py#L393). The new server makes no such inference; distinguish initial selection=`selection: OperationSelection` from limited updates of existing groups=`update_groups`. The former creates a new smaller server; the latter protects existing unselected routers.

1. Finalize all models and the whole selected server plan from the same accepted attempt. Do not narrow model scope for partial updates.
2. Initial generation uses ENTRY's unowned-path rules. Do not downgrade corrupt/unknown-version/inconsistent manifests, old F trees, or hand-edited trees to an initial run and overwrite them. The target has no create-only paths: an existing file at any planned path that no valid previous manifest owns produces E_OUTPUT_CONFLICT.
3. update_groups requires the same target/package/layout/selection as before. Unknown groups, empty tuples, or absent manifests are errors. Add/remove groups or change selection/layout through full regeneration.
4. Unselected groups' owned files, their operations' service-method signature fingerprints, operation plan/codec/docs fingerprints, and shared runtime revision must match between previous/current runs or produce `F_PARTIAL_UPDATE_INCONSISTENT`. Require identical artifact bytes for model modules referenced by unselected operations. Changes for selected groups inside a shared single model module also require full regeneration; do not infer semantic equivalence. No regeneration reads or writes user modules.
5. For full and partial runs alike, ENTRY rewrites missing/edited previously owned regular files with their planned bytes. Unselected groups' planned bytes equal the previous generation (item 4), so restoring them changes no generated content; never downgrade missing to initial CREATE. ENTRY still defines diagnostic precedence for symlinks/non-regular files/manifest inconsistencies. Do not describe this as automatic merging of handwritten edits in old F selected routers.
6. Render shared application/runtime/docs from the whole plan and verify that unselected dependencies do not change. Byte-identical files have zero writes and unchanged mtime. DELETE of obsolete owned files is limited to full regeneration and requires previous ownership; an edit does not keep an obsolete file. Never delete files the previous manifest does not own.
7. Pass the target's WRITE/DELETE/UNCHANGED plan to ENTRY. Models, metadata, and remote locks belong to the same new batch; create no separate FastAPI writer/journal.

Operation additions, removals, renames, and signature changes change services.py and the routers like any other owned artifacts; the target keeps no per-operation user files to preserve, adopt, or report as orphans, and no handler paths to reassign. Users' implementations surface each difference through type checking against the regenerated Protocols, TypeError when instantiating a subclass that lacks a new abstract method, and the builder's startup checks. Keep a drifting name stable through operation_names when implementations should not change.

### 11.2 Removed responsibilities and remaining costs

The new server shares one D parse/reference acquisition/model finalization, common operation facts, final symbol mapping, model/wire codecs, and artifact/publication handling. Do not bring old F's super+additional schema parse, root deletion, live DataModelField/Imports visitors, or whole-output constr replacement into the new server. Old F remains independently maintained during migration; do not count its old code as immediately removed maintenance.

Permanent server responsibilities are static native/adapter boundary decisions, standard FieldInfo rendering, necessary FastAPI codec integration, server authentication boundaries, generated-owned OpenAPI fragment composition, templates/context/hooks, service Protocols/selective regeneration, and runtime/package tests. Ordinary DI, sync/async execution, form parsing/UploadFile lifetime, response filtering, and standard errors delegate to FastAPI/Starlette, without a custom ASGI/task/parser foundation. Do not count client transport/retry/paging/auth sending as implemented by this work. Investment in common codecs/neutral binding is reused where the client's five backends and server's two overlap, but bundled wire validators/runtime create new dependency-maintenance and regeneration-release costs.

Every choice here is a fixed design, not evidence of a completed product. If implementation finds counterexamples, preserve original compatibility constraints and explicitly revise the corresponding contract and independent oracle. Implementers may not resolve them by changing existing model bytes, silently dropping unmet capabilities, falling back to old F, or creating another public API.
