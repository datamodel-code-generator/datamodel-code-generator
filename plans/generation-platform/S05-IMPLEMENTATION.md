# S05 implementation record

Status: in progress. S05 (artifact ownership and publication) starts from main at `0352c9f9`, after the S04 stack (#4143, #4145, #4147, #4148) merged. Nothing in this stack has been merged.

## Baseline and review boundaries

The authoritative contracts are ENTRY §§1–6 (shared entry points, configuration, model generation/reuse, ownership manifests, staging, publication, locks, layout and dependencies), G08/G11 in ACCEPTANCE and B10 in BINDING, read from the plan checkout used since S03. PR-STACKS fixes the gate: single-target ownership, no model rerender, no cross-target registry and no combined generation.

S05 adds internal machinery only. The public `api_types` module, the `--generate-server` / `--generate-client` selectors, `--target-config`, `--target-output`, `--diagnostics-json` and the `generate_*` / `render_*` entry points stay private until the targets expose them (S07 for the server, S14 for the client), because PR-STACKS forbids merging an incomplete public feature. When they become public they are registered through the existing experimental-feature registry (`experimental.py`, `docs/experimental.md`, `--list-experimental`).

Decisions recorded before S05 that bind later stacks:

- Template rendering for the targets (S06/S07, S09) follows the model side: builtin `.jinja2` sources ship in the package together with renderers compiled by `scripts/compile_builtin_templates.py`, custom templates use the same overlay and `_build_environment`, and the sandboxed Jinja environment with `SpecText`/`EncodedFragment` encoders and runtime AST checks in DECISIONS-FASTAPI §9.3 and DECISIONS-CLIENT §10 is not implemented. Builtin templates place values the generator already escaped, and adversarial G12-style fixtures check builtin output at test time. The plan's affected sections are rewritten, or recorded as deviations, when S06 starts.
- Every generated file is target-owned and regenerated idempotently. The maintainer decided on 2026-09-26 that a target writes no create-only files: handwritten code lives in the user's own modules and implements generated interfaces, and a rerun on the same inputs reproduces every generated byte. The ENTRY create-only ownership (the manifest's `ownership` field, CREATE_ONLY publication, preserved create-only bytes) and the FastAPI scaffold are out of the plan, which [PR #4098](https://github.com/datamodel-code-generator/datamodel-code-generator/pull/4098) updates.
- Generation-platform features are experimental and follow the existing experimental-feature mechanism when they become user-visible. The explicit `api` scope already shipped in 0.83.0, so it stays an existing feature and is not registered.
- Main at `0352c9f9` failed CI because the security fix `ebfc11d0` rejects string constants outside `Literal[...]` in `x-python-type`, which made the frozen-set fixture `tuple_forward` invalid and the fallback in `_has_native_bound_hash` unreachable. [PR #4149](https://github.com/datamodel-code-generator/datamodel-code-generator/pull/4149) drops the case and folds the fallback into the existing negative checks without changing any result.

## Planned stack

1. `generation-platform-target-config`: shared records and diagnostics, the shared target configuration and its flat TOML loader, operation selection, the coordinator's render path (facade preparation, backend and single-root validation, one model generation in private staging with capture, remote-lock candidates, verify-mode comparison), and manifest identity (canonical JSON, target manifest and model inventory v1, fingerprints, persistent use identities, state reading and ownership planning).
2. `generation-platform-target-publication`: the target publication journal (WRITE and DELETE in the fixed commit order, reverse rollback on any `BaseException`, `PublicationRollbackError`), OS advisory locks, remote-lock publication (stage, mark, discard, `E_STATE_CHANGED`), path collision checks and the publishing generate path.
3. `generation-platform-target-layout`: one formatter per target, headers, encoding and timestamps, embedded and standalone package layouts, and the internal entry integration that S06 and S09 call.

## S05-1: target configuration, render path and manifest identity

Modules, all in the new `target` architecture layer:

- `_api_types.py`: `Diagnostic`, `APIGenerationError`, `OperationSelection`, `ArtifactRecord`, `GeneratedArtifact`, `GenerationReport` and `GeneratedProject`, with the literal kinds, stages and actions of ENTRY §2. `OperationRef` stays in `_codec_declarations`, where S04 defined it.
- `_target_config.py`: the frozen `TargetConfig` every target extends, validated in field order into `E_CONFIG_VALUE`, `E_CONFIG_CONFLICT` and `E_SELECTION` diagnostics, and `load_target_config`, the flat TOML loader (`schema_version = 1` only, `E_CONFIG_UNKNOWN` for keys without a field or converter, paths and explicit documents resolved against the file's directory, `--target-output` precedence through `output=`).
- `_api_generation.py`: `render_target`, the coordinator's render path, and the `TargetGenerator` protocol with `TargetRequest`, `TargetRender` and `TargetBinding`.
- `_api_manifest.py`: canonical JSON, target identity, the accepted document table, persistent type-use identities, portable configuration values, model records and fingerprints, state reading and ownership planning.

`render_target` validates in the ENTRY §2.1 order (required `model_config.output`, facade preparation once through `_prepare_generate_facade_config`, the target's backend set, then one root: a list, a directory or a non-OpenAPI input type is `E_INPUT_ROOT`), evaluates `_uses_legacy_process_state` once, and resolves the remote lock through the existing helpers (`_prepare_atomic_generation_remote_lock` for an owned update, `_resolve_generation_remote_lock` otherwise; an update collector resolved by another caller is `E_CONFIG_CONFLICT`). It then generates the models once through `_run_generation` into private staging next to each destination, with the logical output, metadata and resolved lock on the staged copy and an `OpenAPIGenerationSession` as capture, and takes the product with the staged artifacts in ordinary emit order (sorted result keys). An owned update lock is staged into the same private directory, read as an unpublished candidate and discarded.

Selection resolves plain pointers and `OperationRef` values against root use sites only (`E_OPERATION_REF` for another document, a missing operation or a webhook; `E_SELECTION` for unknown tags and repeated operations), takes the union of inclusions, subtracts exclusions, keeps document order and reports every excluded operation as `S_OPERATION_EXCLUDED` with its grounds and the user's reason. The target renders from the selection, the accepted batch, the borrowed sources, the model artifacts, the document table and the previous state; verify mode then compares every candidate model with the file at its logical path (`E_MODEL_MISMATCH`), and ownership planning applies ENTRY §4 (`E_OUTPUT_MODIFIED` for changed or missing owned files, `E_OUTPUT_CONFLICT` for unmanaged files at owned paths, deletions only for unchanged previously owned files; the target owns every file it plans, so the manifest records a hash and size for each). The project lists models, target files, metadata, the remote lock, the inventory and the manifest in publication order, each marked `unchanged` when the current bytes already match.

The manifest follows ENTRY §4.1: persistent URIs relative to the target root, the root document at `/inputs/root` and the other accepted documents deduplicated by URI and digest, provenance for every model setting that differs from its default (secret HTTP settings and callables opaque), public options with paths as URIs and `SchemaRef`/`OperationRef` as `SourceRef`, opaque options for values that have no JSON form, formatter extensions, bindings with `PersistentTypeUseId`, and the target's data under its kind. The same relative layout in another checkout produces identical manifest bytes.

`scripts/check_architecture_boundaries.py` classifies the four modules as the `target` layer, forbids parser imports from it (`target-parser-import`) and imports of it from every other layer (`target-reverse-import`).

Tests: `tests/api_generation/test_target_generation.py` renders the scenarios in `tests/data/generation_platform/targets/cases.json` with the fixture targets in `tests/data/python/target_generation.py` (a server target that accepts the two Pydantic v2 backends and a client target that accepts all five) and compares the reports in `tests/data/expected/main/generation_platform/targets/`. Only two failures are injected: a remote-lock staging error and a path that cannot be relative to the target root. The four modules are covered completely by these tests.

### Deviations and notes for later stacks

- Document digests are SHA-256 digests of the canonical JSON projection of the parsed documents the accepted attempt borrowed, for file, URL and Mapping inputs alike, instead of digests of the bytes read: the loader keeps no source bytes, and the parsed documents are what the attempt used.
- URL documents are recorded by the same display URL as remote locks (scheme, host and port only, because deployments put tokens in paths), so documents from one origin differ by digest.
- `runtime_revision` is the SHA-256 digest of the private runtime sources (`_runtime/**/*.py`, by path and content). ENTRY names the field without defining it.
- Reading a previous manifest checks what the coordinator consumes: top-level keys, the key sets of the record-valued keys, list types, the target record and identity, inventory agreement and the file records, whose paths must be normalized relative POSIX paths that stay inside the target root on POSIX and Windows (no `..`, drive or root). Targets validate their own `target_data`.
- The TOML loader canonicalizes explicit `OperationRef`/`SchemaRef` documents against the file's directory. S04's `declared_document` still compares loader URIs, and the S04 wire plan numbers external documents by loader URI instead of the manifest order. S06 resolves codec declarations through `DocumentTable.pointer`, which accepts both spellings, and gives the wire planner the table's pointers, so `CodecSourceRef` documents equal manifest pointers.
- Path collision checks, OS advisory locks, the publication journal and remote-lock publication belong to S05-2; formatting, headers, encodings and package layouts to S05-3.
