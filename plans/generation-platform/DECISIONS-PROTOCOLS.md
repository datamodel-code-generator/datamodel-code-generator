# Final design for API-dependent protocols

2026-09-17. This document establishes the **implementation contract** for C19–23/C25/C33. It does not report that the product has been implemented. It makes the general requirements in `CLIENT-REQUIREMENTS.md` / `COVERAGE.md` / `ARCHITECTURE.md` concrete through the public APIs, metadata, state transitions, limits, and independent tests below. Numeric values are dcg design decisions.

Do not infer pagination, resumption, signatures, or idempotency that the API does not provide. Every capability listed here remains subject to implementation and conformance testing; diagnosing missing metadata alone does not complete that capability. Hosting, enterprise SSO, billing, and resident queue workers are outside the generated client's implementation scope. Offline queues execute through an explicit user call to `drain()`.

[DECISIONS-TYPING](DECISIONS-TYPING.md) is authoritative for types, and the signatures below have the same shapes. Use Python 3.10-style Generic/Protocol and typing_extensions in the new package. Bind T/P/Send/Recv/InputT to declared schemas/uses; do not expose bare generics, Any returns, or unbound TypeVars. Refining types must not change dcg model fields/annotations or the existing contracts for send counts, persistence, deadlines, and ownership.

## 1. Shared vocabulary and metadata

Do not change the return values or names of ordinary generated endpoint methods for the convenience of helpers. Place protocol helpers at `client.protocols.<api_name>`. `api_name` is a required key in the `helpers` map below, consisting of Python identifiers separated by `.`. Keywords, empty components, duplicates, and path collisions with ordinary generated artifacts are generation errors. Generate the same hierarchy for sync and async clients. `Page[T,P]` / `StreamEvent[T]` and similar types are public envelopes owned by the client; they do not change the bases, fields, or settings of existing dcg models.

Sync I/O methods are ordinary functions; async methods are coroutines with the same names. The initial AsyncClient targets native asyncio; hidden executor delegation to synchronous HTTP/WS/providers does not count as async support. Only explicitly blocking disk adapters use the owned workers described below. Factories that do not start I/O, such as `iterate()`, are ordinary functions in both variants; the async variant returns an async iterator. `close()` / `aclose()` are idempotent. Handles that hold responses implement sync/async context managers. GC, iterator `break`, and loss of references are not part of the release contract. The SDK owns the response/session until it successfully returns a handle; afterward, the handle's user owns it. User-injected HTTP clients and WS connectors are borrowed and are not closed when a helper finishes.

The configuration reference is `ClientGenerationConfig.protocols: Path|ProtocolConfiguration|None` (default None; an explicit file path in TOML). Always expose `SessionOptions` / `ProtocolClientOptions` in `pkg.options`. Put all other public envelopes, options, and injection Protocol types in stdlib + typing_extensions definitions in the always-generated `pkg.protocols`; only API-specific helper modules and optional implementations belong to the dependency closure of enabled capabilities. Exception classes always reside in `pkg.errors` as specified in section 1.3, never in pkg.protocols. Importing shared types must not initialize optional libraries, threads, or networking. Only C23 concrete key wrappers are emitted in pkg.webhooks.keys according to the selected profile; that module imports at runtime the cryptography types required by public-key profiles. T/P and similar symbols in this document denote public types statically declared by codec bindings; protocols must not independently remove or add envelopes such as ModelValue/ModelInput required by the shared codec. Helper operation arguments are also keyword-only. In addition to the ordinary endpoint reserved names `body/options/media_type/response_media_type`, helpers reserve `session_options`, `pagination_options`, `poll_options`, `stream_options`, `ws_options`, `cache_options`, `upload_options`, `batch_options`, `queue_options`, `source`, `items`, and `state`. A collision with a wire parameter requires explicit `parameter_names` in client configuration; otherwise emit `E_NAME_COLLISION` without silent renaming. An enabled helper referencing an excluded operation produces `E_SELECTOR_DEPENDENCY`; do not silently reinclude it. Helper/client close ordering follows the shared runtime: closing the originating client closes active handles. It does not close the borrowed transport itself.

The configuration source is the new client's auxiliary `client-protocols.yaml` file, encoded as UTF-8, schema version **1**. Do not rewrite the OpenAPI input. Its form is `schema_version: 1` and `helpers: {<api_name>: <HelperDefinition>}`. Each definition has `kind` and the operation/create/channel/event references and kind-specific settings defined in each section. Unknown fields, unknown kinds, and unknown schema versions are errors. Do not silently remove an enabled helper. A helper with `enabled: false` is not generated, and its runtime/dependencies are not included in the output.

Include scope/audience/server origin and auth scheme identity in the fingerprint as well. Token refresh alone does not change the partition. |
| URL selector | Resolve a relative URL against the request URL of the response that returned it. Reject userinfo, fragments, and values exceeding 8192 UTF-8 bytes. | `ResumeState` | An opaque envelope containing version, helper fingerprint (schema, operation, protocol settings, codec version), security fingerprint, protocol state, and any necessary unconsumed response bytes. The standard format is a JSON envelope + base64 bytes; hashes detect corruption only and are not called signatures. An operation that owns querystring cannot also have ordinary query parameters, and later pagination/polling/resumption/auth stages must not add query pairs. Add/update values through a querystring RequestTarget and explicit Binding to the declared whole value or schema property. An ordinary `in:query` target is diagnosed at generation time; an undeclared runtime query patch fails before sending. [DECISIONS-MODEL-CODECS](DECISIONS-MODEL-CODECS.md) section 10 is authoritative for URLencoded/JSON/+json/text serialization, single ownership of percent-encoding, treating empty raw query bytes as unspecified, and treating an explicit value that encodes to empty bytes as an encode error. Even when writing a cursor to a URLencoded property, encode the whole value once through the codec; do not concatenate strings onto an existing raw query.

The metadata example has the following fixed form. Other kinds use the same shared types; each section's table defines that kind's required fields and defaults.


### 1.2 Borrowed adapter signatures, records, and ownership

Expose the following Protocols. Sync methods in the table are ordinary functions; `AsyncX` uses coroutines with the same names, except that source `open_range()` and BlobStore.open() are ordinary functions returning sync/async context managers. RangeReader/AsyncRangeReader expose only the read entry point below; do not require an undeclared iter_bytes. Release uses sync `close()` and async `aclose()`. Generated clients do not call close on injected connectors/stores/sources/factories themselves, but always close the connections/readers/decoders obtained from open/new. Only client-owned fallbacks close with the client. Store atomicity, leases, and CAS belong to the adapter; the SDK must not replace them with read-modify-write. Store I/O exceptions retain their causes through the corresponding store exceptions in section 1.3 and do not resend successful HTTP requests. External async adapters must be native async; builtin disk-worker exceptions are limited to sections 9/11.

| --- | --- |
| `WebSocketConnector` / `AsyncWebSocketConnector` | `open(request:WebSocketOpenRequest, *, context:AttemptIOContext, options:ResolvedWSOptions, transport:ResolvedWebSocketTransportOptions)->WebSocketConnection` / AsyncWebSocketConnection. **One open performs at most one handshake**, with no internal redirects/retries/auth/reconnects. Status rejection uses HandshakeResponse in section 6; other failures use shared TransportError with phase/delivery. Do not let unclassified native raw exceptions escape the SDK |

BlobStore.put's reader is **borrowed and owned by its caller**. Read from its current position to EOF in chunks of at most 64KiB, without rewind/seek/close/aclose. The store computes size/SHA256 in read order and returns BlobRef only after capacity checks and atomic publication. On failure/cancellation, roll back/delete unpublished writes, return no partial BlobRef, and do not claim to have undone consumption of the original reader. Do not automatically repeat the same put. A caller that invokes put directly releases the reader; queue enqueue releases a reader it opened from the input exactly once in finally. Do not pass a private BodySource to user adapters; adapt it to the public RangeReader/AsyncRangeReader within the SDK. Each BlobStore.open context owns an independent reader positioned at the beginning for that ref; context exit closes/acloses the reader (the store itself remains borrowed).

BlobRef.key is the **identity of an ownership lease**; sha256/size are **content identity and validation values**, not the same identity. Within a store namespace, each successful put allocates a key different from all previous puts, including identical bytes, concurrent puts, and puts after restart; never reuse a deleted key. delete releases only the single lease corresponding to its key; subsequent deletes of the same ref succeed as no-ops. Do not release another key even if it points to the same digest. For a live key, if the ref's size/digest differs from stored values, raise BlobStoreError(action='delete'|'open') without changes. Deleting a deleted/unknown key is a no-op; opening one raises BlobStoreError(action='open'). Physical storage may deduplicate by digest, but must retain bytes while another key has a live lease or an open reader exists. Reject new opens of the same key after deletion; already-open readers may read the immutable bytes to completion.

Builtin SQLiteBlobStore/AsyncSQLiteBlobStore allocate a persistent namespace per database and a monotonically increasing lease number in 1..2**63-1 within the same publish transaction, returning the key as an opaque string. Do not reset the number on delete/VACUUM/reopen. At the numeric limit, raise BlobStoreError(action='put') with no publication; do not wrap. Map a ref table to content; use separate ref rows even for identical content. When the queue receives a ref from a successful put, it owns only that single lease and saves one owned ref per enqueue. If the subsequent QueueStore.put fails, release only the ref it acquired. Do not copy an existing ref's key into another entry and grant blob_owned=True twice. The queue does not delete caller-owned refs with blob_owned=False.

Records passed to stores are also frozen public types; exclude payloads/headers/URLs/keys from repr/str. `Origin(scheme:str,host:str,port:int)` is a frozen public value representing an effective origin normalized under shared URL rules (scheme is http/https, host is lowercase IDNA, port is 1..65535). ## 2. Integration with LogicalCall and OperationSession

Use the shared runtime's `LogicalCallContext` / `AttemptContext` / `OperationSession` and public `RequestOptions` / `ClientOptions` / `TimeoutOptions` / `RetryOptions`. Do not create an independent HTTP retry loop inside protocols. A child's deadline is `min(parent absolute deadline, child total deadline)`; the default child total timeout is 60 seconds. Default resource retries are 2, for at most 3 resource sends within the same child; `max_retries=0` also prohibits a resource resend following reauthentication after 401. OAuth token exchanges have a separate counter from resource attempts. Only the shared runtime's shared refresh is provider-owned with an independent 30-second/1-send budget; once, it reserves and consumes a send slot from the triggering call/parent that approved its start. Do not charge waiters again; an approved refresh may finish after the triggering caller's cancellation/deadline. Do not admit new resources/refreshes after the parent deadline.

The complete `SessionOptions` field set is only `total_timeout:float|None|Unset=UNSET`, `deadline:Deadline|None|Unset=UNSET`, and `max_network_sends:int|None|Unset=UNSET`. The effective deadline default is None; the other two values are in the table below. total_timeout is nonnegative (0 means immediate expiration), max_network_sends is nonnegative (0 prohibits new admissions with SessionLimitError), and None removes that local cap. bool/NaN/Infinity/negative values raise ConfigurationError. Reject max_reconnects/idle/parallelism and similar fields as unknown fields. Only the types in section 1.1 own kind-specific values. When both `deadline` and `total_timeout` are present, the earlier wins. The deadline runs from session creation and includes waiting for user consumption.

| Session | total_timeout | max_network_sends | Effective defaults of kind-specific options (not SessionOptions fields) |
| --- | ---: | ---: | --- |
| Pagination | 300 seconds | 3000 | 1000 pages, 100000 items, 8MiB decoded body per page, 64KiB cursor |
| Polling/LRO | 600 seconds | 2000 | 1000 polls, 1-second poll interval, 60-second maximum allowed poll wait |
| SSE/NDJSON | `None` (explicitly no overall deadline) | 16 | 60-second idle, 5 reconnects, 256KiB line, 1MiB event/record |
| WebSocket | `None` | 16 handshakes/token requests | 60-second idle, 5 reconnects, 1MiB message, receive queue 16, 30-second send, 5-second close |
| Resumable upload | 600 seconds | 10000 | 8MiB chunk (reduced by server maximum), 10000 chunks/parts, parallelism 4 |
| Batch | 600 seconds | 10000 | 100000 input items, batch 100 (reduced by server maximum), parallelism 4, 8MiB per item, 32MiB prepared-input buffer |
| Queue drain | 300 seconds | 1000 | 100 entries this invocation, parallelism 1, 8MiB entry body, store 10000 entries/256MiB |

Per-field precedence is **explicit fields in helper call kind-specific options/session_options > the same fields in ProtocolClientOptions.defaults[helper name] > effective kind defaults**. None as an options argument is equivalent to omitting the object; pass None to a field to remove a limit. Only idle_timeout in StreamOptions/WSOptions inherits merged RequestOptions.stream_idle_timeout (call > view > client > generated default 60) immediately before the kind default. For the HTTP stream as a whole, SessionOptions.total_timeout/deadline owns one session deadline; raw-handle RequestOptions.stream_total_timeout supplies an additional cap after each connection is handed over, taking the minimum. Do not duplicate total_timeout in StreamOptions. Explicit None in SessionOptions does not remove the child's 60-second total timeout or raw-handle caps. All awaits, sleeps, and lock waits share RUNTIME's deadline/cancellation primitives; do not create protocol-specific wait_for.

The independent P-OPTIONS oracle fixes: client idle 120 + StreamOptions() -> 120; explicit idle 10 -> 10; explicit None -> no idle cap with the session deadline retained; SessionOptions(max_reconnects=0) -> construction error; StreamOptions(reconnect=True,max_reconnects=0) -> initial connection only; defaults parallelism 2 + empty call options -> 2; explicit parallelism 1 -> 1.

Callers may explicitly set `total_timeout=None` outside streams/WS as well, but finite send/page/poll and similar caps remain. Each cap also requires an explicit None in its own field to remove it. Buffer/body/message/checkpoint size caps cannot be None. Even when users raise those limits, require finite positive integers.

A shared reserve function atomically consumes OperationSession send slots. Limit checks use `network_send_budget_used` (reservations/admissions), distinct from actual adapter-send observations in `network_send_count`. Ordinary children reserve immediately before sending; shared refresh reserves once when its start is approved, without refund on caller departure. HTTP page/poll/chunk/batch/result fetch/reconnect handshake/token exchanges count; cache hits, parsing, local queue enqueue, and local waits do not. After WS establishment, do not mix data/control frames into handshake counters; separately record `messages_sent/messages_received/bytes_sent/bytes_received`. Disable hidden reconnections inside the WS transport. At a session limit, send nothing further and raise `SessionLimitError` (kind/limit/progress/resume_state in section 1.3). Do not disguise partial results as successful completion.

Retries use the same logical request; resume/pagination/poll/chunk operations create **new child logical requests** from explicit state. An idempotency key is constant across all attempts of a child. Do not conflate different pages/cursors/chunks under the same key. The initial create request's key may be retained in resume state, but do not repeat create after obtaining the server's session/ID.

Automatic reconnect continues the current OperationSession without resetting budgets. An explicit user `.resume(..., session_options=...)` creates a new OperationSession and applies that invocation's budget. State saves cumulative progress, retrieval/consumption positions, cycle-check history, and unconfirmed deliveries; do not replace the same remote operation with another create. Observe old and new session IDs/counters distinctly. Do not serialize monotonic deadlines across processes; wait the saved not-before remaining seconds again starting at resume (a conservative wait that does not deduct time in storage). Only server-declared UTC expiry is checked against current UTC.

Page has `items:tuple[T,...]`, `data:P`, `response:ResponseInfo`, `continuation:Continuation|None`. `.next_page(page: Page[T,P]) -> Page[T,P] | None` fetches manually and rejects Pages with any other fingerprint. `iterate()` performs zero network operations at creation; the first `next`/`anext` fetches the initial page. Define `Pager[T,P].__iter__() -> Iterator[T]` and `iter_pages() -> Iterator[Page[T,P]]`. The async ordinary-def factory returns `AsyncPager[T,P]`, with `__aiter__() -> AsyncIterator[T]` / `iter_pages() -> AsyncIterator[Page[T,P]]`. Mixing item and page modes on one Pager raises `ProtocolStateError`.

Completely decode each page and close its response before returning values. Do not fetch the next page until the current page is consumed. Retain canonical encodings of continuations in the session's visited set; a repeated continuation raises `PaginationCycleError`. max_pages bounds the cursor count. When a page/item limit is reached and continuation remains, raise a limit error on the next iteration; `max_items=0` ends empty with zero network operations. However, combining it with explicit non-None call compression produces the zero-applicable-children configuration error in section 12.1. A normal terminal page ends normally even exactly at the limit.

`Pager.checkpoint()` saves current raw page bytes + next continuation + consumption index + initial immutable request. `.resume(state)` from a partial page redecodes and returns saved remaining items before fetching the next page. Checkpoints do not pickle model objects. A current page exceeding 8MiB raises `ProtocolSizeError` when fetched instead of producing a huge checkpoint. The SDK guarantees neither server-side collection snapshot consistency nor exactly-once delivery. If metadata declares a snapshot token, retain it from initial into every request through Binding.

## 4. C20 polling / long-running operation

Metadata requires `create:OperationRef`, `accepted_statuses:list[int]`, `poll:OperationRef`, create-to-poll `bindings`, `state:Selector`, disjoint literal sets for `pending/succeeded/failed/cancelled`, and `result`. `result` is `{kind:inline, selector, schema}`, `{kind:operation, operation, bindings}`, or `{kind:none}`. `interval` is `{seconds:1, retry_after_header:"Retry-After"|null}`. Use of Retry-After requires explicit metadata. Generate `remote_cancel:{operation,bindings}` only when declared. Unknown state raises `PollingStateError`; do not infer success.

`.start(<create arguments>, options, session_options)->LroHandle[T,P]` (the concrete helper handle type in section 1.4 when remote_cancel is declared) executes create as one LogicalCall, validates accepted status, and returns. Do not repeat create except for create attempts deemed safe by shared retry. An API where a nonaccepted status can represent synchronous success explicitly declares `immediate_result:{statuses,selector,schema}` and returns a completed handle. Otherwise, raise a status error.

The handle provides `.status()->PollSnapshot[P]` (one explicit poll), `.wait()->T` (poll until terminal), `.checkpoint()->ResumeState`, and the helper's `.resume(state)->LroHandle[T,P]` (the same concrete helper handle type when remote_cancel is declared). PollSnapshot[P_co] is a frozen output record with read-only `state:WireValue, terminal:bool, data:P_co, response:ResponseInfo`. P_co is a covariant TypeVar bound to the existing poll type, separate from the final LRO result type T. LroHandle[T,P] and AsyncLroHandle[T,P] are invariant. Repeated `.wait()` after success returns the saved result with zero network operations. Concurrent `.status()` and `.wait()` raise `ProtocolStateError`. Failed termination raises `OperationFailedError` (retaining the snapshot); cancelled termination raises `OperationCancelledError` (retaining the snapshot).

Use the create-response receipt time as the first poll's baseline: `next_not_before=receipt monotonic time+max(interval,valid Retry-After)`. After shared poll retry completes, compute the next poll's not-before once from its final response. Do not unconditionally add retry sleep and poll sleep. If the required wait exceeds PollOptions.max_wait (default 60 seconds) or the remaining deadline, raise `PollWaitLimitError` (retaining resume_state); do not round down and send. Although `status()` is one explicit caller-requested fetch, it respects the same wait without violating the server's Retry-After not-before.

`.close()` only stops local polling. Only explicit `.cancel_remote()->CancelReceipt[C]` calls the cancel endpoint (the method is not generated without metadata). At generation time, close C to that cancel endpoint's existing response type. Do not put a method with free C on public base LroHandle[T,P]; only the helper-specific nongeneric handle subclass generated when remote_cancel is declared returns concrete CancelReceipt[C]. The receipt is a frozen value with read-only data:C and response:ResponseInfo. The async-specific handle's cancel_remote is async def with the same result type. Calling the cancel endpoint does not imply job completion; preserve the last poll state until the next status fetch. Local cancellation/timeout does not mean remote job deletion. With result.kind=none, wait returns None. A result-fetch operation also counts as a child; do not refetch a result already obtained successfully. The checkpoint saves the create-response-derived ID/URL, state, relative not-before wait, and initial creation key; resume does not call create. Use `expires_at:Selector` only for a wall-clock expiry supplied by the server; do not invent an undeclared TTL.

## 5. C21 SSE / NDJSON / HTTP stream

Metadata explicitly supplies `operation`, `kind:sse|ndjson`, media, event-schema mapping, completion, and resume. `event_schema` is a single SchemaRef, or `discriminator:{from:event_type|body,pointer?}` plus a literal-to-SchemaRef table. Unknown discriminators are errors by default; return `UnknownEvent` only for explicit `unknown:raw`. `error_events` specifies discriminator literals and existing error schemas. Matches raise `StreamRemoteError` instead of being treated as ordinary events.

Require one completion form: `{kind:eof}`, `{kind:sentinel, value:<exact raw data/line>}`, or `{kind:event_type, value:<SSE type>}`. Check sentinel/type before typed decoding; do not yield the terminal value itself. EOF before termination raises `StreamInterruptedError`. Even under an eof contract, an incomplete frame raises `IncompleteFrameError`. NDJSON requires `final_line:require_newline|allow_eof`; decode the final complete JSON only with allow_eof.

`.open(<operation arguments>, options, session_options, stream_options)->EventStream[T]` validates the initial response headers/status/media before returning a handle. All `StreamOptions` fields/defaults/merge rules use the single table in sections 1.1/2. The overall deadline obeys the earlier of SessionOptions and the raw handle's additional cap. The 60-second LogicalCall timeout for opening a stream applies until handover; afterward, stream idle/total and the parent session deadline apply.

Iteration always returns `StreamEvent[T](data, event_type, event_id, retry_ms, sequence, raw_data)`. `raw_data` is a decoded string bounded by the event size limit and excluded from repr. `.data()` yields only data from the same iterator. Reject concurrent consumption through the two paths. Read only the frames needed for one `next/anext`. SSE follows WHATWG handling of UTF-8/BOM/CR/LF/multiple data lines/comments/NUL in id/retry digits; invalid UTF-8 uses standard replacement decoding. NDJSON uses strict UTF-8. JSON decode/validation failure raises `StreamDecodeError`; do not silently discard records. Check byte/line/event limits before every append; on excess, close and raise `ProtocolSizeError`. Measure idle only while waiting for bytes during a user's next/anext call, updating it even for comment/control bytes. Pause idle measurement after next returns, while session/stream overall deadlines continue.

Resume defaults to `{enabled:false}`. Enabling it requires `cursor:Selector|event_id`, next-request `write:RequestTarget`, `reopen_operation`, `bindings`, `completion`, `delivery:at_least_once`, and optional `expires_at?`. Do not automatically resume before any cursor has been delivered to the user. Save the cursor of the last event returned to the user, discard interrupted incomplete events, and create a new child request. An empty SSE event_id clears the cursor and suppresses Last-Event-ID. Events without an id inherit the previous id. NDJSON/body cursors require metadata `missing:inherit|error` and `null:clear|error`. Default reconnect=False returns interruption errors without explicit configuration. Even when metadata supports resume, do not reconnect unless the caller enables it.

Metadata `resume.reconnect_on` specifies a finite set of eligible automatic reconnect reasons, defaulting to `[transport_interruption]`; the only additional value is `incomplete_eof`. transport_interruption is limited to read-phase ReadError/ReadTimeout/RemoteProtocolError classified as retryable by the shared adapter. Only explicit incomplete_eof permits resumption from StreamInterruptedError for EOF before declared termination or IncompleteFrameError at EOF. Do not reconnect for reasons outside this set. In particular, StreamDecodeError, ProtocolSizeError, ordinary schema/validation failure, auth rejection, StreamRemoteError, protocol idle/total deadline/budget excess, normal termination, and caller cancellation/close return the original terminal outcome with zero reconnects even if a cursor exists. Retry eligibility for the reopen HTTP request itself is determined solely by the shared LogicalCall contract.

Reconnect delay uses shared RetryOptions backoff and waits at least a valid SSE `retry:` value when present (StreamOptions.max_reconnect_wait defaults to 60 seconds; excess is an error). `max_reconnects` counts **reconnections across the entire session** and does not reset on events. Initial HTTP retries and each reopen's HTTP retries each use their LogicalCall budgets; all sends accumulate in the session budget. Exhaustion raises `StreamResumeExhaustedError` (retaining resume_state), never normal EOF. No automatic deduplication or exactly-once delivery. Explicit `.checkpoint()` / `.resume(state)` uses the same contract. Zero reconnects after terminal receipt, close, or caller cancellation.

## 7. C23 webhook / callback

Signed receiver helpers do not create HTTP clients. Place metadata-selected helpers at public `webhooks.<api_name>` in the generated package. Require event SchemaRef/mapping, discriminator, and signature profile. Treat OpenAPI callbacks only as information about send/receive schemas; do not infer signatures. Builtin profiles are `hmac-sha256` / `hmac-sha512` / `ed25519` / `rsa-pss-sha256`. HMAC uses the standard library; public-key methods use optional `cryptography`. Metadata requires the signature header, encoding (hex/base64/base64url), prefix, multiple-signature separator, key-ID location, timestamp header/unit, and signed-parts order. signed-parts elements are only raw-body, the timestamp's **original byte representation**, delivery-id header bytes, and literal ASCII bytes. Header strings prohibit obs-text and are encoded once as ASCII/declared UTF-8. Do not reserialize JSON or normalize newlines. RSA-PSS is fixed to SHA256/MGF1-SHA256/salt_length=32; Ed25519 uses raw signatures. Other methods require `kind:adapter` and the explicit verifier argument below; do not leave them as candidates to select during implementation.

`.verify(raw_body:bytes, headers:Sequence[tuple[str,str]], keys:KeySet[KeyT], *, now:datetime, replay_store:ReplayStore|None=None, options:WebhookOptions|None=None)->VerifiedWebhook[T]`. At generation time, close builtin KeyT and every helper's event T to the profiles/declared event schemas below. Only kind:adapter is a generic function that, in addition to the same keys argument, accepts required keyword `verifier:Verifier[K]` and binds the same K through keys:KeySet[K]. It returns the helper's fixed VerifiedWebhook[EventType]; do not derive a free event T from K. The async variant is `async def verify_async` with the same result type; only replay_store changes to AsyncReplayStore or None. Do not create an implicit event loop. `VerifiedWebhook[T]` is frozen/read-only with `data:T, delivery_id:str | None, timestamp:datetime | None, matched_key_id:str, duplicate:bool`. Defaults: at most 8 keys, 8 signatures, 16KiB header bytes, 8MiB body, timestamp tolerance 300 seconds into the past and 30 into the future. Methods without timestamps require `timestamp:none`; generated documentation must state that time-window replay prevention is unavailable. Follow metadata for multiple header values and signature splitting; do not arbitrarily choose among ambiguous values.

The order is size/syntax checks -> timestamp-window checks -> signature verification with candidate keys (constant-time comparison for HMAC) -> event decode -> replay store atomic `claim(namespace,delivery_id,expires_at)` if required. Invalid signature/signature format/timestamp rejection raises WebhookVerificationError from section 1.3 without constructing a typed model. With a key ID, consider only valid keys with that ID; without an ID, try all candidates and record the first successful key. Exclude keys/signatures from repr/exceptions. Without replay_store, duplicate=False does not guarantee duplicate prevention. A store requires delivery_id; an existing claim returns duplicate=True under the default policy, or `WebhookReplayError` under `duplicates:reject`. Store failures fail closed with `WebhookStoreError`, without fallback to unsigned success.

`ReplayStore` only claims and retains entries until expiry; do not put a global store in the SDK. namespace is the helper fingerprint + explicit caller namespace. Claim expiry is `timestamp+past_window+future_window`, or `now+replay_ttl` (default 300 seconds) without a timestamp. Guarantee duplicate detection only until expiry. Builtin `MemoryReplayStore(max_entries=10000)` is explicitly constructed independently of clients; when full, raise `ReplayStoreFullError` without discarding live entries. Injected external stores can provide multiprocess atomicity. Adapter verifiers must meet the same limits/cancellation/secret rules and known-answer tests of `Verifier[K]` immediately below; internal networking is prohibited.

## 9. C33 resumable upload

`kind:resumable_upload` selects `profile:offset|parts`. Public APIs are `.start(source:UploadSource, <create arguments>, options, session_options)->UploadHandle[T]` and `.resume(source,state)->UploadHandle[T]`. With remote abort declared, both return the concrete helper handle type from section 1.4; async closes to AsyncUploadSource and the corresponding AsyncUploadHandle/concrete type. Handles provide `.advance()->UploadProgress`, `.run()->T`, `.checkpoint()`, `.close()`, and explicit `.abort_remote()` only when metadata declares it. Local close/cancellation does not delete remote uploads.

UploadProgress contains `confirmed_bytes`, `total_bytes`, `confirmed_parts:tuple[PartReceipt,...]`, and `complete:bool`. advance completes one chunk for offset or one wave of up to parallelism parts before returning. run repeatedly advances to completion and returns the result. T is None for length completion, and the existing success type referenced by metadata for operation completion/parts complete. A completed handle's run returns its saved result with zero network operations. Concurrent advance/run raises `ProtocolStateError`.

`UploadSource` implements immutable content identity (size, SHA256), required `max_parallel_ranges:int>=1`, and an `open_range(offset,length)` context manager. Async uses native async readers. Public signatures are in section 1.2. Even with up to max_parallel_ranges simultaneously open ranges, each reader has an independent position within its specified range; seek/read/close on one cannot change another's bytes. SDK effective concurrency is `min(UploadOptions.parallelism, source.max_parallel_ranges)`, or 1 for the offset profile. A source sharing one seek handle is usable if it declares max_parallel_ranges=1; the SDK never opens ranges concurrently. Missing/zero/negative capability is rejected before sending, with the same cross-task rule for async. Provide builtin `from_bytes` / `from_path`; path calculates the hash once with bounded memory, records size/inode/mtime, and raises `UploadSourceChangedError` on changes detected for each range. The caller is responsible for not modifying the source during processing; this is not a complete filesystem snapshot. On resume, revalidate content identity before network access. Injected sources are borrowed; close only ranges opened by the SDK. Nonseekable one-shot streams are not resumable sources; use ordinary C13 uploads. No automatic disk spooling.

Builtin bytes/path sources open independent readers/file descriptors for every range. AsyncFileUploadSource owns a separate descriptor and position per reader; positions remain independent even when disk jobs are serialized through one worker. Builtin max_parallel_ranges is 4. Users wanting higher concurrency use a source declaring an explicit independent-handle limit.

**Consistency between the original and transmitted ranges**: After fixing chunk layout from server limits and UploadOptions, but before network/create/probe, start/resume scans the source from beginning to end through one reader. Compute expected SHA256/length for every chunk and whole-content SHA256; require exact agreement with UploadIdentity. On resume, also compare the checkpoint's layout/expected digests. The expected manifest must fit ResumeState's 16MiB maximum; excess raises ProtocolSizeError with zero network operations. Parallel workers completely read each range into a dedicated buffer no larger than chunk_bytes, check length/EOF/expected digest, then send that buffer as the same replayable payload. Do not first determine the expected digest solely from bytes obtained through parallel reading. Even when resuming at a partial offset, validate the relevant original chunk before sending the unconfirmed suffix. Short/long ranges and hash mismatches from the source raise UploadSourceChangedError and prohibit further sends/complete; retain already-confirmed remote parts in state. RAM is limited to effective parallelism x chunk_bytes plus fixed read buffers and the digest manifest. No automatic spooling. This precheck prevents completion with corruption from a source violating concurrent-seek requirements; it does not guarantee a complete snapshot against filesystem changes.

The explicit async path builtin is `AsyncFileUploadSource.from_path()`. One source-owned worker performs only file open/read/hash/close. Maximum job queue 8, read chunk 64KiB, prefetch at most two chunks; queue waiting also obeys the parent deadline/cancellation. Join the worker on the source context's aclose; the caller owns the worker of a source injected into the SDK. Do not execute cancelled jobs that have not started. For disk reads already started, discard the resulting buffer and stop additional reads/network sends after completion. Do not guarantee forced termination of blocking OS file I/O.

Required offset-profile metadata: create, session ID/URL selector, probe operation + remote_offset selector, append operation + offset/length/body write bindings, server maximum chunk, `partial_commit:allowed|forbidden`, and `completion:{kind:length}|{kind:operation,operation,bindings,result_schema}`. Offsets are nonnegative integers; remote offset > size or below the previous confirmed offset is an error. append sends one range. If its outcome is unknown after transmission, suppress append HTTP retry and probe the remote offset. An unchanged offset permits resending the same range as a new child; the expected ending offset confirms completion; a partial offset permits the remainder only with allowed. forbidden raises `UploadOffsetError`. Each uncertain append gets UploadOptions.max_uncertain_probes checks, default 3; if still unresolved, raise `UploadDeliveryUnknownError` with state.

Required parts-profile metadata: create, session ID, list_parts, part index/receipt/digest selectors, upload_part (index/body/digest Binding), complete (ordered index/receipt list and result SchemaRef), server maximum parts/part bytes, minimum part bytes, and last-part exceptions. Part indices start at 1; checkpoint fixes layout and chunk size. Effective chunk_bytes below the server minimum, impossible layout including last-part exceptions, or a required part count exceeding API/UploadOptions limits raises ConfigurationError before create. Execute with bounded default parallelism 4; on intermediate failure, stop scheduling new parts, cancel/close in-flight parts, and record their outcomes as unknown. Resume reads list_parts, checks matching digests at the same indices, and skips them; mismatches are errors. Do not resend successful parts as an entire batch. complete is one logical request; without API idempotency guarantees, do not repeat it when its outcome is unknown. Only metadata `completion_probe:{operation,bindings,state,completed_values,result}` permits resume to query the confirmed result. Without it, retain unknown completion as `UploadDeliveryUnknownError` without declaring either completion or noncompletion.

Checkpoints retain the server session, source identity, chunk size, confirmed offset or part receipts, expiry, completion state, and logical operation identity. Do not repeat create. Server expiry requires a metadata selector; expired state raises `UploadExpiredError`. Do not infer TTLs; APIs without expiry information use probes to check existence. Methods sending content digests/checksums explicitly declare algorithm, encoding, and scope in metadata.

Independent tests P33-U: compare bytes stored by an independent server with the original digest; disconnect before/during append/after ACK; unchanged/partial/regressed/excessive offsets; one-part failure; reordered completion; zero create on resume; source changes; expired sessions; unknown partial/complete outcomes; range-handle release; bounded memory. The R2-16 oracle includes: an independent-reader source that reads four ranges with distinct byte patterns concurrently through a barrier; a single seek handle/max_parallel_ranges=1 with at most one simultaneous open; a shared-seek source incorrectly claiming cap 4, whose expected-digest mismatch gives zero sends for that part/zero completes; failure after a post-baseline source change; final sync/async server digests matching the original; and zero network operations during resume revalidation. A tus-compatible API may explicitly map to the offset profile and use its HEAD/PATCH/offset oracle, but do not add headers to an API that does not declare tus. [tus 1.0.x](https://tus.io/protocols/resumable-upload) (checked 2026-09-17).

If already sent, persist delivery_unknown as terminal without automatic resend. Only `.retry_unknown(id)` may validate TTL/remaining deliveries and return it to pending with the same key. Crash recovery without cancel_requested follows the at-least-once rules below.

Lease duration is `max(entry.policy.lease_min, remaining entry child deadline+entry.policy.lease_grace)`. One entry delivery's overall deadline is bounded by the earlier of entry.policy.max_delivery_timeout (at most 300 seconds) and child/parent deadlines. Store claim is atomic. Expired leases after process crashes return to pending, so delivery is at least once, not exactly once. Fix max deliveries/TTL/backoff/lease in entry.policy from resolved QueueOptions at enqueue. Default max_deliveries is 5; entry TTL is 24 hours for side-effect-free operations, otherwise min(24 hours,server dedupe TTL). Drain queue_options may change only max_entries/parallelism; explicit changes to entry-policy fields raise QueuePolicyConflictError. Entries whose TTL/deadline puts them beyond the key's safe period become dead. For a retryable terminal failure, save `next_not_before=max(now+delivery_backoff, server_not_before)`. delivery_backoff is full-jitter exponential using entry.policy.retry_initial_delay/retry_max_delay (default base 5 seconds, maximum 600 seconds). server_not_before uses the shared Retry-After parser on the final response; even if the child's max_retry_after=60 ended HTTP retries, do not shorten server waits such as 120 seconds. A wait exceeding only the current drain deadline reschedules the entry as pending and ends its delivery for this invocation; other ready entries proceed within remaining budget. If it exceeds entry TTL/idempotency retention, mark dead. Persist UTC not-before and the remaining wait at save time; a clock rollback must not shorten the remaining wait. Shared retry operates only within each delivery. Immediately before the first resource send, transactionally save `send_intent` and increment delivery count once; do not send if saving fails. A process crash immediately after saving consumes one delivery even without an actual send, a conservative limit distinct from network_send_count. CircuitOpen/provider not ready before send_intent is deferred and leaves delivery count unchanged.

If store acknowledgement fails before response success is confirmed, leave the lease with delivery_unknown so the same key can be processed again. Provider scope/partition/helper fingerprint changes raise `QueueBindingError` without automatic migration. Schema migration is transactional only between SDK-defined versions; reject opening unknown newer versions. `DrainReport` contains counts and entry IDs for success/rescheduled/dead/unknown/deferred, without secrets/bodies. A full store raises `QueueFullError` without discarding old unprocessed entries.

Independent tests P33-Q: RangeReader/AsyncRangeReader + BlobStore fixtures using no private imports verify explicitly allowed bodies over 8MiB, short reads/EOF in 1..64KiB, matching size/SHA256/key, put never closing a borrowed reader, finally close exactly once for readers opened by the queue, zero partial refs/zero repeated puts on read/cancel/storage failure, and independent open-context readers/one close. Two enqueues of identical 10MiB content through an explicit custom BlobStore and raised body limit must have matching size/digest and distinct keys; after A succeeds/is purged/is deleted twice, B's open and delivery bytes must still match the original. Verify the same lease isolation with physical deduplication, concurrent puts, and a third put after deletion. Test builtin SQLite with a separate vector of at most 8MiB, including reopen. Also cover zero deletes of borrowed refs; releasing only the new ref acquired when QueueStore.put fails; continued reading after deletion for an already-open reader; rejection of new opens on the same key; and zero changes after ref size/digest tampering. Cover zero network operations during enqueue, concurrent claims by two processes, crashes after claim/after response but before acknowledgement, identical idempotency keys, five deliveries/TTL, redelivery not-before for Retry-After 120 seconds against a 60-second child cap, server waits exceeding drain deadline/entry TTL, clock injection, capacity, blob-digest corruption, tokens not persisted, unchanged partition after refresh, drain cancellation, database transaction failures, restarts, and schema versions. Automatic communication with real APIs and scheduler creation are outside this feature.

## 12. C33 circuit breaker / compression

Circuit breaking defaults to disabled. Enable it with both `ClientGenerationConfig.operations[].runtime.circuit_group` (channel.runtime for WS) and `ClientOptions(protocols=ProtocolClientOptions(circuit=CircuitBreakerOptions(enabled=True)))`. Apply the same execution path to ordinary endpoints and helper children. State is per client instance + origin + credential partition + group, shared only through explicitly injected stores. Five consecutive failures of **completed child resource LogicalCalls** open the circuit, with a 30-second cooldown and only one concurrent HALF_OPEN call. Count Connect/Read/Write/RemoteProtocol transport failures and HTTP500/502/503/504. Pool timeout, cancellation, auth/validation/programming errors, 429, and cache hits do not count as failures. Success resets the consecutive count to zero; half-open success becomes CLOSED; failure becomes OPEN for 30 seconds. Half-open cancellation releases the probe permit without increasing failures.

While OPEN, raise `CircuitOpenError` (retaining retry_at/key) before send/auth exchange without consuming send count. Do not count individual retry attempts as five failures or mix token acquisition into failures of another backend. State transitions are atomic under a lock with identical sync/async rules. Public `Client.reset_circuit(group:str, *, origin:Origin)->None` / async `AsyncClient.reset_circuit(...)` is a local, zero-network operation resetting the store key for the current client's credential_partition and explicit origin/group. Advance generation so old in-flight permit results cannot overwrite post-reset state. Independent tests P33-C: attempt counts up to five logical failures, success reset, cooldown fake clock, one send among 20 concurrent half-open calls, cancellation permits, exclusion of 429/parse failures, queue deferral, and isolation of multiple clients/partitions.

Shared RUNTIME ResolvedCompression is authoritative for request-compression values and provenance. Resolve them through the same prepared-body path for ordinary endpoints and helper children without losing configuration origin. Validate HTTP token syntax and registered encode capability for non-None tokens at configuration time, but selecting one in client/view/generated defaults does not require every operation to declare it. Ordinary endpoints determine initial-request body presence through codec/argument resolution before applying the table below. Only explicit calls at helper entry first create the one-time preflight/admission in section 12.1. Do not peek at/consume a body reader solely to determine compression eligibility.

| Compression origin / value | Fixed initial-request behavior |
| --- | --- |
| Token inherited from generated defaults / ClientOptions / view | Apply only when an actual body exists **and** the operation's accepted_content_encodings contains the token. Otherwise off. An inherited value does not fail for absent bodies, undeclared operations, request_raw without operation binding, or WS handshakes |
| Explicit non-None token on an ordinary endpoint/request_raw call | Require both an actual body and a matching operation declaration; either missing condition raises ConfigurationError before sending. Explicit request_raw use raises the same error. Ordinary operation with_raw_response/with_streaming_response retains operation binding and follows ordinary-method rules |
| Explicit non-None token on a helper-entry call | Once before network access, check under section 12.1 that at least one applicable child exists. After admission, apply only to children with actual bodies and matching operation declarations; poll/probe/next_url/reopen and similar children failing those conditions are off. Do not repeat strict call validation for every child |
| None at any layer / UNSET at call | None means off at that layer. UNSET inherits the lower origin unchanged without promoting it to explicit call origin. Values forwarded by helpers to child calls retain origin; track helper admission separately |

UNSET optional body means absent body; explicit b'' and JSON null encoded under a nullable schema count as bodies. Gzip from generated defaults/client/view is also off for an undeclared operation with a body. After initial strict validation, an allowed 303 or similar redirect hop that removes the body turns the effective token off and removes body headers such as Content-Encoding. Do not reject body removal within the same call as a new call-configuration error.

### 12.1 Helper compression admission and application unit

The application unit is the **workflow originating from one public helper execution entry point**. Create private `HelperCompressionAdmission(helper_fingerprint, token, child_slots)` exactly once. child_slots is a finite mapping of `(role, OperationRef)` that the generated helper can invoke from this entry point/state, not URL strings or arbitrary caller-added requests. Retain value and origin as RUNTIME ResolvedCompression; do not rewrite origin=call to client/view. Distinguish only helper children carrying admission from strict ordinary-endpoint validation. Do not add public options/metadata fields or create a bypass that weakens explicit compression on ordinary endpoints.

Run preflight once after helper configuration/binding/ordinary argument validation, **before any credential acquisition, shared refresh start, limiter acquisition, or resource send**. Lazy iterate/resume factories do not enumerate input at creation; first next/anext is the execution entry. Bind children reachable in the automatic workflow under current state/options to the operation declarations in the table above. Admit if at least one child provably has both a matching token declaration and a body. Evidence is known arguments, a body key in a saved request, or an explicit Binding that necessarily constructs a body value. A body Binding proves presence even if its source value is not yet retrieved: successful construction of the child is governed by a total rule supplying a value (including null). Missing/wrong types remain ordinary ProtocolDataError; do not turn them into UNSET and send. Do not infer presence solely from an optional-body schema or arbitrary future values. Do not count completed branches, disabled reconnects, creates excluded from resume, or saved Results that will not be sent as candidates.

Zero applicable children raises `ConfigurationError(field_path=('options','compression'), condition='no_applicable_helper_child')`, with zero token/resource sends and admissions. Empty batches, empty drains, max_items=0, and **new resume calls** on completed state produce the same configuration error for explicit non-None call compression. None/UNSET/inherited tokens do not get this existence check and retain ordinary successful empty processing. Admission based on a conditional later child does not guarantee one compressed send; for example, the API may complete immediately. This preflight does not infer future execution counts from responses not yet received; it checks that the fixed workflow has an explicit request-construction path capable of applying compression.

| Helper execution entry | Preflight children and body evidence / behavior after admission |
| --- | --- |
| Pagination page / iterate | The initial operation uses its actual argument body. Cursor/offset/page uses body-construction rules of the same operation after updates. next_url/link defaults to GET/no body, so compression is off. Reuse the original operation's body/token declaration only with explicit repeat_request_body=True and replay/safety conditions |
| Pagination next_page / resume | New admission. Retrieved pages/saved items are not candidates; examine only the next request from saved continuation and subsequent legal continuations. Automatic Pager next-page execution inherits the original admission and does not error after switching to GET |
| Polling start / resume | start uses create's actual body and explicit body Bindings for poll/result operations. resume includes only remaining poll/result and excludes create. status/wait retains handle admission; bodyless GET is off. Repeated wait on a completed handle returns the saved result without creating new admission |
| SSE/NDJSON open / resume | open includes the initial operation and reopen operations for enabled reconnect (metadata enabled, caller reconnect=True, max_reconnects not 0). resume includes only reopen. Determine bodies from input/saved requests/explicit cursor Bindings. Even if only initial POST supports compression, GET reopen is off. Automatic reopen retains the same admission |
| WebSocket / cache fetch | Handshake/cache fetch has no body, so explicit non-None call compression is a zero-network configuration error. An explicit cache mutations wrapper checks its single operation's actual body; local invalidation is not a candidate. WebhookOptions does not accept compression |
| Resumable upload start / resume | start includes create, append/upload_part from the actual layout, and legal complete branches. resume includes only remaining append/part/complete and probe/list_parts/completion_probe from saved state, excluding create. Prove a body for nonempty unconfirmed ranges from source.identity/layout; do not invent chunks for zero-byte completion. Do not open source/range readers for this decision; separately run section 9's existing original-digest validation before network access. Bodyless probes and similar requests are off; compress only children with actual bodies and declarations. Retain original-byte offset/digest rules |
| Batch iterate / resume / retry_items | Use the single batch operation, shared arguments, and value constructed in the body by the items RequestTarget. Prepare only the first candidate batch within existing batch_size/byte/prefetch limits; do not enumerate all input or read body readers for compression eligibility. resume excludes saved Results and decides from an unsent prepared batch or the source's next batch; do not send that new batch before returning saved Results. retry_items includes only the explicitly failed subset. Empty input/zero limit means zero applicable children for an explicit token |
| Queue drain | Only the first finite claim set described below. Use each entry's saved operation and the body key in its precompression prepared payload or non-None blob. Empty bytes/JSON null/zero-byte blobs count as bodies. No BlobStore.open is needed for the decision. With mixed aliases, compress matching entries only; others are off |

cancel_remote/abort_remote are controls explicitly requested later by the caller, so cannot alone satisfy start/resume preflight. When executed from an existing handle, they belong to the same admission/child_slots and are compressed if they have actual bodies and matching token declarations, otherwise off. HTTP retry replays the same child's compressed payload; automatic pagination/poll/reopen/append resolve the above conditions as new children. Add automatic Content-Encoding and similar headers only to that child's prepared body; do not write them into parent RequestOptions or the initial request. Do not apply compression to token acquisition.

A drain with explicit non-None call compression performs `QueueStore.claim(limit=QueueOptions.max_entries, ...)` once and fixes that finite tuple (default maximum 100) as this invocation's set. claim itself is local store work; inspect only precompression payload/ref metadata without buffering blob bytes. Do not replenish the drain with newly arrived entries. On zero applicable children, inspection failure, or cancellation, return only its own leases to pending through compare_exchange without changing not-before/policy/delivery_count/send_intent. An unsent entry observed with cancel_requested follows ordinary cancelled transition; do not overwrite leases transferred to another worker. On CAS conflict, recheck once with get; if the lease is still the same, attempt return once using the current version. If return is impossible, retain QueueStoreError in the original configuration/cancellation error's secondary_errors and defer to ordinary expired-lease recovery, preserving zero network operations. After successful admission, process in created_at/ID order with default parallelism without skipping ordinary lease/CAS checks before each send. Entries that expire or move to another worker while waiting become deferred with zero sends and are not reclaimed in this drain. Drains with omitted/None/inherited compression retain existing claim behavior.

Admission is private live-handle state, never serialized into ResumeState or QueueEntry.payload. Checkpoint/import/new resume checks anew from the helper fingerprint and current options/state. Saved requests/queue payloads retain the immutable pre-content-coding representation; do not apply new compression twice to an already-compressed body. Existing-handle status/wait/run and automatic next/reopen retain admission; retrieving an already-successful result does not rerun strict validation.

Independent P33-Z-H (also connected to P19/P20/P21/P33-U/B/Q and RT01/CG07): independent servers verify Content-Encoding/expanded bytes/arrival counts for successful wait from gzip-declared create POST -> bodyless poll GET -> result GET; compressed POST -> next_url GET versus repeat_request_body; POST stream -> GET reopen; and upload with undeclared create/HEAD probe -> gzip only for declared append/part -> uncompressed complete. ### 12.2 Content-coding execution and resource limits

Builtin gzip uses level 6/mtime 0/no filename and is incremental, subdividing input into chunks of at most 64KiB. Keep Content-Encoding consistent; conflicts with an existing caller header are errors before sending. Resends of compressed bodies also follow shared BodySource's same-payload/replay contract. Compression does not turn a one-shot body into a replayable body.

Builtin response content codings are identity/gzip/deflate (zlib framing). The HTTPX2 adapter receives responses in stream mode, passes content-coded bytes from `iter_raw`/`aiter_raw` to the codec, and decodes exactly once. Raw-handle `iter_raw_bytes` returns content-coded bytes; `iter_bytes` returns once-decoded bytes. Prohibit double decoding alongside automatic transport decoding. For br/zstd and others, match `ClientGenerationConfig.content_coding_adapters` registrations with implemented ContentCoding instances in `ProtocolClientOptions.content_coding_factories`. The tables in sections 1.1/1.2 are authoritative for schemas/signatures. Request encoders meet the same bounded CodingStep contract. Accept-Encoding advertises only RUNTIME's gzip/deflate plus registered decode tokens in declaration order; never implicitly advertise an unavailable codec. output stays within the specified size, consumed stays within input, and unconsumed input is passed to the next feed. Use empty input while draining; finish checks missing trailers/CRC/termination, ending with ProtocolDataError(condition='malformed') and retaining cause when invalid. A nonterminal step consuming no input and producing no output is a valid request for more input only when needs_input=True on empty input; otherwise it raises `ContentCodingProtocolError`. The same condition during finish means incomplete content coding and raises ProtocolDataError(condition='malformed'). Produce at most 64KiB at a time rather than checking sizes only after huge expansion. Require conformance tests for incremental operation, limits/cancellation, and unknown/malformed-stream failures; an absent adapter does not count as support.

Align decoded buffered-body default 16MiB, error-body 64KiB, and read-chunk 64KiB with the shared runtime. Streams prioritize per-event and similar limits; each decoder layer has the default cumulative expansion ratio `decoded_bytes <= max(1MiB, encoded_bytes * 100)`. Excess raises `DecompressionLimitError` and closes the response; even the raw handle's decoded path does not allow unlimited expansion. Decode stacked Content-Encoding in reverse order, with at most two layers; decoding an undeclared coding raises `UnsupportedContentCodingError`. `iter_raw_bytes` may return unknown codings unchanged. The only public stream-total field is client/view/call `max_stream_bytes:int|None`, with constructor default UNSET and effective default None (no total cap); explicit nonnegative integers are allowed (0 permits only empty bodies). Do not define or use `DownloadOptions`. `iter_bytes` / `stream_to` cumulatively check decoded bytes, including identity; `iter_raw_bytes` checks content-coded bytes against the same field's cap. Only one path may be selected; consuming both raw and decoded raises the shared handle-state error. Close before passing an over-cap chunk to the user and raise `ResponseTooLargeError(representation="decoded"|"content_coded",limit,observed_bytes,info)`, with zero resends. The `read()` buffer cap is separate `max_response_bytes` (effective 16MiB); stream None does not remove it. Expansion ratio, parser frame, chunk, and concurrent-buffer limits remain independently enforced. P33-Z/RT09 uses the same fixture to verify default stream_to of 100MiB identity/gzip within buffer limits, raw/decoded differences under an explicit 16MiB cap, exception class/one close/zero resends immediately beyond the boundary, and read failure at 16MiB. The independent P33-Z compression-selection oracle applies gzip from each of generated defaults/client/view to declared POST bodies, undeclared POST bodies, bodyless GET, request_raw bodies, and WS connections: only the first is gzip; the rest preserve wire bodies without Content-Encoding. Explicit call gzip on ordinary endpoints gives zero-send ConfigurationError for undeclared/bodyless/raw requests; WS gets the same error from zero applicable children in section 12.1; P33-Z-H verifies subset application among helper children. Verify call None off, call UNSET preserving original origin, empty bytes/JSON null as present and optional UNSET as absent, preserved origin in helper children, and off without error on a subsequent 303 hop removing body/headers. The default 100MiB gzip fixture uses data within expansion-ratio limits, separate from bomb vectors. Independent tests P33-Z: external gzip/zlib vectors, corrupt CRC/missing termination, double coding, bomb ratios including small encoded bodies, chunk splitting, deterministic retry bodies, raw bytes/exactly one decode, and cancellation/close.

## 13. Completion criteria

Include each kind's metadata schema, generated sync/async helpers, runtime implementation, public types/docs/examples, P-API/P-OPTIONS, and dedicated P tests in the same implementation plan. Merely accepting configuration, generating stub methods, or diagnosing missing contracts does not complete that kind. Generate no helper for a spec lacking its API conditions; add no fixed overhead to ordinary endpoints or model-only paths.

The final gate combines P19/P20/P21/P22/P23/P25/P33-U/B/Q/C/Z with shared-runtime retry/auth/ownership/codec tests. Use independent servers, known vectors, and store failures as oracles; do not rely only on expected values generated by the generator itself. With protocol helpers both enabled and disabled, pass the gates preserving existing D bytes/order/API/behavior/performance/model-only dependencies. This gate measures implementation success. Leave no "design next" or "choose a candidate" gaps in this document; any need to invent values or failure policies during implementation is a contract defect to correct.
