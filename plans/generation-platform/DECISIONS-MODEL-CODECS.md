# Final contract for model codecs and wire boundaries

Created 2026-09-17; incorporates the user's decisions of 2026-09-18. This document records **planning decisions** for the new FastAPI / Python client, not completed product implementation. The initial client supports all five builtin model backends in the pinned dcg; the FastAPI server supports two backends: Pydantic v2 BaseModel and Pydantic v2 dataclass. The choices in this document must not be deferred to implementation. Acceptance tests that have not been run are explicitly identified at the end, separately from the decisions.

The FastAPI integration revision of 2026-09-18 makes this document's conversion, presence, and wire validation rules the contract for the **client, server codec adapters, and public factories that use ModelCodec**. Native FastAPI integration points follow the generation-time plan in the [FastAPI decisions](DECISIONS-FASTAPI.md) and delegate to the framework's public parsing/coercion/validation/filtering/serialization. They are not required to perform conversions exactly equivalent to this document's strict codec. Both paths retain model artifact invariance and the common OpenAPI semantics, binding, and ignored-header rules. The common codec retains support for all five backends for the client; server admission is limited to the two backends in §1. Use [DECISIONS-TYPING](DECISIONS-TYPING.md) alongside this document for final public annotations, overload correlations, and independent type tests.

Source references retain dcg SHA `3452dfbb428c4384f40cb16faf61aadfda58a3a8` where inspected; the implementation baseline is `4f96e22ea403a66faae96f3949d41dd61fc1186f`. Given the same selected D, input, and explicit model settings, preserve model bytes, files/order, public types, base classes, fields, defaults, native APIs, and import dependencies unchanged. Do not add an SDK base, sentinel field, cache, or serializer method to a model for a target's convenience. Do not bypass model constraints with `model_construct`, `object.__new__`, forced `setattr`, or type-string replacement.

The common implementation's ability to handle all five backends does not justify adding unused backend dependencies to each package. Do not ship builtin converters for the three excluded backends in the server; retain required common processing and explicitly declared dependencies of selected custom field adapters separately. Do not create a separate `FieldCodecFacts` type. Retain schema identity separately from final model/field identity. Do not rediscover classes, aliases, or union branches from annotation display strings. Also use known runtime APIs to check binding consistency, without renaming Python names from schema names. Dynamic results such as runtime alias generators are owned by public introspection or explicit adapters; do not misrepresent them as generation-time facts.

Check uses that require types through the common `require_type_bindings`. If scope makes a use `not_generated`, report `BND_MODEL_SCOPE_REQUIRED`; if it is `invalid`, use the original binding diagnostic. The codec must not generate extra models. The new `OpenAPIScope.Api='api'` is also an explicit user model setting; the target must not add this scope implicitly. Use ordinary D output with the same explicit `api` scope as the comparison oracle for model artifacts. Do not require unnecessary native types for schema-only documentation uses.

If a namespace collides with an existing model artifact, stop target generation with a diagnostic; do not rename the model. Each generation invocation is limited to one client or server target and passes that target's codec plan the same `GeneratedTypeContractBatch` finalized by its ordinary D generation. When client and server are generated separately, each package has its required private runtime; only codec development source/tests are jointly owned across all five backends. Do not create runtime cross-imports between generated packages or discovery, registration, or simultaneous updates of other targets. Generate shared models through ordinary D first, then generate and verify each target separately with model_mode='verify'. Transactions for a single target plus models / explicit metadata / a remote lock follow ENTRY and do not change the meaning of the binding batch or runtime protocol batch helpers.

Expose generation-time CodecAdapterRegistration / SchemaDirectionalUse and manifest input records through the generator's target configuration API; do not add them to generated model modules. Normalize the generator and generated runtime's capability records to the same version 1 data schema for comparison; do not require matching Python class identity or imports of the generator from the generated runtime. ModelValue/ModelInput are frozen records constructed by the codec; the user-facing value construction contract is the bound factory in §3.

## 3. Public types and entry points

The following defines interfaces; this document does not create an implementation.

```python
CodecContext(*, surface: Literal['client', 'server'],
             direction: Literal['request', 'response'],
             schema_id: str | None, operation_id: str | None = None,
             media_type: str | None = None)

ModelCodec[T].decode(wire: WireValue, context: CodecContext) -> DecodedValue[T]
ModelCodec[T].encode(value: T | ModelValue[T] | ModelInput[T],
                     context: CodecContext) -> WireValue
ModelCodec[T].from_wire(wire: WireValue, context: CodecContext) -> DecodedValue[T]
ModelCodec[T].snapshot(value: T, context: CodecContext,
                       *, presence: PresenceTree | None = None) -> ModelValue[T]

DecodedValue[T] = ModelValue[T] | ModelInput[T]

OutboundCodec[T].from_wire(value: JSONValue | WireValue) -> DecodedValue[T]
OutboundCodec[T].snapshot(value: T, *, presence: PresenceTree | None = None) -> ModelValue[T]
NativeOutboundCodec[T].from_wire(value: JSONValue | WireValue) -> ModelValue[T]
EnvelopeOutboundCodec[T].from_wire(value: JSONValue | WireValue) -> DecodedValue[T]
```

`ModelCodec` is the protocol used by the common implementation and adapters. `decode` is the receiving entry point (client responses / server codec-adapter requests) and rejects fields prohibited in that direction. `from_wire` is the sending entry point (client requests / server codec-adapter or explicit-wrapper responses); it copies its input and applies exclusions for the sending direction before schema/native validation. They share the validation core in §5 but have different directional policies. A context argument inconsistent with the use raises `CodecBindingError`. Neither fills schema defaults or falls back to an envelope for invalid values. Do not unconditionally feed values constructed by native FastAPI back into this decode.

CodecContext is a frozen record. operation_id is the root use-site's canonical RFC6901 pointer (for example, `/paths/~1pets/patch`), not the OAS optional operationId name; do not mix in an external PathItem's declaration URI or session integers. Use None only for startup schema-conformance checks that are not bound to an operation. For bodies, parts, and content-based parameters/headers, media_type is the selected actual media in canonical form, with lowercase type/subtype and declared parameters retained. It is None for schema/style-based parameters and schema-based response headers. Do not fill it with an empty string or fictitious application/json. schema_id must match the stable ID of the bundle's SchemaView. Only callbacks for media without a schema may use None; model/schema callbacks always require str.

Users do not assemble `CodecContext` or `ModelCodec` manually. Generated packages expose the following **frozen facade instances** and immutable `OutboundCodec` objects containing their bindings/contexts. `NativeOutboundCodec` / `EnvelopeOutboundCodec` are its public subclasses; one is returned according to generation-time projection_mode. `T` is invariant because it is used for both input and output. Both subclasses have the same `snapshot` signature shown above.

| Public instance | Access methods |
|---|---|
| Client `pkg.types.<resource>.<PascalMethod>RequestCodecs` | `body` (the declared Literal / corresponding RequestMedia / existing dynamic str / default-omission overloads below), `parameter(*, location: Literal['path','query','querystring','header','cookie'], name: str)`, `part(*, name: str, media_type: str \| None = None)` |
| Server `pkg.responses.<PascalOperation>ResponseCodecs` | `body(*, status_code: int, media_type: str \| None = None)`, `part(*, status_code: int, name: str, media_type: str \| None = None)` |

Each method generates Literal overloads for actual uses, returning `NativeOutboundCodec[T]` or `EnvelopeOutboundCodec[T]`. If the factory's str selector is not statically determined, return a **union of the applicable codec types**. Do not use `OutboundCodec[T1 | T2]` as a common supertype of individual invariant codecs. Client body/part factories use the same media selection table as ordinary requests and can be generated for multiple media without a default. In that case, media_type is required in each overload, and omitting it at runtime raises `CodecSelectionError`. The server resolves status in exact → range → default order; omitted media uses that response branch's ordinary default. Put exact Literal overloads first; the int overload for dynamic status returns a union containing every codec reachable through exact/range/default resolution. Mismatched selectors, absent bodies, whole binary / schema-less media that do not use model codecs, and file parts raise `CodecSelectionError`. For parts, named properties take priority; unknown names bind to an existing additionalProperties schema/part plan only if it has a non-file codec. Return unions for dynamic names also include the applicable additional schema's codec. Untyped additionalProperties=true is a media surface using WireValue/freeze_wire and does not create a model codec. Do not turn additionalProperties=false, additional file parts, or a schema without a type binding into successful codecs: the first two raise CodecSelectionError; missing bindings use the existing generation diagnostic. Do not add ambiguous all-use lookup by `SchemaRef`. Pascal-case naming and collision diagnostics follow each target's naming rules. Preserving this factory's codec union is distinct from the str catchall prohibited by CLIENT/TYPING because it loses media/body correlation in sending methods.

The same client RequestCodecs facade also provides `select_request_media(*, declared_media: Literal[m], concrete_media: str) -> RequestMedia[S_m, A_m]` and `select_response_media(*, declared_media: Literal[m], concrete_media: str) -> ResponseMedia[R_m]`. Here m denotes an actual media declaration, S_m/A_m its synchronous/asynchronous body surfaces, and R_m the union of reachable success values defined below. These are explanatory variables: actual artifacts generate declaration-specific overloads with every variable replaced by concrete Literals/types. Do not expose a str fallback for unknown declarations or a catchall with free type variables. Provide the same selectors for finite media declarations; use this factory to select a concrete value for a wildcard. Do not generate select_request_media if there are zero request-body media, or select_response_media if there are zero success-body media. With only one signature, use an ordinary typed method, not a lone @overload. Retain the existing body/part factories' dynamic str → codec union and selection errors.

Public `RequestMedia[SyncOutT, AsyncOutT]` is invariant on both axes; `ResponseMedia[R]` is also invariant. Both are frozen/slots types constructible only through factories. Their only public readonly fields are `declared_media: str` and `concrete_media: str`. Retain the root operation, top-level media/Accept plan, direction, and fingerprint as private binding identity; do not create fictitious TypeUseIds for schema-less media. User constructors must not allow arbitrary type or owner declarations; these values contain no secrets. Normalize concrete values using the existing media rules and verify both a declaration match and the existence of a media plan. Bind only to the top-level request body/Accept. Reject use with a different operation/use/direction or an old fingerprint with CodecSelectionError before provider/HTTP I/O.

This section is authoritative for the correspondence between selectors, types, and media; CLIENT/TYPING refer to its result. Determine the winning media through the existing most-specific dispatch plan in CLIENT §5, without a separate selector-specific evaluator. The request factory requires the winning declaration key for concrete_media to equal declared_media. For example, given `application/*: B` and `application/json: A`, a selector declaring the former with concrete_media='application/json' raises CodecSelectionError with zero I/O. Response R_m is the union of every winning type reachable from all statuses classified as success by the existing status table, for concrete media within declaration m's range. Retain types reachable through more specific media declarations and status fallbacks, as well as None for successes without bodies; do not force receive dispatch to one declaration key. Document that the static union may be broader than the runtime concrete string warrants, and do not disguise it as a narrower type through free T or cast. This connects the existing [request content precedence](https://spec.openapis.org/oas/v3.1.1.html#request-body-object) and [response content precedence](https://spec.openapis.org/oas/v3.1.1.html#response-object) to types; it does not send extra HTTP requests or decode bodies twice.

When the corresponding RequestMedia is passed to body(media_type=...), only branches with a model codec return the same NativeOutboundCodec/EnvelopeOutboundCodec as their Literal. Media selectors can be generated for binary/schema-less media, but must not invent model codecs for them. Parts are different uses and do not accept RequestMedia; they return codec unions through the existing Literal/str selectors. Ordinary client sending uses fixed overloads for each declaration to connect the selector's synchronous/asynchronous axes to body types. Do not combine a selector with body omission through UNSET. Creating a selector does not convert the body; validation and encode/decode remain delegated to the existing ModelCodec/media codec. These client selectors do not change server ResponseCodecs/status selection.

The bound factory's `from_wire` / `snapshot` are synchronous CPU operations without I/O and raise common errors such as `WireValidationError`, `NativeValidationError`, and `CodecResourceLimitError`. Map them to the public errors in §5 / §11 at generated method / codec route-adapter boundaries. A native factory's from_wire always returns `ModelValue`; an envelope factory returns `ModelValue | ModelInput` depending on the presence of enumerated structural differences. Runtime validation failures must not change whether an accessor is native or envelope. Factories exposed for native FastAPI routes have the same strict contract and must not be replaced with weaker framework-only factories.

For example, construct input to CreatePet, whose id is required+readOnly, with `CreatePetRequestCodecs.body().from_wire({'name': 'A'})` and pass the result directly to `client.pets.create(body=...)`. For GetPet, which excludes a required+writeOnly password from its response, return `GetPetResponseCodecs.body(status_code=200).from_wire({'id': 1})` from the handler. Neither requires injecting a fictitious id/password into T. In both cases, an already valid complete T is also accepted directly through the OutboundType in §4.

`WireValue` is an immutable snapshot of the JSON domain: null/bool/string/integer/finite number, ordered objects, and arrays. Internal finite decimals are JSON numbers, not converted to strings. It excludes binary values, files, and HTTP responses. `PresenceTree` is an immutable tree following wire object keys / array indices, retaining the RFC 6901 pointer of every present node and container order. A present null differs from an absent key. A null root is still present. Omission/no-content of the HTTP body itself is represented by operation-level UNSET, separately from JSON null. A no-content binding does not call the model codec.

Include `WireValue` among the public types in `pkg.model_codecs`. For a legal use whose source has content but no schema at all, the media surface is fixed as WireValue for JSON/+json, str for text, and bytes for binary. Treat schema absence and final binding failure as separate facts; the latter must not fall back to untyped values. Uses with a schema use ordinary final type bindings.

The public entry point for constructing immutable WireValue is `freeze_wire(value: JSONValue | WireValue) -> WireValue` in the same module; obtain a mutable independent copy through `thaw_wire(value: WireValue) -> JSONValue`. `presence_of(value: JSONValue | WireValue) -> PresenceTree` performs the same domain/cycle checks and copying, constructing presence from actual keys/indices without schema validation. JSONValue recursively comprises null/bool/string/int/finite float/finite Decimal, list/tuple, and string-key dict. freeze copies while retaining order and rejects cycles, non-string keys, non-finite values, and arbitrary objects. Changes to thaw's result do not affect the original snapshot. Do not implicitly stringify arbitrary objects or construct extra models. Recursive runtime aliases for JSONValue/WireValue use the TypeAliasType definitions in TYPING §2, without changing the domain, copy, or validation semantics above.

| Type | Required fields and meaning |
|---|---|
| `ModelValue[T]` | `kind='model'`, `value:T`, `binding_id`, `wire`, `presence`, `extras`. `value=None` is a valid value when T is nullable. `require_model()` returns `value` |
| `ModelInput[T]` | `kind='input'`, `binding_id`, `wire`, `presence`, `extras`, `issues: tuple[ProjectionIssue,...]`. Contains neither a fictitious `value:T` nor `value=None`. `require_model()` raises `ModelProjectionError` |
| `ProjectionIssue` | `code`, wire `pointer`, `schema_location`, `field_id`, explanation. Do not embed values or credentials in diagnostic text |
| `extras` | Pointer → snapshot mapping for schema-permitted unknown properties not stored in the native model. This is not a route around explicit `extra=forbid` |

Copy and freeze snapshot `wire/presence/extras` at entry. Envelope encode validates this wire snapshot against the new direction's rules before sending it. Later mutation of the enclosed model does not implicitly update the snapshot. To send changes, call the bound codec's `snapshot(new_value, presence=...)` or `from_wire(new_wire)`. `presence=None` uses the plain-T policy in §5. An explicit PresenceTree takes priority over that policy and passes present None to schema validation without omission. For example, explicit None in a dataclass can be checked with `snapshot(value, presence=presence_of({'name': 'A', 'tag': None}))`, which fails if tag is nonnullable. The mask only selects nodes readable from actual native values; it does not create nonexistent fields, UNSET values, or values excluded by a serializer. Mismatched pointers, container kinds, or array-index sequences raise `CodecBindingError`. Do not automatically repair stale presence whose array order or length differs.

A `binding_id` mismatch raises `CodecBindingError`. Reuse between request/response uses sharing the same schema identity and final binding is allowed, but direction is validated every time. `ModelInput` is not an automatic fallback to a weaker type.

Each package's private runtime contains one `UNSET/Unset` instance for HTTP omission. The client re-exports it from `pkg.options`; the server re-exports it from `pkg.responses` and the root. `pkg.model_codecs` also re-exports the same object so adapters can return omission from decode_parameter. Do not create another singleton, add sentinel fields to model-codec value records, or confuse it with native `msgspec.UNSET` / Pydantic MISSING.

## 4. Static selection of native values and envelopes

Finalize `projection_mode='native'|'envelope'` for each type use at generation time. The receiving `InboundType` (client responses / server codec-adapter handler arguments) is `T` for native uses and `DecodedValue[T]` for envelope uses. The sending `OutboundType` (client arguments / server codec-adapter or explicit-wrapper handler return values) is fixed as `T | ModelValue[T]` for native uses and `T | DecodedValue[T]` for envelope uses. Typed parameters / non-file parts in the client and server codec adapters use the same directional table; media surfaces such as binary retain separate contracts. A method must not return an undeclared `dict` or envelope in response to arbitrary validation failures.

The native in projection_mode and `NativeOutboundCodec` means **whether the wire value can be represented as T**; it is separate from the choice to delegate processing to FastAPI. Without changing the type/factory contracts above, §11 / the FastAPI decisions own the existing T annotations for server native bodies / primary responses and the handling of bare primary T return values. Native parameters pass handlers the `SurfaceType` determined by the structural rules in that document's §5.1. For example, even if a purely structural primitive `RootModel[int]` remains in the model artifact, the parameter surface may be `int`, without changing the existing model, the binding's T, or the bound factory's T. Do not flatten body/response T using this parameter rule. Even on native routes, use the strict codec's snapshot/presence for explicit envelopes rather than unwrapping `.value` into the framework.

Known structural conditions requiring envelope mode are: (a) a field excluded by direction is required in T, which must remain unchanged; (b) a wire value cannot be supplied to an existing `init=False` / non-init field; or (c) explicit model projection drops schema fields / shapes so the retained T alone cannot represent that use's input. Conservatively fix conditional structural differences to envelope mode as well: return `ModelValue` if the wire satisfies all native conditions, otherwise `ModelInput` with reasons. The ability to construct a runtime dict does not make a TypedDict missing `Required` keys a valid T.

For example, if the schema includes `id: {type: integer, readOnly: true}` in required and the existing model also requires `id: int`, request `{"name":"A"}` is valid but T's constructor fails. Put this request use in envelope mode without injecting 0 / None / UNSET into id. The same applies when excluding a required writeOnly password from a response. This limitation follows from preserving the model; it is not lack of backend support.

Do not convert unknown Enum/Literal values, native constraint/validator rejection, default-factory / `__post_init__` exceptions, or invalid schema values to `ModelInput`. An unexpected projection failure on a native use is also an exception; do not automatically add an envelope. Create `ModelInput` only for structural differences enumerated in the binding and recognized in advance.

## 5. ModelCodec decode / encode order

The validation order, presence, converter, and scalar/schema rules in this section through §9 are the ModelCodec contract. Ordinary FastAPI-native defaults/coercion/validation/serialization follow the framework path; do not claim that they execute this section's procedure. Do not replace native validators/serializers/regex engines with the common codec implementation. Record supported scope and known differences in the target's static selection and capability information.

decode proceeds in this order: **media/parameter lexical parsing → record original wire presence → directional wire schema validation → alias/key mapping → selected native converter/constructor → native validation → snapshot**. Do not populate required fields from backend defaults before validating them. Schema defaults are annotations; this layer does not insert values into the wire. Native constructor default/default_factory behavior remains unchanged, but does not add wire presence.

For plain T encode, read initialized fields and official presence, then apply **explicit PresenceTree → backend public presence → limited policy when presence is unavailable**, in that order. Pydantic BaseModel omits optional fields absent from `model_fields_set`, regardless of nullability/default values. TypedDict uses actual keys; msgspec uses actual UNSET. Validate only present None as null and reject it when nonnullable. When actual presence marks a required field absent, a default must not make encoding succeed: it is an encoding error except for directional projection exclusions. Then map Python/native keys to wire names, apply media conversion and direction rules, and validate the wire schema. Do not use blanket value-only `exclude_defaults/none` or equality comparisons with defaults. Do not restore values excluded by Pydantic's explicit `Field(exclude=True)` or a registered serializer. If that leaves a required field absent, raise an encoding error. Do not forcibly disable a model's secret-value exclusions.

Omission of fallback None is allowed only when the wire property is **optional and nonnullable** in that direction and binding provenance proves that the final model field's default=None / nullable type **comes from D's standard optional fallback**. Schema default:null, explicit model default / nullable settings, default_factory, and custom/opaque types do not establish this provenance. The authoritative fact is `ModelFieldFacts.none_default_provenance: NoneDefaultProvenance` in BINDING §7.2. Require all three conditions: `emitted_default=none`, `origin=synthesized_optional_fallback`, and `annotation_null_origin=optional_fallback`. Do not reconstruct them from type strings or `value == default`. Use only the output of the ordinarily adopted render and the model-owned freeze result that reads existing data attributes; do not evaluate additional getters, render again, or mutate fields.

| Plain T presence capability | Behavior when the relevant fallback field is None |
|---|---|
| Pydantic BaseModel | Apply public `model_fields_set` to every optional field before this fallback decision. Omit absent fields regardless of nullability/default. Validate included None as null. Check nested objects against each original object; do not infer fields-set information lost in model_dump |
| TypedDict | If the actual key exists, retain and validate null. Omit only keys that do not exist. Do not omit None present in a dict because its type is optional |
| Pydantic dataclass / stdlib dataclass, and builtin native objects without a public presence API | Omit only None with the provenance established above. Whether None was explicitly passed to the constructor is indistinguishable; this limited case produces the same omission. Explicit presence / from_wire does not use this omission rule |
| Ordinary optional nonnullable msgspec field | Omit the `msgspec.UNSET` emitted by D. None is not evidence of ordinary fallback and is a native/wire error unless nullability allows it. Other explicit settings also do not permit None omission without the provenance conditions above |

None in a required nonnullable field is an error. For nullable fields in both dataclass backends without presence, default=None initialized through omission cannot be distinguished from explicit None; plain T sends either as null. Apply the same indistinguishability rule to msgspec fields initialized with None instead of UNSET. Do not omit nullable None through default equality. Encode other initial values as initialized only when public presence is unavailable. To preserve omission, use the bound factory's from_wire or snapshot(value, presence=presence_of(...)). Generated README/reference documentation must explain this difference for each backend and include factory examples, explicitly stating that in JSON Merge Patch omission preserves a value while null deletes it. For example, instead of sending `PetPatch(name='B')` directly with either dataclass backend, `UpdatePetRequestCodecs.body().from_wire({'name':'B'})` leaves tag absent, while `{'name':'B','tag':None}` explicitly deletes it. Plain Pydantic BaseModel values retain the same distinction through official presence. [RFC 7396 §2](https://www.rfc-editor.org/rfc/rfc7396#section-2).

Envelope encode uses the snapshot's wire, retaining explicit null, explicitly supplied values equal to defaults, and nested extras. Before sending in another direction, apply directional projection and serializer exclusions explicitly recorded in the binding, then validate required/constraints. Envelopes must not bypass explicit exclusions. Snapshots are not raw responses preserving JSON whitespace, original number spelling, or duplicate object keys. Use the explicit raw API when original bytes are required.

Client request encode failures are `RequestEncodingError` before sending. Client response JSON syntax failures are `DecodeError(ResponseDecodeError)`; schema/native/Enum/serializer conformance failures are `ResponseValidationError(ResponseDecodeError)`. Neither path retries, tries alternative unions, or falls back to nullable. The runtime decision sets the default retained response-info/body limit to 64 KiB and the total buffered-response limit to 16 MiB. The entry point for inspecting unknown values is `with_raw_response`; do not create an additional ResponseEnvelope API.

## 6. Backend implementation contracts

`ConverterStrategy` has six Literal values: `pydantic_type_adapter / dataclass_structural / typeddict_structural / msgspec_convert / msgspec_structural / registered_adapter`. Select the conversion plan for the entire final use through the following table. Recursive leaf/container conversion must not introduce fallbacks inconsistent with this declaration.

| Condition, in priority order | converter_strategy |
|---|---|
| Explicit model adapter selected | `registered_adapter` |
| Pydantic v2 BaseModel / dataclass backend | `pydantic_type_adapter` |
| stdlib dataclass backend | `dataclass_structural` |
| TypedDict backend | `typeddict_structural` |
| Final msgspec type graph contains a union unsupported by convert, or pattern-bearing Meta | `msgspec_structural` |
| Other msgspec | `msgspec_convert` |

Store this value in ENTRY's `bindings[].converter_strategy`. Existing `bindings[].strategy` is adapter when a model adapter is selected; otherwise it is projection_mode (native/envelope). A parameter/media/schema adapter alone does not make it adapter. Do not invent a native converter for media without a type binding; record it only in the media plan. There must be zero strategy changes in response to runtime TypeError or similar failures.

### Pydantic v2 BaseModel

Construct `TypeAdapter(T)` once for each final T and cache its schema/namespace. Check official `model_fields` information against the binding. The general whole-JSON path uses `validate_json`; paths passing schema-selected nested models or preconverted Python values use `validate_python`. Strict date validation differs between JSON and Python, so do not indiscriminately pass unconverted RFC3339 strings to `validate_python(strict=True)`. Use `strict=None` to respect existing strict types / ConfigDict / field validators; coercion must not accept type mismatches already rejected on the wire side.

Read typed values through `model_dump(mode='python', by_alias=False, exclude_unset=False, exclude_defaults=False, exclude_none=False)` and final field mappings, applying masks from model_fields_set read on each original object or from an explicit PresenceTree. These dump options are a read mechanism for checking values selected by an explicit mask against native serializer exclusions, not a policy of discarding presence. Pass Pydantic Python values through schema media converters rather than calling them JSON as-is. A custom serializer that changes shape follows the adapter contract in §12. Unwrap the root of `RootModel` to its value; do not add `{"root": ...}` to the wire. Recognize Pydantic `MISSING` emitted by D itself under explicit settings as omission, without adding a new sentinel to models.

### Pydantic v2 dataclass

Use `TypeAdapter(T)` under the same policy. Do not assume BaseModel APIs exist; use final facts and `dataclasses.fields` for field/default/init information. Build alias / validation_alias input paths from emitted Field facts, without relying on private `__pydantic_*` layouts. Preserve constructors / native validators; do not turn the type into a different model through config overrides. Because model_fields_set is unavailable, presence must always come from the wire snapshot. When a root/scalar/union is a type alias, use TypeAdapter for its actual type without creating a dataclass wrapper.

### stdlib dataclass

After wire schema type/constraint validation and recursive conversion of final annotations, call the final T's ordinary constructor with keyword arguments. Use `dataclasses.fields` to check inherited fields / kw_only / default_factory / init. Do not pass omitted fields to the constructor; the constructor calls each factory exactly once. Do not remove `frozen/slots`. Run `__post_init__` normally when present and treat failures as errors.

Do not use `dataclasses.asdict` as a generic wire encoder: it deep-copies and recursively expands values without understanding aliases/presence. Use `getattr` and the codec for each final field. Do not force-set non-constructor fields. Compensate for generated annotations' lack of runtime validation through the common wire validator / final type converter.

### TypedDict

Use actual final TypedDict keys from the binding. Do not arbitrarily substitute Python-identifier-normalized field names as keys. Support both ordinary class syntax and functional `TypedDict(...)`, checking `Required/NotRequired/ReadOnly/closed/extra_items` and inheritance against final facts. `ReadOnly[T]` describes static mutability and does not substitute for OpenAPI readOnly.

Validate the wire schema / final value types and construct a dict without filling defaults. Preserve missing keys as missing. Pass known-field values through nested model / enum / primitive converters. Do not use the TypedDict constructor or `isinstance(value, T)` as validation. Validate permitted extra_items against both final types and the schema.

### msgspec Struct

Check the binding against `name/encode_name/type/default/default_factory/required` from `msgspec.structs.fields(T)`. For natively representable types, use `msgspec.convert(..., type=T, strict=True)` to validate aliases/tags/Meta/unknown-field policy. However, msgspec does not accept unions such as multiple untagged Structs. In those cases, select a **structural converter** at generation time: choose the branch through the wire schema, apply `msgspec.convert` / `Meta` constraints to each leaf, recursively construct containers, and call the official `T(**kwargs)`. Do not feed the entire unsupported union back into convert. Let the ordinary constructor execute `__post_init__`; failures are errors.

The structural converter also checks final `Meta` gt/ge/lt/le/multiple_of/pattern/min_length/max_length/tz and the Struct's unknown-field policy. Select this strategy at generation time for branches containing patterns as well; validate Meta patterns with the common matcher in §9 before calling the ordinary constructor. Do not feed values back into pattern-bearing annotations that invoke Python's backtracking matcher. Do not remove explicit model constraints absent from the schema. Record the generation-time converter strategy in the manifest. Catching runtime TypeError and switching to an unvalidated constructor is prohibited.

Encode through per-field reads and wire mappings. Do not call `to_builtins` on the whole value: `omit_defaults` loses the distinction between explicit and default values, while `array_like` turns wire objects into arrays. `UNSET` means omission; None means null. Even when D treats a tag field as ClassVar and it disappears from field enumeration, associate the final tag/field binding with the schema constant. OpenAPI determines wire shape; do not change msgspec's standalone serializer API. Use official leaf `to_builtins` only when it matches the schema's byte/decimal/date representation.

## 7. Aliases, omission, defaults, and unknown fields

The source property / parameter name is authoritative for the wire name; final field identity is authoritative for the native attribute/key. Retain D's snake-case conversion, reserved words, alias generator, AliasChoices, and serialization_alias in these two coordinate systems. Do not overwrite input/output wire names with native serializer aliases. The binding places values under accepted Pydantic validation keys. If multiple wire properties compete for the same native slot, emit generation-time `MC_ALIAS_COLLISION`; do not hide it with runtime first-wins/last-wins behavior.

| Input | Common decision |
|---|---|
| Optional key absent | Do not add it to presence. Native defaults are allowed. Do not send it when re-encoding the snapshot |
| Optional key explicitly null | Allow only when nullable. Include it in presence and preserve null on re-encode |
| Required key absent but a default exists | Wire validation failure. Only directional projection exclusions from required are exceptions |
| Value equal to the default explicitly supplied | Present. Omission equivalent to `exclude_defaults` is prohibited |
| Default initialized in an optional field of a plain model | If official presence says absent, omit regardless of nullability/default. Only backends without presence use §5's limited fallback-None and initialized-value policy |
| Exact `msgspec.UNSET` / Pydantic MISSING emitted by D | Treat as absent. If required, wire validation failure |

First evaluate unknown properties against schema additionalProperties/patternProperties/unevaluatedProperties. If prohibited, reject on every backend. Even if the schema permits them, an explicit native constraint such as Pydantic `extra='forbid'`, msgspec `forbid_unknown_fields=True`, or TypedDict closed causes a native validation error; do not discard extras first to make validation succeed. If native behavior ignores them or a dataclass has no storage slot, project known fields into the native value and retain the original information in snapshot/extras. Do not claim that users receiving only ordinary `T` gain unknown attributes; use envelope snapshots or explicit raw responses when complete wire information is needed.

## 8. readOnly / writeOnly, enums, unions, and roots/containers

Direction control is an explicit policy of the new targets. ModelCodec excludes readOnly from outbound client requests and writeOnly from outbound server responses. It strictly rejects readOnly in inbound server requests and writeOnly in inbound client responses. The corresponding fields are not required in those directions. A field with both readOnly and writeOnly true causes a generation diagnostic. This policy gives concrete behavior to OpenAPI annotations; do not claim that OAS 3.1 annotations alone always mandate rejection. A known inability of native server handling to preserve these directional semantics is a reason to select a codec adapter at generation time.

Build normalized request/response schema views separately from the model graph, applying the same rules to fields/required across `allOf`, references, and nested objects. Retain evaluation information for the applicable branches of conditional annotations and apply direction rules to those branches. A custom dialect whose directional information cannot be planned uniquely requires a custom schema adapter through `MC_SCHEMA_DIALECT`; do not proceed by indiscriminately removing required constraints.

Encode Enum values using final enum-class member values; decode by constructing the corresponding official member. Match `Literal` values including their types; do not equate bool and int. Do not reduce unknown enums/discriminators to None, a known default, or str, and do not add enum members. Only explicit raw responses may return invalid/future values without validation.

`oneOf` requires exactly one matching wire-schema branch; multiple matches or no matches fail. `anyOf` requires at least one wire-schema match; native projection follows final emitted union order and explicit union policy. When the common converter selects a branch, use the first final branch corresponding to a matching schema; the SDK must not try another branch after that branch fails. For a whole-union TypeAdapter, preserve branch selection inside native union policy and prohibit SDK fallback after the final TypeAdapter fails. Even when native code selects the branch, verify that the result has not changed into a shape outside the matching set. A discriminator does not authorize skipping schema validation; check declared string mappings against matching branches.

`allOf` is an intersection of wire constraints, not an instruction for the client to generate new inheritance or a merged model. Roots also support scalar/null/array/map/union shapes. Distinguish existing RootModel, assignment aliases, TypeAliasType, and Python 3.12 type statements in the final type graph. Do not assume aliases are callable classes. Resolve recursive references through a registry of stable schema/symbol IDs and deferred binding; do not sever cycles through inline expansion.

Construct list/tuple/set/frozenset/Sequence/Mapping according to final container and item/key types. Preserve wire-array order in list/tuple. Explicit model settings selecting set types produce native projections that lose duplicates/order; retain the original array in the snapshot. Make plain set encoding deterministic by sorting items by the byte order of their JSON representations; snapshots preserve original order. JSON object keys are normally strings. If the final model requires int/Enum or other keys, use a declared reversible key converter. If distinct wire keys collapse to the same native key, raise `ModelProjectionError`. Do not use undeclared `str(key)` conversion.

## 9. Schemas, constraints, and scalar representations

ModelCodec uses `jsonschema.Draft202012Validator` and an offline `referencing.Registry` as its common wire oracle. Normalize OpenAPI 3.1/3.2 dialects/resources and 3.0 nullable, exclusive bounds, and supported annotations into a separate 2020-12 schema sidecar. Do not substitute model_json_schema / native serializer output for the raw wire contract. Bundle external `$ref` resources fetched and digest-pinned at generation time; runtime validation must not initiate network retrieval. Unknown custom dialects / required vocabularies cause generation errors unless a plugin is available. Pass local dict/list trees to the validator; do not expect it to recognize immutable snapshot tuples/mappings as JSON Schema arrays/objects. Finite Decimal number/integer/multipleOf checks and the pattern checks below are shared TypeChecker/keyword extensions; bool is not a number.

Validate required, null, type, const/enum, numeric bounds/multipleOf, length/items/properties, uniqueItems, pattern, dependent/conditional/composition, and additional/unevaluated properties on the wire side. Additionally validate constraints added to final models through native or structural converters. If explicit user model settings are narrower than the raw schema, raise an error even for schema-permitted values; do not remove model constraints. Conversely, wire-schema constraints remain in force when the model is more permissive.

Enable FormatChecker for known formats. The initial registry contains date, time, date-time, duration, uuid, ipv4, ipv6, email, idn-email, hostname, idn-hostname, uri, uri-reference, iri, iri-reference, uri-template, json-pointer, relative-json-pointer, and regex, using the selected jsonschema version's public FormatChecker. Missing dependencies required by standard checkers cause initialization errors, not silent success. The shared converter additionally checks source-declared byte/base64, int32/int64 ranges, and date-time-local/time-local. The media layer owns binary; password is a display annotation and a subject for secret-type conversion. Preserve unknown formats as JSON Schema annotations and do not reject their use as strings. Converting an unknown format to a nonstandard native type requires an explicit scalar adapter. The email wire checker checks syntax only, without DNS/deliverability checks. Additional native normalization such as Pydantic EmailStr remains part of the model's ordinary contract.

The common pattern engine uses `google-re2`'s public `Options` / `compile` / `search`. Do not create a fallback to Python `re`. Centralize `pattern`, `patternProperties`, and evaluated-key calculation for additional/unevaluated properties in the same matcher, leaving no jsonschema internal Python re path. Replace `format:regex` with syntax validation against this grammar as well. RE2's linear-time guarantee is based on the [pinned release source](https://github.com/google/re2/blob/927f5d53caf8111721e734cf24724686bb745f55/README.md); public options/search are based on the [Python wrapper:35–74,218–225](https://github.com/google/re2/blob/927f5d53caf8111721e734cf24724686bb745f55/python/re2.py#L35).

The builtin grammar accepts Unicode literals, literal escapes, `[abc]` / ranges / negated classes, concatenation, `|`, ordinary or non-capturing groups, `* + ? {n} {n,} {n,m}`, and their lazy forms. RE2 safely handles nested quantifiers themselves; do not pass `^(a+)+$` to Python re. Wire `\d/\D/\w/\W` denote ASCII sets; `\n/\r/\t/\f/\v` and `\xHH/\uHHHH` denote the corresponding literals. The compiler maps `.` to a set excluding LF/CR/U+2028/U+2029. Accept `^` / `$` only at the ends of the entire pattern or top-level branches, mapping them to the absolute start/end under the ECMA Unicode mode below. `a$` does not match `a\n`. Do not rewrite native source. Lookaround, backreferences, named groups, flags, Unicode property escapes, lone surrogates, and other engine-specific escapes require an explicit schema adapter through `MC_PATTERN_DIALECT`. Do not perform Unicode normalization.

Wire `\s` is the explicit ECMA WhiteSpace and LineTerminator set `U+0009–000D, U+0020, U+00A0, U+1680, U+2000–200A, U+2028–2029, U+202F, U+205F, U+3000, U+FEFF`; `\S` is its complement. Do not use RE2's ASCII `\s` unchanged. Apply set operations in the AST inside and outside classes and map the result to the corresponding RE2 class. Outside classes, `\b/\B` use RE2's ASCII assertions as word/non-word boundaries for `[A-Za-z0-9_]`. On empty input, `\b` is false and `\B` is true. Inside classes, `\b` is U+0008 and `\B` is a syntax error. Wire character units are Unicode code points; fix the ECMAScript oracle to Unicode mode (u=True, i/m/s=False). Do not accept arbitrary flags. A scalar outside the BMP therefore counts as one character for `.`, not two UTF-16 code units. Combine valid surrogate pairs in Unicode escapes into one scalar; reject lone surrogates. This subset follows [ECMA CharacterClassEscape / ClassEscape](https://tc39.es/ecma262/2026/multipage/text-processing.html#sec-characterclassescape), [CompileAssertion](https://tc39.es/ecma262/2026/multipage/text-processing.html#sec-compileassertion), and [WhiteSpace](https://tc39.es/ecma262/2026/multipage/ecmascript-language-lexical-grammar.html#sec-white-space). An escape with the same name in RE2 is not by itself evidence of identical semantics.

The matcher plan retains wire `ecma262` and native Meta `python` as separate dialects. The ASCII-class/dot/end rules above apply to the wire. For the Python dialect of msgspec Meta, the same RE2 compiler preserves semantics by mapping `\d` to Unicode Nd, `\w` to Unicode L/N plus underscore, `.` to everything except LF, and `$` to the end or immediately before a final LF. Python `\s` is `U+0009–000D, U+001C–001F, U+0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028–2029, U+202F, U+205F, U+3000`; `\S` is its complement. Preserve differences from ECMA such as U+FEFF and U+0085. Python Unicode word boundaries `\b/\B` are not equivalent to RE2 ASCII assertions, so they require an explicit model adapter outside classes. Inside classes, `\b` is U+0008 and `\B` is a syntax error. The adapter's Python range/conformance must also distinguish Python 3.14's change to `\B` on empty input. Do not assume the original pattern has ECMAScript semantics. Python-specific flags/lookaround and other syntax outside the grammar also require an explicit model adapter. The codec must not replace the Rust/Python engine configuration of Pydantic's official native validator. These rules are based on the [official Python re specification](https://docs.python.org/3/library/re.html) and [RE2 syntax](https://github.com/google/re2/wiki/Syntax). <!-- codespell:ignore nd -->

Resource limits are: pattern source 4 KiB UTF-8, group depth 32, finite repeat bound 1000, compiled program size 4096, `Options.max_mem=1 MiB`, `never_capture=True`, and `log_errors=False`. The compiled-pattern cache holds at most 128 entries; the registry retains only source/plans. Each subject is limited to 1 MiB, and the cumulative subject bytes passed to matchers in one codec call are limited to 32 MiB; exceedance raises `CodecResourceLimitError`. Source/depth/repeat limit exceedance checked at generation time is `MC_PATTERN_RESOURCE_LIMIT`. Actual compile/program/memory limits cause runtime-startup CodecConfigurationError as described in §1; the generator must not additionally install missing RE2. Limits must not be turned into schema success. Arbitrary Pydantic custom validators, custom dataclass `__post_init__`, and explicitly selected Python regex-engine execution are user code; the common matcher's safety does not guarantee a hard CPU deadline for all native validation. An explicit Python regex engine requires an adapter capability declaration. Check ECMA boundaries and RE2 limits with an independent corpus.

Distinguish JSON numbers from bool and reject NaN/Infinity. Preserve Python integer precision; treat decimals as JSON numbers without stringification. Normalize numeric lexemes from the media parser and schema numbers to finite Decimal for multipleOf and related calculations, so floating-point error does not reject 0.3/0.1. Reject overflow/non-finite values when projecting to an explicit final float. Snapshots use exact wire numbers; plain floats use Python round-trip representations. Duplicate JSON object keys cause decode errors rather than silently choosing one value.

Preserve source formats for date/time/date-time. date-time requires an RFC3339 timezone; local formats allow no timezone. After schema validation, convert to datetime through public ISO parsers / Pydantic JSON validation / msgspec converters, without adding a timezone arbitrarily or converting to local time. UUID/IP/network/Path use their declared official constructors and string representations; Enum uses member values. Decimal becomes a string only when explicitly mapped to a string schema; bytes use base64 only under a byte/base64 declaration. Pass format-binary files to the media layer. Do not treat arbitrary objects' `str()` or `__dict__` as JSON serializers.

Include Pydantic SecretStr emitted by the pinned D for password, or explicitly selected SecretBytes, in dedicated leaf converters. For permitted outbound fields, use official `get_secret_value()` to obtain the wire value; do not send the masked display `**********` as a password. Apply writeOnly/Field exclusions first, and never use extracted values in logs/repr/diagnostics. Record representations equivalent to `round_trip=True` required by explicit native wrapper types such as Json[T] in type bindings. Do not confuse native display serialization with API wire representation by indiscriminately using model_dump_json. The basis is the public accessor/round-trip APIs in [Pydantic Types](https://docs.pydantic.dev/latest/api/types/).

## 10. Parameter / form / media boundaries

Fix the common wire-parameter entry points as `encode_parameters(ParameterPlan, values, context)` / `decode_parameters(ParameterPlan, RawParameters, context) -> WireValues`. Preserve the input's OAS 3.0/3.1/3.2 version; do not silently apply 3.2-only syntax to older versions. `RawParameters` is a multimap retaining raw path fragments, the whole query's raw bytes, and query/header/cookie order and duplicates. Do not treat queries already converted to dict by a native framework as authoritative. After parameter schema/default/required processing, pass each typed value to this document's model codec.

These entry points and this section's lexical, duplicate, empty-value, default, and media-conversion rules apply to the client / server codec adapters. Selected native FastAPI parameters/bodies/forms/files use the public framework semantics declared by the target, without an additional common decoder. Integration points whose styles/media/types are unsuitable for native handling remain on the existing adapter path. The ignored-header exclusions below are common rules that must apply before selection of either path.

The single common semantic decision in [BINDING §5.2](DECISIONS-BINDING.md#binding-order-and-semantics) is authoritative for header / Media Type `encoding` applicability and ignored declarations. It evaluates, in order, the root's adopted OAS feature/version, actual Request Body parent location, encoding media, headers media, and wire name. CODECS, client, and FastAPI consume the finalized effective sequence and source/info. Do not implement target-specific predicates or refiltering. Do not equate request-direction Parameter/Header content with Request Body, or replace the adopted version/parent location based on the document where an external `$ref` is declared.

BINDING's `IgnoredEncodingDeclaration` has the closed reason set `oas_encoding_request_body_only` / `oas_encoding_media_not_applicable`; the existing `IgnoredHeaderDeclaration` has `oas_non_multipart_encoding_headers` / `oas_header_ignored`. In OAS 3.0/3.1, `encoding` outside RequestBody (including responses / components.responses), and in all three versions `encoding` for media other than multipart/urlencoded even at a valid location, is **inapplicable in its entirety, including headers**. Do not pass style/contentType or other fields to the effective wire plan. When both location and media exclusion conditions apply, use only BINDING's first applicable reason. Consequently, `response_encoding_header` can be effectively bound only for 3.2 input; even in 3.2, media and encoding-method support conditions must also be met. For applicable encoding, exclusion of all headers on non-multipart media and name-based exclusions use the same common decision. Do not make response multipart encoding in 3.0/3.1 applicable merely because the parent media is multipart. [OAS 3.0.4 Media Type](https://spec.openapis.org/oas/v3.0.4.html#media-type-object), [3.1.1 Media Type](https://spec.openapis.org/oas/v3.1.1.html#media-type-object), [3.2.1 Media Type](https://spec.openapis.org/oas/v3.2.1.html#media-type-object).

Retain raw encoding/header occurrences, declaration sources, root use-sites, and reasons in BINDING records. Exclusion of an entire encoding yields one `I_OAS_ENCODING_IGNORED`, without descending into its value or headers; record the same single field-level diagnostic even when no headers exist. Only partial header exclusion uses the existing `I_OAS_HEADER_IGNORED`; do not add per-header diagnostics to whole-encoding exclusion. Retain source occurrences and common diagnostics for components.responses and similar declarations not attached to operations. Inapplicable encoding must not trigger Header/schema resolution, type acquisition, or require_type_bindings, and must not enter signatures, handler/method arguments, required/enum validation, typed header accessors, or credential/transport ownership collision checks. This is not a general rule to ignore failures in required reference resolution. Do not delete actual headers derived from security schemes/media or models independently generated through other components/uses. Do not treat a Header component key as the actual wire name. Preserve same-scope artifact equality between ordinary Api and target Api generation.

| Location | Initial standard codec |
|---|---|
| path | simple / label / matrix; scalars and flat arrays/objects; both defined explode values |
| query | form; spaceDelimited / pipeDelimited for flat arrays/objects (explode=False); deepObject for flat objects (explode=True) |
| querystring (3.2) | Treat the whole query as one content media. Builtins: URLencoded, JSON/+json, text/plain. Other media require an adapter with explicitly declared uses |
| header | simple; scalars / flat arrays/objects; defined explode values |
| cookie | Explicit compatibility convention for form, and 3.2 style:cookie. Scalars produce the same single pair for both explode values; flat arrays/objects use explode=True (default). Compound explode=False follows the version-specific diagnostics below |
| parameter content | Registered body codecs for the single declared media, such as JSON / `+json` |

Nested deepObject, n/a style/explode/type combinations in the table, and collisions between expanded parameter keys are generation errors with `MC_PARAMETER_ENCODING`. Extend these only through explicit custom parameter-codec registration. Do not substitute a similar style. URI and cookie-form percent encoding uses UTF-8: split delimiters first, then decode each value exactly once. Do not percent-encode/decode headers or style:cookie. Even with `allowReserved=True`, do not confuse location delimiters such as `#`, `&`, `=`, and `+` with value data. Do not allow CR/LF/NUL in header/cookie values.

Fix implementation-dependent cookie-form behavior as follows. Scalars use `name=value`; explode has no effect, so false is also accepted. Arrays with explode=True repeat the same name; objects with explode=True expand property names into cookie names. Join ordered pairs with `; `. For form, percent-encode every name/value character outside the unreserved set: spaces become `%20`, and literal `%` becomes `%25`. Examples: `color=blue; color=black`, `R=100; G=200`. Decode by splitting on `;`, allowing one space, then splitting name/value at the first `=`; percent-decode only for form. 3.2 style:cookie uses the same pair joining with no escaping at all, so an input string `%2C` remains that literal value. Names must be HTTP tokens and values unquoted RFC6265 cookie-octets; quoted/custom-escape conventions require explicit adapters. Preserve duplicate array order; reject duplicate scalars/object properties and collisions with other cookie/auth names. Empty arrays/objects are errors before sending because they cannot be reversibly distinguished from omission. This convention explicitly resolves the implementation-defined portion of [OAS 3.1 Appendix D](https://spec.openapis.org/oas/v3.1.1.html#appendix-d-serializing-headers-and-cookies); it does not claim every server uses the same form.

Treat compound cookie explode=False separately from scalars. OAS 3.2 prohibits it for both styles because comma delimiters violate cookie syntax; the style:cookie example table also marks arrays/objects n/a. Do not infer that raw comma CSV is defined for cookies from the generic form example tables in 3.0/3.1 alone. Appendix D of 3.1 itself states that the same form expansion does not apply to compound cookies, so this combination is a builtin generation error for older versions too. Peer-agreed custom encodings require explicit parameter adapters. Acceptance of false for scalars follows the general rule that explode affects only arrays/objects and the 3.2 scalar examples; it does not justify ignoring the compound prohibition. [OAS 3.2.1 Parameter fixed fields and style examples](https://spec.openapis.org/oas/v3.2.1.html#parameter-object).

3.2 querystring permits only one across the effective operation/path-item, cannot coexist with ordinary `in:query`, requires exactly one content media, and cannot directly specify schema/style/explode. `name` is only declaration/Python-argument identity; do not add `name=` to the wire. URLencoded follows the same Encoding Object as bodies, without double-encoding generated query bytes (space=`+`, literal plus=`%2B`). For JSON/+json, percent-encode the entire serialized UTF-8 value once. For text/plain, do the same to the entire opaque string's UTF-8 bytes. Non-URLencoded decode must not replace `+` with a space. Builtins treat an empty raw query as omitted; required then fails. Encoding an explicit value to empty bytes is an encode error. ASGI does not guarantee information distinguishing `/path` from `/path?`, so do not infer a distinction between empty and missing values. Custom empty-value conventions require explicit parameter adapters. Do not append ordinary query pairs to an operation owning querystring; protocol/auth additions also require explicit binding to the declared whole value / property pointer. Official definitions and examples are in [OAS 3.2.1 Parameter](https://spec.openapis.org/oas/v3.2.1.html#parameter-object).

Reject duplicate scalar parameters. Exploded arrays retain duplicates as declared. Optional UNSET means not sent; an explicit empty string is an empty value. If a standard style cannot reversibly distinguish JSON null from an empty string/omission, explicit None raises `ParameterEncodingError`; APIs requiring null must use `content: application/json` or an explicit parameter adapter. Do not automatically convert null to strings `'None'/'null'`. Convert integers/bools/numbers from canonical lexical forms according to the schema; ambiguous lexical types in unions require explicit content/adapters. The server must not arbitrarily replace received empty values with schema defaults or null.

**Empty arrays/objects** in style-based path/query/header/cookie parameters and form fields cause builtin ParameterEncodingError before sending because they cannot be reversibly distinguished from omission or empty-string elements. On receive, do not fill a present empty scalar sequence into an empty container. If the owned fragment itself is absent, use UNSET; an empty fragment present for a container use is a validation error. Do not turn explicitly empty containers into omission even when optional. APIs requiring empty containers must use JSON parameter content (`[]`/`{}`) or an explicit parameter adapter's empty-value convention. Empty containers in JSON bodies / JSON parts follow their ordinary schemas; do not extend this style restriction to them.

Parameter defaults do not instruct the client to turn omission into sending. The client does not send omitted optional parameters. If the server's ParameterPlan explicitly contains a schema default for an optional parameter, validate it and apply it to the handler value, while retaining absent wire presence. Missing required parameters fail even if a default exists. Do not extend this rule to injecting schema defaults into body object properties.

This codec handles JSON/+json bodies; media codecs handle text/binary. Decompose URLencoded/multipart into per-property part plans and pass non-file values and JSON parts to this codec. The media layer owns file required/presence/contentType/encoding and `UploadFile` / the client's public BodyInput and AsyncBodyInput (converted internally to BodySource). Do not force an UploadFile into a model merely because the model emits its file field as str/bytes. When whole-body T cannot represent the body, use typed handler arguments / body-parts surfaces without altering the type.

Fix whole binary requests to public BodyInput / AsyncBodyInput excluding multipart variants, buffered binary responses to bytes, and streaming responses to the runtime's RawResponse surface. Even if D's declared type is str, do not rewrite it; retain declared model type and media surface type as separate bindings. Do not force the JSON T/DecodedValue contract onto file handles or whole binary bodies.

For schema-less URLencoded ordered FormData, multipart responses with files or without schemas using MultipartData/DecodedPart, and custom-media WireValue, use the explicit surfaces owned by CLIENT/media. Model codecs must not mix file bytes into JSON snapshots or invent nonexistent D body models. Schema-bearing non-file parts continue to validate their UseType normally.

## 11. FastAPI integration

The only server builtin backends are Pydantic v2 BaseModel / Pydantic v2 dataclass from §1. Within them, choose FastAPI native handling or a codec adapter at generation time for each parameter / body / primary response. Native bodies / primary responses pass final T to public FastAPI annotations / `response_model`; native parameters pass §4's `SurfaceType`, using framework parsing/coercion/validation/filtering/serialization. Codec adapters use `Request` / `Response` and the common codec, passing `ModelValue.value` to handlers for request codec-native uses and `DecodedValue[T]` for envelope uses. The [FastAPI decisions](DECISIONS-FASTAPI.md) own how both paths connect to one FastAPI route, and the finite selection conditions and reasons. Even for Pydantic v2, known differences in shape/required/nullable/alias/directional/projection assertions or input validation mode, and styles/media unsupported natively, require adapters. Do not add new guards, BeforeValidator, Body markers, or schema-location searches to force native handling.

A typical Pydantic v2 model in which D's standard output turns a source optional nonnullable property into `Optional[T] = None` uses adapters for both requests and primary responses because of the known nullability difference. Do not change model options implicitly; document this limitation in capability information. A required nullable whole body, or an optional whole-body use that must distinguish absence from null, also uses an adapter. Native integration points such as required-only models, nullable optional models with matching semantics, and scalar parameters can be selected independently within the two supported backends. Native exclude_unset cannot compensate for Pydantic dataclasses' lack of presence or required fallback-None omission; connect these to static selection or the codec contract for explicit envelopes. Opaque/custom field types use the existing explicit adapter contract; this does not extend server support to stdlib dataclass / TypedDict / msgspec backends. Retain those three backends' converters for the client / common codec.

Return bare T for native primary responses to FastAPI under `response_model=T`, `response_model_by_alias=True`, and `response_model_exclude_unset=True`, without common encode or post-serializer decode/encode. Explicit `ModelValue` / `ModelInput` / `HTTPResult` constructs a `Response` through the strict codec/media path for its declared surface; an explicit `Response` remains the existing escape hatch. Expose native routes' ResponseCodecs / bound factories unchanged from §3. This dispatch is based on explicit return surfaces, not fallback following runtime validation failure.

Invalid requests on codec adapters become the server's `RequestValidationError` → 422. Pass valid wire values with static projection gaps to envelope handlers. Invalid native construction/validators produce 422 for requests; invalid handler return values / response wire values become `ResponseValidationError` → 500, without exposing internal schemas/values/causes in public error bodies. Codecs do not raise HTTP exceptions themselves; route adapters map common errors to these forms. Native FastAPI integration points use public framework validation/errors; do not claim they raised common WireValidationError. Validation failures must not switch between native and codec paths.

Retain the common 2020-12 registry's stable schema_id and request/response views as records preserving source-schema and directional semantics. FastAPI integration owns native FastAPI schema connections and codec-adapter projection of components.schemas names/refs and documentation metadata. Do not relax known source nonnullable constraints to nullable to make native handling fit; explicitly record the adopted framework coercion/presence/validation profile in capability information. Serve input 3.2 as 3.2.1 and input 3.0/3.1 as 3.1.0; do not misrepresent querystring/style:cookie as 3.1 features. Separate standard documentation UI display capability from specification expressiveness; do not cut recursive schemas through inline expansion. The FastAPI decisions own multipart/file, auth, custom routes, and Request passthrough details.

### 12.1 Generator settings and explicit compatibility/exports

Do not make the generator infer arbitrary custom Python behavior. Even custom templates/bases preserving builtin codec semantics require the following explicit declarations. Do not add fields to existing `GenerateConfig` / CLI model settings. SchemaRef uses a plain RFC6901 pointer and an optional document selector, where None denotes the root. External documents may be selected, but resolve only to **known schema occurrences actually processed** in the adopted attempt's SourceLease/document table. Declarations cause zero additional fetches, parses, registrations, or model generation. Unprocessed occurrences yield `BND_MODEL_SCOPE_REQUIRED`; non-unique directional variants yield `MC_ADAPTER_CONTRACT`. Do not infer unfetched types from URIs/names. Normalize persisted values to ENTRY's SourceRef.

A compatibility name is a nonempty unique name; backend is one of the five pinned enum values. Empty schemas means all adopted models for that backend; a nonempty list applies only to models actually bound by the listed schemas. The declaration asserts user-provided semantic conformance to `builtin-v1`, not source-text identity. That contract requires preserving the official constructor/field-read/alias/default/presence/unknown-policy/constraint/serializer APIs in §§5–9 and passing MC12 as an ordinary model of the same backend. Do not require arbitrary undefined fixture records or enumeration of every field in input. Distinguish generation-time checks of known static facts, runtime-startup checks of public APIs, and release MC12; do not claim that the generator proves custom-code semantics.

`builtin-v1` means strict-codec compatibility. Neither this declaration nor an export binding authorizes inferring FastAPI-native conformance for arbitrary custom code. Adding native integration points does not weaken the existing contracts for explicit model adapters on opaque/external types, artifact/export checks, or public callbacks. The common backend enum / BackendId / capabilities retain all five values for the client, but server builtin backend selection remains limited to §1's two values. An adapter's ability to enumerate other backends in its capabilities does not authorize bypassing server backend admission. For custom field types within a selected Pydantic backend, separately check native_kind, final type, and capabilities.

ModelExportBinding.module is the absolute dotted import name of `model_package` itself or a child, corresponding to an actual module in the same adopted artifact set. symbol is one Python identifier; expressions/getattr chains are not accepted. direction selects an actual schema variant; do not infer neutral as a substitute for request/response. Check static definitions/re-exports against the ordinary token index. For dynamic exports, retain an explicit assertion in the bundle and check imports/getattr/official APIs at runtime startup. The generator does not import/execute user modules. This setting neither adds/renames models nor assumes that a model exists in another handwritten module.

The generator calculates module/export/field identity, digests of adopted artifacts, and effective bindings and pins them in the bundle. Do not require digests/field IDs in handwritten input. Exports choose only import locations; they do not establish builtin compatibility. A custom base/template without either compatibility or a selected model adapter causes `MC_ADAPTER_REQUIRED`; duplicate declarations, equal-priority conflicts, or contradictory assertions in one batch cause `MC_ADAPTER_CONTRACT`; nonexistent modules/exports cause `BND_SYMBOL_NOT_EMITTED`. A single model adapter for the same target takes priority over a builtin-compatibility declaration, without hiding export contradictions.

TOML declarations live at `[[builtin_codec_compatibility]]` / `[[export_bindings]]` in the single flat target configuration file explicitly selected by the existing CLI's `--target-config PATH`. Client and server use the same locations, applying them only to the target selected for that invocation. Record keys match Python names; tuples are arrays, SchemaRef is an inline table, enums use official CLI values, and omitted keys represent None. Existing D CLI/configuration owns input/model settings; do not add a target wrapper or models/input to this file. The following registration fragment is added to a flat file containing the required schema_version/output/package/model_package according to ENTRY. These two declarations do not change model bytes.

Model decode runs after wire validation; encode maps official native values into schema wire coordinates. The core applies directional exclusions, presence, and wire validation; adapters cannot disable required/null constraints. If presence capability is native, the callback returns official presence; if unavailable, it returns None. Other returns are contract errors. Envelopes / explicit PresenceTree take highest priority, followed by adapter presence. Treating all adapter-returned values as initialized must not be confused with proof that they were explicitly supplied. Do not convert native exceptions into ModelInput.

Parameter encode receives WireValue already validated by the model codec; decode's Unset denotes only omission of the target. JSON null is None, not Unset. Do not percent-encode fragments again. The boundary verifier checks location, reserved names, CR/LF, URI/percent triplets, header tokens, cookie octets, a single path fragment, and querystring exclusivity. Reject contributions to reserved_names belonging to other parameters/auth. Perform schema validation outside the adapter; do not erase raw/contribution order or duplicates by converting to dicts.

Schema compile plans the selected use's reachable schema closure once. validate performs no conversion/default filling and returns an empty tuple on success or a WireIssue tuple on failure. The adapter owns every required_keywords meaning and composition including evaluated properties/items; one successful pattern must not make the whole schema succeed. Common directional projection/HTTP/presence policy remains outside. Map adapter exceptions / invalid records to contract errors, WireIssue to WireValidationError, and resource exceedance to CodecResourceLimitError. All model/parameter/schema callbacks are synchronous CPU processing without I/O, with identical results for sync/async. Compile and compare capabilities before the first request; do not use validation results to retry through another adapter/builtin after runtime failure.
