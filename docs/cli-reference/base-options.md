## `--emit-model-metadata` {#emit-model-metadata}

Write a separate JSON map from the final generated models, modules, fields, and type hints to the JSON Pointer locations of their source schemas. Several models can share one location, such as read and write variants of one schema, so the module and class name identify a model.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input model_metadata.json --emit-model-metadata model-map.json --module-split-mode single --disable-timestamp # (1)!
    ```

    1. :material-arrow-left: `--emit-model-metadata` - the option documented here

??? example "Examples"

    **Input Schema:**

    ```json
    {
      "$schema": "https://json-schema.org/draft/2020-12/schema",
      "title": "Root title",
      "type": "object",
      "properties": {
        "method": {
          "const": "thread/started"
        },
        "payload": {
          "$ref": "#/$defs/MetadataPayload"
        }
      },
      "required": ["method", "payload"],
      "$defs": {
        "MetadataPayload": {
          "title": "Payload title",
          "type": "object",
          "properties": {
            "id": {
              "type": "integer"
            }
          },
          "required": ["id"]
        }
      }
    }
    ```

    **Output:**

    <!-- fmt: off -->

    ```python
    # generated by datamodel-codegen:
    #   filename:  model_metadata.json

    from __future__ import annotations

    from typing import Literal

    from pydantic import BaseModel

    from . import metadata_payload


    class RootTitle(BaseModel):
        method: Literal['thread/started']
        payload: metadata_payload.MetadataPayload
    ```

    <!-- fmt: on -->

    **Generated metadata (`model-map.json`):**

    <!-- fmt: off -->

    ```json
    {
      "version": 1,
      "models": [
        {
          "class_name": "RootTitle",
          "name": "RootTitle",
          "module": "root_title",

          "source_path": [],
          "title": "Root title",
          "fields": [
            {
              "name": "method",
              "alias": "method",
              "original_name": "method",
              "type": "Literal['thread/started']",
              "required": true
            },
            {
              "name": "payload",
              "alias": "payload",
              "original_name": "payload",
              "type": "metadata_payload.MetadataPayload",
              "required": true
            }
          ]
        },
        {
          "class_name": "MetadataPayload",
          "name": "MetadataPayload",
          "module": "metadata_payload",
          "source_ref": "model_metadata.json#/$defs/MetadataPayload",
    ```

## `--encoding` {#encoding}

Specify character encoding for input and output files.

The `--encoding` flag sets the character encoding used when reading
the schema file and writing the generated Python code. This is useful
for schemas containing non-ASCII characters (e.g., Japanese, Chinese).
Default is UTF-8, which is the standard encoding for JSON and most modern text files.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input encoding_test.json --encoding utf-8 # (1)!
    ```

    1. :material-arrow-left: `--encoding` - the option documented here

    ```json
      "$schema": "http://json-schema.org/draft-07/schema#",

      "description": "モデルの説明文",
      "type": "object",
      "properties": {
        "名前": {
          "type": "string",
    ```

## `--external-ref-mapping` {#external-ref-mapping}

Map external `$ref` files to Python packages.

Use `--external-ref-mapping FILE_PATH=PYTHON_PACKAGE` to import referenced models from an existing package,
instead of generating duplicate classes from external schema files. An `allOf` of a mapped `$ref` and keywords that
add no field, such as `maxLength` or `description`, is typed by the import too; its other keywords are not kept, as
with a local `$ref`.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input api.yaml --input-file-type openapi --external-ref-mapping common.yaml=mypackage.shared.models # (1)!
    ```

    1. :material-arrow-left: `--external-ref-mapping` - the option documented here

??? example "Examples"

    **Input Schema:**

    ```yaml
    openapi: "3.0.3"
    info:
      title: API
      version: "1.0.0"
    paths: {}
    components:
      schemas:
        UserResponse:
          type: object
          properties:
            user:
              $ref: "common.yaml#/components/schemas/User"
            request_id:
              type: string
          required:
            - user
            - request_id
        ErrorResponse:
          type: object
          properties:
            error:
              $ref: "common.yaml#/components/schemas/Error"
            timestamp:
              type: string
              format: date-time
          required:
            - error
            - timestamp
    ```

    **Output:**

    <!-- fmt: off -->

    ```python
    # generated by datamodel-codegen:
    #   filename:  api.yaml
    #   timestamp: 2019-07-26T00:00:00+00:00

    from __future__ import annotations

    from mypackage.shared.models import Error, User
    from pydantic import AwareDatetime, BaseModel


    class UserResponse(BaseModel):
        user: User
        request_id: str


    class ErrorResponse(BaseModel):
        error: Error
        timestamp: AwareDatetime
    ```

## `--http-backend` {#http-backend}

Select the HTTP client backend for remote schemas.

`--http-backend auto` selects stable HTTPX when its client module is installed
and selects experimental HTTPX2 only when that module is absent. Explicit
`httpx` or `httpx2` selections require that exact backend. Explicit selections
and paired dependency errors do not fall back.

!!! tip "Usage"

## `--ignore-ref-siblings-by-schema-version` {#ignore-ref-siblings-by-schema-version}

Read a `$ref` as its target alone where the schema version ignores the keywords beside it.

JSON Schema draft 4, 6 and 7, OpenAPI 3.0 and AsyncAPI 2 ignore every keyword beside a `$ref`. Without the option
those keywords overlay the referenced schema: a sibling `format: binary` types the field `bytes`, a sibling
`maxLength` constrains it, and a sibling `uniqueItems` makes it a set under `--use-unique-items-as-set`. With
`--ignore-ref-siblings-by-schema-version` the field is typed by the referenced schema alone, and annotations beside
the `$ref`, such as `description` or `default`, are left out too. Versions that apply the keywords beside a `$ref`
(2019-09 and later, OpenAPI 3.1 and later, AsyncAPI 3) read them as before. The version is the one
`--read-schema-version-per-document` reads, else that of the document being parsed. A schema converted from Avro,
XML Schema or Protocol Buffers, also as an AsyncAPI payload, keeps the keywords its converter writes beside a `$ref`,
such as the default of a field typed by a named type.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input ref_siblings_ignored_oas30.yaml --ignore-ref-siblings-by-schema-version # (1)!
    ```

    1. :material-arrow-left: `--ignore-ref-siblings-by-schema-version` - the option documented here

??? example "Examples"

    **Input Schema:**

    ```yaml
    openapi: 3.0.3
    info:
      title: Keywords beside a Reference Object
      version: '1'
    paths: {}
    components:
      schemas:
        Text:
          type: string
        Holder:
          type: object
          properties:
            data:
              $ref: '#/components/schemas/Text'
              format: binary
            note:
              $ref: '#/components/schemas/Text'
              description: A note
              maxLength: 3
    ```

    **Output:**

    === "With Option"

        <!-- fmt: off -->

        ```python
        # generated by datamodel-codegen:
        #   filename:  ref_siblings_ignored_oas30.yaml

        from __future__ import annotations

        from pydantic import BaseModel, RootModel


        class Text(RootModel[str]):
            root: str


        class Holder(BaseModel):
            data: Text | None = None
            note: Text | None = None
        ```

        <!-- fmt: on -->

    === "Without Option"

        <!-- fmt: off -->

        ```python
        # generated by datamodel-codegen:
        #   filename:  ref_siblings_ignored_oas30.yaml

        from __future__ import annotations

        from pydantic import BaseModel, Field, RootModel, constr


        class Text(RootModel[str]):
            root: str


        class Holder(BaseModel):
            data: bytes | None = None
            note: constr(max_length=3) | None = Field(None, description='A note')
        ```

## `--input-file-type` {#input-file-type}

Specify the input file type for code generation.

The `--input-file-type` flag explicitly sets the input format.

**Important distinction:**

- Use `jsonschema`, `openapi`, `asyncapi`, `graphql`, `mcp-tools`, `xmlschema`,
  `protobuf`, or `avro` for **schema definition files**
- Use `json`, `yaml`, or `csv` for **raw sample data** to automatically infer a schema

For example, if you have a JSON Schema written in YAML format, use `--input-file-type jsonschema`,
not `--input-file-type yaml`. The `yaml` type treats the file as raw data and infers a schema from it.

## `--read-dynamic-anchors-in-document-order` {#read-dynamic-anchors-in-document-order}

Resolve a `$dynamicRef` to the first `$dynamicAnchor` of its name in document order.

A plain-name `$dynamicRef` that its dynamic scope does not bind names a `$dynamicAnchor` of its name in its document.
Without this option that is the first one the parse has met, so the answer depends on the order of the schemas: with
`Holder` written before the components `First` and `Second` that both declare `$dynamicAnchor: T`, `#T` resolves to
`Second`, written after them to `First`. With it the document as loaded decides: the first declaration in document
order. A `$ref` or `$dynamicRef` to a plain name several schemas of a document declare, which JSON Schema leaves
undefined and which warns either way, names the first declaration too, where it names the last without the option.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input dynamic_ref_anchor_parse_order.yaml --read-dynamic-anchors-in-document-order # (1)!
    ```

    1. :material-arrow-left: `--read-dynamic-anchors-in-document-order` - the option documented here

??? example "Examples"

    **Input Schema:**

    ```yaml
    openapi: 3.1.0
    info:
      title: dynamic anchor parse order
      version: "1"
    paths: {}
    components:
      schemas:
        Holder:
          type: object
          properties:
            item:
              $dynamicRef: "#T"
        First:
          $dynamicAnchor: T
          type: object
          properties:
            first:
              type: integer
        Second:
          $dynamicAnchor: T
          type: object

            second:
              type: string
    ```

## `--read-escaped-ref-pointers` {#read-escaped-ref-pointers}

Read the escapes of a `$ref` JSON pointer as the characters they encode.

A pointer writes `/` in a name as `~1`, `~` as `~0`, and, in a URI fragment, any other character percent-encoded
(`%20` for a space). Without this option a reference keeps the escaped text as the key of its target, so the definition
it names, keyed by its name, gets a copy named after the escaped text (`Line20Item` beside `LineItem`, `Tax1rate`
beside `TaxRate`), which the field takes. With it every spelling of a pointer names the one model of its target, keyed
as the `api` scope keys it; a model a reference adds is named after the decoded name, and a `--model-name-map` key that
names a path matches it in any spelling, in the `api` scope too, where the first of the keys that spell one path renames
it. A `/` written unescaped inside a name is a separator then, as JSON Pointer reads it, also after a `~1`, so such a
pointer warns as a dangling reference, unless the name holds `://`, which is still read whole.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input escaped_ref_pointers.json --read-escaped-ref-pointers # (1)!
    ```

## `--read-input-model-dataclass-fields-by-alias` {#read-input-model-dataclass-fields-by-alias}

Read the fields of a Pydantic dataclass by their aliases with --input-model.

`--input-model` gives each field the Python type of its model, such as `deque[int]`, where JSON Schema cannot spell
it. A Pydantic dataclass is read by its annotations, keyed by field name, so a field with an alias takes the type its
JSON Schema spells (`list[int]`) instead. With this option the fields of a Pydantic dataclass are read with their
aliases, as those of a model, so an aliased field keeps its Python type like one without.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input schema.json --input-model mymodule:Outer --read-input-model-dataclass-fields-by-alias # (1)!
    ```

## `--read-schema-version-per-document` {#read-schema-version-per-document}

Read each document by the schema version it declares.

Without the option the schema version of the document parsed first decides, for every document of a run, whether the
keywords beside a `$ref` apply and which features of its version are read (`const`, `prefixItems`, `$id`, `$defs`).
With `--read-schema-version-per-document` each document is read by the version its `$schema`, `openapi` or `asyncapi`
field declares; a referenced document that declares none takes the version of the document whose reference loads it,
and an input document that declares none is read as it is on its own. Here the draft-07 document ignores the `maximum`
beside its allOf `$ref`, as draft 7 says, and the 2020-12 root keeps it. An OpenAPI 3.1 document reads the keywords
beside a `$ref` as JSON Schema 2020-12 does, and the property-count rule of `--generate-schema-validators` leaves out a
`minProperties` beside an allOf `$ref` of a draft-07 document. An explicit `--schema-version` reads every document by
that version, with or without the option, except that without it the schema validators of
`--generate-schema-validators` read an OpenAPI or AsyncAPI document as draft 7.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input root.json --read-schema-version-per-document # (1)!
    ```

    1. :material-arrow-left: `--read-schema-version-per-document` - the option documented here

??? example "Examples"

    **Input Schema:**

    ```json
    {
      "$schema": "https://json-schema.org/draft/2020-12/schema",
      "title": "Root",
      "type": "object",
      "properties": {
        "legacy": {
          "$ref": "legacy_draft07.json#/definitions/Score"
        },
        "score": {
          "$ref": "#/$defs/Score"
        }
      },
      "$defs": {
        "Positive": {
          "type": "integer",
          "minimum": 1
        },
        "Score": {
          "allOf": [
            {
              "$ref": "#/$defs/Positive",
              "maximum": 10
            }
          ]
        }
      }
    }
    ```

    **Output:**

    === "With Option"

        <!-- fmt: off -->

        ```python

        #   filename:  root.json

            root: conint(ge=1)

            root: conint(ge=1, le=10)


        class ScoreModel(RootModel[Positive]):
            root: Positive

            legacy: ScoreModel | None = None
            score: Score | None = None
        ```

## `--reuse-every-reached-input-model-type` {#reuse-every-reached-input-model-type}

Reach the types to reuse through every model kind and write no copy of an imported type.

With `--input-model-ref-strategy reuse-all` or `reuse-foreign` the types an input model reaches are imported from its
module instead of generated. Reuse follows the fields of Pydantic models only, so a type reached through a dataclass
field is still generated: `Color`, which only the dataclass `Box` uses, is written although `Box` is imported
(reuse-all), or written beside the imported `Size` (reuse-foreign). A field whose Python type the output keeps, such as
`Mapping[str, Item]`, imports `Item`, and a copy of `Item` (`ItemModel`) is written too. With this option reuse follows
the fields of dataclasses, TypedDicts and msgspec Structs too, and a type that the Python type of a field imports is
reused instead of copied, so references to it name the import.

!!! tip "Usage"

    ```bash
    datamodel-codegen --input schema.json --input-model mymodule:Order --input-model-ref-strategy reuse-foreign --reuse-every-reached-input-model-type # (1)!
    ```

    1. :material-arrow-left: `--reuse-every-reached-input-model-type` - the option documented here
