=== release notes 0.2.0 (exit 0) ===
## Breaking Changes

### Code Generation Changes
* String enums become `StrEnum` - Enums of strings subclass `StrEnum` instead of `Enum`. Keep the old output with `--no-use-specialized-enum`. (#2512)
* Models of `anyOf` members lose the `Item` suffix - Models of `anyOf` and `oneOf` members no longer end in `Item`. No option restores the old names; `--model-name-map` can pin individual names. (#1682)

### Python Version Changes
* datamodel-code-generator no longer runs on Python 3.7 - Install and run the generator on Python 3.8 or newer. Use Python 3.8 or newer. (#2060)

## Deprecations

* `--validation` now emits `DeprecationWarning`. Planned removal: 0.4.0. --validation is deprecated.

## New Dated Presets

* `standard-py3XX-20260101` and `practical-py3XX-20260101`: The first dated presets; the [presets page](https://datamodel-code-generator.koxudaxi.dev/presets/) lists their options.

=== release notes 0.3.0 (exit 0) ===
## Breaking Changes

### Code Generation Changes
* Constraints move into `Annotated` - With `--use-annotated`, constraints are written in `Annotated`. Keep the old output with `--field-constraints`. (#3001)
* `format: date-time` becomes `AwareDatetime` - A timestamp without a UTC offset is rejected. Keep the old output with `--output-datetime-class datetime`. (#1735)

### API/CLI Changes
* `generate_dynamic_models()` no longer formats the code it builds - It skips Black and isort unless formatters are selected. Pass `formatters=[Formatter.BLACK, Formatter.ISORT]` in the config. (#6750)

### Python Version Changes
* datamodel-code-generator no longer runs on Python 3.8 - Install and run the generator on Python 3.9 or newer. Use Python 3.9 or newer. (#3003)

## Deprecations

* `PythonVersion.has_type_alias` now emits `DeprecationWarning`. Planned removal: TBD. has_type_alias is deprecated.

## New Options

* New option `--released-flag`

## New Dated Presets

* `standard-py3XX-20260201` and `practical-py3XX-20260201`: they keep the 20260101 options and add Python 3.15 targets; Strict types (`--strict-types str`): Be strict.

## Experimental Features

* `--input-file-type avro` is experimental. Avro input is experimental.

## Changes That Need No Action

* Class docstrings are wrapped - Long class docstrings are wrapped at the line length. (#3002)

=== release notes 0.4.0 (exit 0) ===
## Breaking Changes

### API/CLI Changes
* `--validation` is removed - --validation is deprecated. Use --field-constraints.

### Error Handling Changes
* An empty `enum` is refused - A schema with `enum: []` fails with an error instead of generating an empty enum. Drop the empty `enum` keyword. (#4002)

## Changes That Need No Action

* Class docstrings are no longer wrapped - The wrapping of 0.3.0 is undone. (#4001)

=== release notes unreleased (exit 0) ===
## Breaking Changes

### Custom Template Update Required
* Custom templates receive `fields` instead of `model_fields` - Templates of `--custom-template-dir` read the fields as `fields`. Rename `model_fields` to `fields` in your templates. (#5001)

### API/CLI Changes
* `--old-flag` is removed - The option did nothing since 0.3.0. Drop `--old-flag`. (#5002)

## Scheduled Breaking Changes

* `argcomplete installation` is registered without a runtime warning. Planned removal: TBD. argcomplete will become optional.

## New Options

* New option `--new-flag` (`--no-new-flag`): Turn on new things.
* New value `c` of `--output-model-type`
* New option `--quiet-flag`

## New Dated Presets

* `standard-py3XX-20260301` and `practical-py3XX-20260301`: they keep the 20260201 options and add Snake case (`--snake-case-field`): Snake case field names.

<!-- Generated by scripts/build_migration_docs.py. Do not edit manually. -->

For datamodel-code-generator 0.1.0. On the way to 0.4.0: 3 required changes, 4 output changes an option keeps, 1 changes no option keeps, 2 new warnings, 4 changes that need nothing. Each item names the release that made it. [All changes](changes.md) · [Machine-readable list](https://datamodel-code-generator.koxudaxi.dev/data/migration.json)

## Keep your current output

Add these options to keep the output of your release where 0.4.0 can (every option exists in 0.4.0):

```bash
datamodel-codegen ... --no-use-specialized-enum --output-datetime-class datetime
```

or in `pyproject.toml`:

```toml
[tool.datamodel-codegen]
use-specialized-enum = false
output-datetime-class = "datetime"
```

Only if you pass `--use-annotated`, also add `--field-constraints`.

Outside the command line:

- `generate_dynamic_models()` no longer formats the code it builds: Pass `formatters=[Formatter.BLACK, Formatter.ISORT]` in the config.

## Required changes

### datamodel-code-generator no longer runs on Python 3.8 (0.3.0) { #python-38-runtime-dropped }

Install and run the generator on Python 3.9 or newer.

- **What to change:** Use Python 3.9 or newer.
- **Pull requests and issues:** [#3003](https://github.com/datamodel-code-generator/datamodel-code-generator/issues/3003)
- **Source:** the release notes

### An empty `enum` is refused (0.4.0) { #refuse-empty-enum }

A schema with `enum: []` fails with an error instead of generating an empty enum.

- **What to change:** Drop the empty `enum` keyword.
- **Pull requests and issues:** [#4002](https://github.com/datamodel-code-generator/datamodel-code-generator/issues/4002)
- **Source:** the release notes

### `--validation` is removed (0.4.0) { #removal-cli-validation }

--validation is deprecated.

- **Affects:** only with: `--validation`
- **What to change:** Use --field-constraints.
- **Source:** the registry of deprecations, experimental features and dated presets

## Output changes an option keeps

### String enums become `StrEnum` (0.2.0) { #specialized-enum-default }

Enums of strings subclass `StrEnum` instead of `Enum`.

- **Affects:** input types: `openapi`, `jsonschema`
- **Keep the old output:** `--no-use-specialized-enum`
- **Pull requests and issues:** [#2512](https://github.com/datamodel-code-generator/datamodel-code-generator/issues/2512)
- **Source:** the release notes

```diff
-class Status(Enum):
+class Status(StrEnum):
```

### Constraints move into `Annotated` (0.3.0) { #annotated-constraints }

With `--use-annotated`, constraints are written in `Annotated`.

- **Affects:** only with: `--use-annotated`
- **Keep the old output:** `--field-constraints`
- **Pull requests and issues:** [#3001](https://github.com/datamodel-code-generator/datamodel-code-generator/issues/3001)
- **Source:** the release notes

### `format: date-time` becomes `AwareDatetime` (0.3.0) { #aware-datetime }

A timestamp without a UTC offset is rejected.

- **Affects:** output model types: `pydantic_v2.BaseModel`
- **Keep the old output:** `--output-datetime-class datetime`
- **Pull requests and issues:** [#1735](https://github.com/datamodel-code-generator/datamodel-code-generator/issues/1735)
- **Source:** the release notes

### `generate_dynamic_models()` no longer formats the code it builds (0.3.0) { #dynamic-models-unformatted }

It skips Black and isort unless formatters are selected.

- **Affects:** Python API: `generate_dynamic_models`
- **Keep the old output:** Pass `formatters=[Formatter.BLACK, Formatter.ISORT]` in the config.
- **Pull requests and issues:** [#6750](https://github.com/datamodel-code-generator/datamodel-code-generator/issues/6750)
- **Source:** the release notes

## Changes no option keeps

### Models of `anyOf` members lose the `Item` suffix (0.2.0) { #union-item-suffix-removed }

Models of `anyOf` and `oneOf` members no longer end in `Item`.

- **Keep the old output:** No option restores the old names; `--model-name-map` can pin individual names.
- **Pull requests and issues:** [#1682](https://github.com/datamodel-code-generator/datamodel-code-generator/issues/1682)
- **Source:** the release notes
