usage: 
  datamodel-codegen [options]

Generate Python data models from schema definitions or structured data

For detailed usage, see: https://datamodel-code-generator.koxudaxi.dev

Options:
  --additional-imports ADDITIONAL_IMPORTS
                        Custom imports for output (delimited list input). For
                        example "datetime.date,datetime.datetime"
  --allow-private-network, --no-allow-private-network
                        Allow HTTP(S) schema requests to private, loopback,
                        link-local, or otherwise non-public network hosts. By
                        default these targets are blocked to reduce server-
                        side request forgery (SSRF) risk. If a trusted
                        internal schema endpoint is blocked, verify the URL
                        and pass this option; otherwise use a local schema
                        file or public endpoint. Pass --no-allow-private-
                        network to override a configuration file that enables
                        it.
  --allow-remote-refs, --no-allow-remote-refs
                        Allow fetching remote $ref references over HTTP/HTTPS.
                        Currently remote fetching is allowed by default but
                        emits a deprecation warning. Pass --allow-remote-refs
                        to opt in without warning, or --no-allow-remote-refs
                        to block remote fetching. In a future version, remote
                        fetching will be disabled by default.
  --class-decorators CLASS_DECORATORS
                        Custom decorators for generated model classes
                        (delimited list input). For example
                        "@dataclass_json(letter_case=LetterCase.CAMEL)". The
                        "@" prefix is optional and will be added automatically
                        if missing.
  --custom-formatters CUSTOM_FORMATTERS
                        List of modules with custom formatter (delimited list
                        input).
  --emit-model-metadata EMIT_MODEL_METADATA
                        Write a separate JSON map from generated models and
                        fields to the JSON Pointer locations of their source
                        schemas; module and class name identify a model.
  --external-ref-mapping FILE_PATH=PYTHON_PACKAGE [FILE_PATH=PYTHON_PACKAGE ...]
                        Map external $ref file paths to Python import packages
                        instead of generating duplicate classes. Accepts one
                        or more mappings after a single flag. Format:
                        "path/to/schema.yaml=mypackage.models". When a $ref
                        points to a mapped file, an import statement is
                        generated instead of a class definition.
  --formatters {builtin,black,isort,ruff-check,ruff-format} [{builtin,black,isort,ruff-check,ruff-format} ...]
                        Formatters (current default: black, isort; future
                        default: builtin). For Ruff projects, use --formatters
                        ruff-check ruff-format (install with pip install
                        'datamodel-code-generator[ruff]'). Use --formatters
                        builtin when no external formatter is used or
                        generation speed takes priority. Keep --formatters
                        black isort to preserve existing formatting. Presets
                        dated 20260909 or later include builtin; explicit
                        formatters override presets. The future builtin
                        default reduces installation dependencies and version
                        constraints. Black/isort remain required today;
                        declare [black,isort] extras for their later optional
                        installation. Review custom-template output with
                        builtin. Details: https://datamodel-code-
                        generator.koxudaxi.dev/formatter-behavior/
  --http-backend {auto,httpx,httpx2}
                        Select the HTTP client backend. 'auto' (default)
                        selects stable HTTPX when its client module is
                        installed and only selects experimental HTTPX2 when
                        that module is absent. 'httpx' and 'httpx2' require
                        that exact backend. Explicit selections and paired
                        dependency errors do not fall back.
  --http-headers HTTP_HEADER [HTTP_HEADER ...]
                        Set headers in HTTP requests to the remote host.
                        (example: "Authorization: Basic dXNlcjpwYXNz")
  --http-ignore-tls     Disable verification of the remote host's TLS
                        certificate
  --http-local-ref-path HTTP_LOCAL_REF_PATH
                        Resolve HTTP(S) JSON Schema $ref URLs from a local
                        directory instead of fetching them. URLs are mapped
                        under the directory by host and path; extensionless
                        refs also try '.json'.
  --http-query-parameters HTTP_QUERY_PARAMETERS [HTTP_QUERY_PARAMETERS ...]
                        Set query parameters in HTTP requests to the remote
                        host. (example: "ref=branch")
  --http-timeout HTTP_TIMEOUT
                        Timeout in seconds for HTTP requests to remote hosts
                        (default: 30)
  --ignore-ref-siblings-by-schema-version, --no-ignore-ref-siblings-by-schema-version
                        Read a $ref as its target alone where the schema
                        version ignores the keywords beside it (JSON Schema
                        draft 4, 6 and 7, OpenAPI 3.0, AsyncAPI 2), as those
                        versions specify: a $ref with a sibling format: binary
                        takes the referenced type instead of bytes, a sibling
                        uniqueItems makes no set, and a sibling description or
                        default is left out too. Versions that apply the
                        keywords beside a $ref (2019-09 and later, OpenAPI 3.1
                        and later, AsyncAPI 3) read them as before. Without it
                        the keywords beside such a $ref overlay its target, as
                        in 0.88.0. The version is the one --read-schema-
                        version-per-document reads, else that of the document
                        parsed. A schema converted from Avro, XML Schema or
                        Protocol Buffers keeps the keywords its converter
                        writes beside a $ref, such as the default of a field
                        typed by a named type.
  --input INPUT         Input file/directory (default: stdin)
  --input-file-type {auto,openapi,asyncapi,jsonschema,mcp-tools,xmlschema,protobuf,avro,json,yaml,dict,csv,graphql}
                        Input file type (default: auto). Use 'jsonschema',
                        'openapi', 'asyncapi', 'graphql', 'mcp-tools',
                        'xmlschema', 'protobuf', or 'avro' for schema
                        definitions. Use 'json', 'yaml', or 'csv' for raw
                        sample data to infer a schema automatically; Genson
                        infers it and will become optional: declare the genson
                        extra.
  --input-model MODULE_OR_PATH:NAME
                        Python import path or file path to a Pydantic v2 model
                        or schema dict (e.g., 'mypackage.module:ClassName',
                        './models.py:ClassName', or
                        'mypackage.schemas:SCHEMA_DICT'). Can be specified
                        multiple times for related models with inheritance.
                        For dict input, --input-file-type is required. Cannot
                        be used with --input or --url.
  --input-model-ref-strategy {regenerate-all,reuse-foreign,reuse-all}
                        Strategy for referenced types in --input-model.
                        'regenerate-all': Regenerate all types. 'reuse-
                        foreign': Reuse types from different families (Enum,
                        etc.), regenerate same-family. 'reuse-all': Reuse all
                        referenced types via import. If not specified,
                        defaults to regenerate-all behavior.
  --locked              Require an existing remote lock and validate each
                        fetched resource against it (experimental).
  --lockfile LOCKFILE   Select the remote reference integrity lock file
                        (experimental). An existing selected lock is verified
                        automatically; a missing selected lock is ignored
                        unless --locked is used. The default is datamodel-
                        codegen.lock beside the discovered pyproject.toml, or
                        in the invocation working directory when no project is
                        found. Explicit relative paths resolve from the
                        invocation working directory.
  --no-formatters       Select no formatter, not even the default or a
                        preset's formatters; --custom-formatters still run.
  --output OUTPUT       Output file (default: stdout)
  --output-model-type {pydantic_v2.BaseModel,pydantic_v2.dataclass,dataclasses.dataclass,typing.TypedDict,msgspec.Struct}
                        Output model type (default: pydantic_v2.BaseModel)

  --read-dynamic-anchors-in-document-order, --no-read-dynamic-anchors-in-document-order
                        Resolve a plain-name $dynamicRef that its dynamic
                        scope does not bind from the $dynamicAnchors its
                        document declares, the first in document order when
                        several declare the name, and a $ref or $dynamicRef to
                        a plain name several schemas of a document declare to
                        the first of them; without it the $dynamicRef takes
                        the first anchor the parse has met, so the answer
                        depends on the order of the schemas, and the $ref the
                        last declaration, as in 0.89.0.
  --read-escaped-ref-pointers, --no-read-escaped-ref-pointers
                        Read the ~0 and ~1 escapes and the percent-encoded
                        octets of a $ref JSON pointer as the characters they
                        encode, as JSON Pointer and URI fragments do, so
                        #/$defs/a~1b, and #/$defs/Foo Bar written with its
                        space percent-encoded, name the models of the
                        definitions a/b and Foo Bar; without it such a
                        reference gets a copy of its target named after the
                        escaped text (A1b, Foo20Bar), as in 0.89.0.
  --read-input-model-dataclass-fields-by-alias, --no-read-input-model-dataclass-fields-by-alias
                        With --input-model, read the fields of a Pydantic
                        dataclass by their aliases, as those of a model, so a
                        field with an alias keeps its Python type (deque[int],
                        frozenset[str], ...) like one without; without it an
                        aliased field of a Pydantic dataclass takes the type
                        its JSON Schema spells (list[int]), as in 0.89.0
  --read-schema-version-per-document, --no-read-schema-version-per-document
                        Read each document by the schema version it declares
                        ($schema, or the openapi or asyncapi field); a
                        referenced document that declares none takes the
                        version of the document whose reference loads it. The
                        keywords beside a $ref and the features of the version
                        (const, prefixItems, $id, $defs) then apply as each
                        document's version says: a 2020-12 file of a directory
                        read after a draft-07 one keeps the maximum beside an
                        allOf $ref, an OpenAPI 3.1 document reads $ref
                        siblings as JSON Schema 2020-12 does, and a draft-07
                        document sets no property-count rule for a
                        minProperties beside an allOf $ref. Without it the
                        version of the document parsed first applies to every
                        document, as in 0.88.0. An explicit --schema-version
                        gives every document its version; the schema
                        validators then read an OpenAPI or AsyncAPI document
                        by it only with the option, else as draft 7.
  --reuse-every-reached-input-model-type, --no-reuse-every-reached-input-model-type
                        With --input-model-ref-strategy reuse-all or reuse-
                        foreign, reach the types to reuse through the fields
                        of every model kind, dataclasses, TypedDicts and
                        msgspec Structs too, and import a type that the Python
                        type of a field already imports instead of writing an
                        unused copy of it; without it reuse descends through
                        Pydantic models only and such a copy is written
                        (ItemModel beside Mapping[str, Item]), as in 0.89.0
  --schema-version SCHEMA_VERSION
                        Schema version. Valid values depend on input type:
                        JsonSchema: auto, draft-04, draft-06, draft-07,
                        2019-09, 2020-12. OpenAPI: auto, 3.0, 3.1, 3.2.
                        AsyncAPI: auto, 2.0, 3.0. XMLSchema: auto, 1.0, 1.1.
                        Protobuf: auto, proto2, proto3, 2023. (default: auto -
                        detected from $schema, openapi/asyncapi field, XML
                        Schema versioning attributes, or Protobuf
                        syntax/edition)
  --schema-version-mode {lenient,strict}
                        Schema version validation mode. 'lenient': accept all
                        features regardless of version (default). 'strict':
                        warn on features outside declared/detected version.
  --strict-refs         Treat unresolved local $ref JSON pointers as errors
                        instead of generating fallback Any models.
  --untrusted-input, --no-untrusted-input
                        Treat the input as a schema from an untrusted source
                        (experimental): read no file or URL but the input, so
                        every $ref and XML Schema include must name a location
                        in the input; refuse the schema keywords whose values
                        the generated module imports or evaluates as Python
                        code (x-python-type, x-python-import, customTypePath,
                        customBasePath), Protocol Buffers input, --validation
                        and a schema nested more than 100 levels deep or
                        holding more than 2,000,000 objects and arrays.
                        Implies --no-allow-remote-refs. Pass --no-untrusted-
                        input to override a configuration file that enables
                        it.
  --update-lock         Create or atomically update the selected remote lock
                        after generation (experimental).
  --url URL             Input file URL. `--input` is ignored when `--url` is
                        used. For HTTP(S), datamodel-code-generator[http]
                        remains the stable HTTPX backend and is not
                        deprecated, while datamodel-code-generator[httpx2] is
                        experimental. The default --http-backend auto policy
                        selects stable HTTPX when its client module is
                        installed and selects HTTPX2 only when that module is
                        absent. Select --http-backend httpx2 to require the
                        experimental backend. Explicit selections and paired
                        dependency errors do not fall back.

Typing customization:
  --allof-class-hierarchy {if-no-conflict,always}
                        How to map allOf references to class hierarchies. 'if-
                        no-conflict': only create subclasses when parent class
                        has no conflicting property definition. 'always':
                        always create subclasses.
  --allof-merge-mode {constraints,all,none}
                        Mode for field merging in allOf schemas.
                        'constraints': merge only constraints (minItems,
                        maxItems, pattern, etc.) from parent (default). 'all':
                        merge constraints plus annotations (default, examples)
                        from parent. 'none': do not merge any fields from
                        parent properties.
  --base-class BASE_CLASS
                        Base Class (default: pydantic.BaseModel)
  --base-class-map BASE_CLASS_MAP
                        Model-specific base class mapping (JSON or JSON file
                        path). Example: '{"MyModel": "custom.BaseA",
                        "OtherModel": "custom.BaseB"}'. Priority: base-class-
                        map > customBasePath (in schema) > base-class.
  --disable-future-imports
                        Disable __future__ imports
  --distribute-allof-over-unions, --no-distribute-allof-over-unions
                        Read an `allOf` with the `anyOf` and `oneOf` it holds
                        or sits beside as JSON Schema validates them: an
                        `allOf` of several is one union variant per
                        combination of one branch of each, also through a
                        `$ref` member that names an `allOf` over a union, a
                        `$ref` branch takes the `allOf` members beside its
                        `anyOf` or `oneOf`, which an inline branch already
                        takes, and the value keywords beside it where it names
                        no object, and an OpenAPI request or response body
                        with an `allOf` beside an `anyOf` or `oneOf` is that
                        union as a schema of the components is; the value
                        branches of those unions are read at a field and
                        beside object branches too. Without it the branches of
                        every `anyOf` and `oneOf` of an `allOf` join one union
                        (the inline branches of a second replacing those of
                        the first), a `$ref` member naming an `allOf` over a
                        union is dropped, a `$ref` branch takes only the
                        `properties` and `required` beside it, a body drops
                        the union, and value branches are read only where the
                        `allOf` would be a model without fields, as in 0.89.0
  --enum-field-as-literal {all,one,none}
                        Parse enum field as literal. all: all enum field type
                        are Literal. one: field type is Literal when an enum
                        has only one possible value. none: always use Enum
                        class (never convert to Literal)
  --enum-field-as-literal-map ENUM_FIELD_AS_LITERAL_MAP
                        Per-field override for enum/literal generation (JSON
                        or JSON file path). Format: JSON object mapping field
                        names to 'literal' or 'enum'. Example: '{"status":
                        "literal", "priority": "enum"}'. Overrides --enum-
                        field-as-literal for matched fields.
  --field-constraints   Use field constraints and not con* annotations
  --filter-literal-values, --no-filter-literal-values
                        Keep only the values of a `const` or an `enum` that
                        meet the `minLength`, `maxLength`, `pattern`, bound
                        and `multipleOf` constraints beside them in its
                        `Literal` or Enum, as JSON Schema validates them; a
                        schema none of whose values meets them stays as
                        written with a warning
  --ignore-enum-constraints
                        Ignore enum constraints and use the base type (e.g.,
                        str, int) instead of generating Enum classes
  --import-overrides IMPORT_OVERRIDES
                        Override modules for generated imports by symbol name.
                        Format: JSON object mapping symbols to module paths.
                        Example: '{"TypedDict": "my_project.typing_compat",
                        "NotRequired": "my_project.typing_compat"}'.
  --intersect-allof-keywords, --no-intersect-allof-keywords
                        Combine the keywords of every part of an `allOf`, of a
                        `$ref` with sibling keywords and of an inherited
                        property override, as JSON Schema validates them: the
                        tightest bounds, the `enum` values every part admits,
                        the `type` every part admits, the conjunction of the
                        `pattern`s, no null beside a `type` that excludes it,
                        and the constraints of the root, item and map value
                        positions of an `allOf`. Without it, the keyword of
                        the last part wins where the parts disagree
  --intersect-combined-schema-keywords, --no-intersect-combined-schema-keywords
                        Combine the keywords of every part of a combined
                        schema as JSON Schema validates them, as --intersect-
                        allof-keywords does (this option turns it on), and
                        also: the keywords beside an `anyOf` or `oneOf` in
                        each branch, the `properties` an inherited property
                        override merges name by name, an override that narrows
                        the inherited `type` (such as to `null`), the length
                        of an inherited closed tuple under --allof-merge-mode
                        none, the `$ref` siblings of an `allOf` member where
                        the dialect reads them, an `allOf` member that names a
                        `$ref` alias, the null branch of an `allOf` member's
                        `anyOf` or `oneOf`, the `required` names an `allOf`
                        adds to the one model it names at a field, an item or
                        a branch, and no `enum` value that the merged `type`
                        rejects. Without it these keep the output of 0.88.0
  --keep-enum-member-values, --no-keep-enum-member-values
                        Write an enum as a plain Enum where the value base of
                        --use-specialized-enum or --use-subclass-enum would
                        change a member value, such as 2.5 in an IntEnum;
                        without it the base follows the schema type, as in
                        0.86.0
  --merge-shared-variant-tags, --no-merge-shared-variant-tags
                        Give a variant that several discriminated unions tag
                        differently (for example one by a mapping key, one by
                        the schema name) every tag they give it, so each union
                        decodes the documents its discriminator selects; such
                        a union also accepts the tags the other unions give
                        the variant. A variant keeps the tag of the first
                        union, as without the option (as in 0.88.0), where a
                        union listing it would then give two of its variants
                        one tag, and msgspec Structs, which take one tag, keep
                        it too.
  --omit-redundant-constraints, --no-omit-redundant-constraints
                        Do not write a constraint again beside a type that
                        already enforces it: the bound of a zero-bound class
                        such as NonNegativeInt, and the length and number
                        constraints a const or enum Literal meets by its
                        values
  --open-enum-base-class-map OPEN_ENUM_BASE_CLASS_MAP
                        Base classes that open the Enum classes of open enums
                        (--open-enums), by the class the enum is written on
                        (JSON or JSON file path). Keys: Enum, StrEnum,
                        IntEnum. Example: '{"StrEnum": "mypkg.OpenStrEnum",
                        "IntEnum": "mypkg.OpenIntEnum"}'. Each is your member-
                        less subclass of that class whose _missing_ keeps a
                        value it does not list; a value type before Enum
                        (--use-subclass-enum) stays: (str, mypkg.OpenEnum). An
                        open enum whose class has no entry, or that is written
                        as a Literal, is written as Literal[...] joined with
                        its type
  --open-enums {none,extensible,all}
                        Accept values an enum does not list. extensible: the
                        enums whose schema marks them open (x-extensible-enum:
                        true, or x-ms-enum with modelAsString: true); all:
                        every enum of two or more values, except one whose
                        schema closes it (x-extensible-enum: false,
                        modelAsString: false); none: no enum, as without the
                        option. An open enum is written as its Enum class on
                        the base --open-enum-base-class-map names for that
                        class, else as Literal[...] joined with its type
                        (Literal['red', 'green'] | str), whatever the options
                        say about Literals
  --read-allof-parents-in-mro-order, --no-read-allof-parents-in-mro-order
                        Read the allOf parents of every inherited schema in
                        the order of the class bases (the MRO), so a property
                        that several bases declare takes the nearer base's
                        constraints and description, as the class does, also
                        where an allOf lists a base before its own descendant
                        (allOf: [A, B] with B = allOf: [A, ...]); without it
                        the parents of an inner allOf are read in document
                        order and the property can take the farther base's
                        looser constraints, as in 0.90.0
  --read-const-beside-enum, --no-read-const-beside-enum
                        Read a `const` beside an `enum` as JSON Schema does: a
                        value whose schema names the enum is typed by the
                        const that narrows it (`Literal[Enum.member]`, a
                        Literal or None) instead of the enum class that lists
                        the values the const excludes, and under --use-single-
                        value-enum-as-const an `enum` that admits its `const`
                        is read as that `const` instead of an Enum, except one
                        with `nullable: true` and a value other than null
  --read-format-as-annotation, --no-read-format-as-annotation
                        Read the format of a schema as an annotation, as JSON
                        Schema does: a string, integer or number schema takes
                        the type its type keyword gives (str, int, float),
                        with its own length, pattern and bound keywords, so
                        every value the schema accepts validates, a string or
                        integer dumps as written (a number as the float it
                        parses to, as without a format), and an unknown format
                        gives no warning; a format that a --type-mappings
                        entry names for the schema's type keeps that mapping,
                        and format: binary stays bytes. Without it each known
                        format selects a type (EmailStr, AwareDatetime, UUID,
                        Decimal, SecretStr, Base64Str, ...), as in 0.96.0
  --read-kubernetes-extensions, --no-read-kubernetes-extensions
                        Read the Kubernetes schema extensions as the keywords
                        they stand for: x-kubernetes-int-or-string (and the
                        int-or-string format) as an integer or a string,
                        x-kubernetes-preserve-unknown-fields beside properties
                        as additionalProperties true, and an x-kubernetes-
                        group-version-kind as the const and default of the
                        apiVersion and kind it names; without it they are
                        ignored, as in 0.96.0
  --read-length-keywords-by-type, --no-read-length-keywords-by-type
                        Read minLength, maxLength and pattern for strings only
                        and minItems, maxItems and uniqueItems for arrays
                        only, as JSON Schema does, so a maxLength beside an
                        array leaves the list unbounded and a maxItems beside
                        a string leaves the string unbounded; without it a
                        declared array writes minLength/maxLength and a
                        declared string minItems/maxItems as their length
                        bounds, as in 0.88.0
  --read-msgspec-union-bounds-exactly, --no-read-msgspec-union-bounds-exactly
                        msgspec.Struct output only: decide whether the int
                        member of a union with a number member drops its Meta
                        bounds on the bounds the schema writes, exactly;
                        without it a number member's bound past 2**53 is read
