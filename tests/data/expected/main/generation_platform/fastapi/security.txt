    | ## Authentication
    |
    | The secured operations use these security schemes:
    |
    | - `api_key`: an API key in the `X-API-Key` header
    | - `bearer`: a bearer token
    | - `oauth`: a bearer token
    | - `query_key`: an API key in the `key` query parameter
    | - `basic`: HTTP Basic credentials
    | - `cookie_key`: an API key in the `session` cookie
    | - `oidc`: a bearer token
    | - `digest`: no builtin credential; a credential extractor reads it
    | - `mtls`: no builtin credential; a credential extractor reads it
    |
    | Each secured operation receives the principal the authorizer returns.
    | The authorizer reads the credentials of each security alternative from `AuthContext` and rejects a request by raising `HTTPException`, such as `403`.
    | A request that presents no complete alternative answers `401`, and missing authentication settings never fall back to anonymous access.
    | `credential_extractors` replace the builtin credential of a scheme, or read a scheme that has none.
    | An extractor may return any payload, such as a `BasicSecret` it decodes as UTF-8 or a `CustomSecret` of its own type, so the authorizer checks each credential's `kind` instead of assuming its scheme's builtin credential.
    | `SecretT` is `Never` while no extractor returns a `CustomSecret`, and otherwise the union of their value types.
    | Bearer credentials, including OAuth2 and OpenID Connect tokens, reach the authorizer as they are: the package never contacts a token endpoint, and the authorizer checks tokens and scopes.
    | HTTP Basic credentials are decoded as ASCII, as FastAPI's `HTTPBasic` decodes them, so other usernames and passwords answer `401`; register a credential extractor for the scheme to accept UTF-8.

    | ## Served OpenAPI document
    |
    | `create_app` and `install_openapi(app)` make the application serve the source document's operations, schemas, and metadata, composed with its other routes when it first serves or checks the document.
    | Pass `operation_keys` when the application includes only some of the operations.
    | If an application registers the same path and method more than once, FastAPI routes requests to the first route while the document describes the last one.
    | The document cannot reveal the shadowed route, so the package detects such duplicates only among its own operations, when it is generated.

    | ## Validation boundaries
    |
    | Parameters, bodies, and responses that FastAPI validates exactly as the OpenAPI document describes use ordinary FastAPI declarations.
    | The rest pass through generated codecs, which answer `400` for a malformed value, `415` for an undeclared media type, and `422`, with FastAPI's error records, for an invalid value.
    | Native parameters follow FastAPI, which takes the last value of a repeated single-valued query parameter and the first of a repeated header; parameters read through codecs reject both with `400`.
