    | # Native checks
    |
    | The `server` package serves the Native checks API with FastAPI.
    | datamodel-code-generator generated it from the OpenAPI document, together with the `models` models of the `pydantic_v2.BaseModel` backend.
    | Every file of the package belongs to the generator: keep your code in your own modules and regenerate the package instead of editing it; see [Regenerating](#regenerating).
    |
    | FastAPI server generation is experimental.
    | The server supports the `pydantic_v2.BaseModel` and `pydantic_v2.dataclass` model backends, while client generation supports all five.
    | Custom templates, base classes, and Python types stay within these two backends.

    | ## Implementing the services
    |
    | `services.py` declares a Protocol for each router group, with an abstract method for each operation of the group.
    | A method takes the operation's arguments as keywords and returns the value to send, an `HTTPResult` with another declared status, headers, or both, or a `Response` sent as it is.
    | Implement each group in a module of your own and pass an instance to `create_app` under the group's name.
    | Subclass the Protocol, so that type checkers report a missing or mismatched method and Python refuses to create an instance while a method is missing; any other object with the same methods is checked where you pass it.
    |
    | ```python
    | from server import create_app
    | from server.services import UntaggedService
    |
    |
    | class Untagged(UntaggedService):
    |     """Implement `post_discriminated`, `post_ranges`, `post_wide`, `post_described`, `post_patterned`, `post_bounded`, `post_painted`, `post_holder`, `post_wrapper`, `post_extended`, `post_defaulted`, `post_listed`, `post_mapped`, `post_opaque`, `post_anything`, `post_constant`, `post_stamped`, `post_closed`, `post_twice`, `post_node`, `post_extra`, `post_nested`, and `post_box`."""
    |
    |
    | app = create_app(untagged=Untagged())
    | ```
    |
    | Run the application with any ASGI server, such as `uvicorn app:app` for a module named `app.py`.
    | To keep your own `FastAPI` application, with its lifespan, exception handlers, or middleware, include the router:
    |
    | ```python
    | from fastapi import FastAPI
    |
    | from server import build_router
    |
    | app = FastAPI(lifespan=lifespan, exception_handlers=exception_handlers)
    | app.include_router(build_router(untagged=Untagged()))
    | ```
    |
    | ## Served OpenAPI document
    |
    | The application serves FastAPI's own document, built from the routes and the models they declare.
    | Each route adds what FastAPI cannot derive from it, taken from the source document when the package is generated: the declared responses, and the parameters, request bodies, and callbacks that adapters read, with their schemas' references resolved in place.
    |
    | ## Validation
    |
    | The models are the contract: FastAPI validates parameters, bodies, and responses with the generated model types, so the model generation settings decide how strictly a value follows the OpenAPI document.
    | Parameter styles and media types that FastAPI cannot read, such as deepObject or form-style cookie parameters, text and binary bodies, and multipart forms, pass through generated adapters.
    | An adapter parses the HTTP syntax, then validates the value with the model's `TypeAdapter`; it answers `400` for malformed syntax, `415` for an undeclared media type, and `422`, with FastAPI's error records, for an invalid value.
    | Native parameters follow FastAPI, which takes the last value of a repeated single-valued query parameter and the first of a repeated header; parameters read through adapters reject both with `400`.
    |
    | ## Regenerating
    |
    | Run the same generation again whenever the OpenAPI document changes; the `--check` option, or `render_fastapi`, reports the files it would change without writing them.
    | Generation rewrites every file it owns, restoring any you edited or deleted, and never touches your own modules.
    | When an operation is added, removed, or changed, its method in `services.py` changes with it, so type checkers point at the implementations to update, and Python refuses to create an instance of a subclass that lacks a new method.
    | Each generation prints the `uv add` command that adds the runtime dependencies of the package to your project;
    | run it again when a new version of datamodel-code-generator changes them.
