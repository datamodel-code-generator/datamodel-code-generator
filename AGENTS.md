# Instructions for coding agents

See `docs/development-contributing.md` for the development setup and the test helpers. Run the commands below, and
the ones failures print, inside the development environment (`.tox/dev` from `tox run -e dev`, or prefix them with
`uv run` in a uv environment).

## Tests

- Add e2e tests with the existing helpers (`run_main_and_assert`, `assert_output`, ...); no expected path is needed.
- Never add or change an expected path to create, split, share or rename stored output: pytest names, shares and
  splits stored files itself.
- Run `pytest '<test>'` and commit every file it writes (`tests/data/expected/**`, `tests/**/*.refs`).
- To accept changed output: `pytest '<test>' --inline-snapshot=fix`.
- Never edit `.refs` or expected files by hand (each `.refs` file starts with a `# Generated by pytest` header);
  failures print the exact command to run.
- A CI failure that ends with `dcg-expected-fix:` is fixed by the `python scripts/fix_expected.py ...` command it prints.
